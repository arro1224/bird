## 4. 当前已经可以演示的主流程

`连接盒子 -> 设备状态 -> 批次列表 -> 图库 -> 单张详情/分组列表 -> 人工修改 -> 复制确认 -> 任务详情`

该流程在模拟盒子上可以演示；真实盒子仍需确认 URL、字段、鉴权、WebSocket 事件和失败结构。

## 6. 可以进一步优化但不阻塞 P0 的项目

1. 将部分 `dynamic` Bloc 状态改为明确类型，减少运行时错误。
2. 将所有中文状态文案集中到统一映射，避免页面自行拼接。
3. 给缩略图和预览图配置统一 URL 解析、鉴权头和 cache key。
4. 使用 Repository DTO 隔离真实盒子字段变化，页面只依赖领域模型。
5. 为长列表增加滚动位置恢复和页面返回后的查询状态恢复。
6. 统一 SnackBar，避免批量操作连续显示两个提示覆盖撤销入口。
7. 发布版加入全局 FlutterError/PlatformDispatcher 错误页面和本地日志。

## 7. 推荐实施顺序

1. **稳定性优先**：类型化路由、错误边界、完整真机页面遍历。
2. **审阅价值闭环**：分组缩略图、对比审阅、批量四状态、标签、撤销。
3. **任务结果闭环**：WebSocket、失败项、重试、日志下载、结果报告。
4. **设置与诊断**：真实版本、缓存大小、自动重连和分步诊断。
5. **交付验证**：万张真机性能、异常矩阵、集成测试、release APK。
