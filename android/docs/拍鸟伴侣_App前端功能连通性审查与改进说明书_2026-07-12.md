## 一、总体结论

当前项目已经具备设备、批次、任务、设置四个主模块，以及照片列表、照片详情、分组审阅、对比审阅、复制确认、任务详情、诊断与日志等页面。主要页面入口、返回按钮、路由参数校验和断线提示已经建立，正常演示路径基本可走通。

但目前仍有一批“页面可以进入，操作结果却没有完整传递到其他页面”的问题。最需要优先处理的是：

1. 设置页重新连接没有统一触发所有页面刷新和离线操作同步。
2. 模拟盒子的批量保留、丢弃、待定、标签操作只返回成功，没有写回数据，刷新后看不到结果。
3. 日志导出返回 `127.0.0.1` 地址且没有真正的下载接口，真机无法下载。
4. 照片详情执行撤销或采用盒子版本后，输入框可能仍显示旧数据。
5. 任务详情不是实时订阅，控制按钮没有提交锁和明确错误反馈。

因此，项目当前属于“主流程已搭建，跨页面数据闭环仍需加固”的阶段。建议先完成本文 P0 项，再进行真机完整验收。

## 三、P0：会影响真机演示或数据正确性的缺陷

### P0-1 设置页重连没有走统一会话恢复流程

**现象**

设置页调用 `ConnectionRepository.connect()` 后，直接执行 `DeviceSessionCubit.setConnectedFromStatus()`。该方法只更新会话状态；与 `DeviceSessionCubit.connected()` 或 `reconnect()` 相比，没有统一保证刷新协调器和离线队列同步被触发。

**影响**

设置页显示“已重新连接”，但设备、批次、照片、任务页面可能继续显示重连前的数据；离线保存的审阅操作也可能等待下一次网络状态变化才补传。

**修改文件**

- 修改 `lib/bird_companion/features/settings/presentation/settings_cubit.dart`
- 修改 `lib/bird_companion/core/session/device_session_cubit.dart`
- 修改 `lib/bird_companion/core/sync/bird_sync_service.dart`
- 修改 `lib/bird_companion/app/app_dependencies.dart`
- 新增测试 `test/bird_companion/core/session_reconnect_test.dart`

**修改方法**

1. 只保留一个公开的“连接成功”入口，例如 `completeConnection(status)`。
2. 在该入口中依次更新会话、触发 `SessionRefreshCoordinator.requestRefresh()`、调用 `BirdSyncService.synchronize()`。
3. 连接页、顶部断线横幅和设置页全部调用同一入口，禁止直接调用只改状态的方法。
4. 同步失败不能把连接状态改回失败，应显示“已连接，但有 N 项待同步”。

**验收**

断开模拟服务后在 App 内产生待同步操作，恢复服务并从设置页点击重新连接；设备、批次、任务数据应刷新，待同步数量应下降，无需切换网络或重启 App。

### P0-2 模拟盒子批量操作没有持久化，页面结果不闭环

**现象**

`POST /api/v1/projects/{batchId}/files/actions` 仅返回 `succeeded_ids` 和 `failed`，没有修改 `decisions` 或照片标签。随后刷新照片列表时，保留/丢弃/待定筛选和标签数据不会反映刚才的操作。

**影响**

界面提示操作成功，但用户看不到结果，容易误判前端按钮失灵；模拟演示也无法验证真实盒子应有的数据闭环。

**修改文件**

- 修改 `mock_box_server/server.py`
- 修改 `lib/bird_companion/core/models/photo_models.dart`（若列表模型尚未携带审阅状态与标签）
- 修改 `lib/bird_companion/features/gallery/data/photo_api.dart`
- 修改 `lib/bird_companion/features/gallery/presentation/widgets/photo_tile.dart`
- 新增测试 `test/bird_companion/features/gallery_batch_operation_test.dart`

**修改方法**

1. 模拟端按 action 更新每个文件的 `keep_state`、`user_tags` 和版本历史。
2. 照片列表接口返回当前人工决策摘要。
3. 照片卡片显示保留/丢弃/待定标记和标签摘要。
4. 部分失败时只刷新成功项，并提供失败文件清单与再次执行入口。

**验收**

选择多张照片标记为保留，刷新页面并使用“保留”筛选，成功项必须仍然存在；失败项不得被错误标记。

### P0-3 真机日志导出地址和下载接口不可用

**现象**

模拟端返回 `http://127.0.0.1:8080/mock-download/bird-companion-log.txt`。在真机中，`127.0.0.1` 指向手机自身，不是电脑；同时模拟服务没有实现 `/mock-download/...` 的文件响应。

**影响**

“导出诊断日志”只能显示文字，不能取得日志文件。

**修改文件**

- 修改 `mock_box_server/server.py`
- 修改 `lib/bird_companion/features/jobs/data/job_api.dart`
- 修改 `lib/bird_companion/features/settings/presentation/diagnostics_page.dart`
- 新增 `lib/bird_companion/core/files/log_download_service.dart`
- 视现有依赖修改 `pubspec.yaml`（文件保存/分享能力）
- 新增测试 `test/bird_companion/features/log_export_test.dart`

**修改方法**

1. 真实接口优先返回相对路径，如 `/api/v1/logs/download/{token}`，App 使用当前盒子 base URI 拼接。
2. 模拟端实现文本或 ZIP 文件下载，并设置正确的 `Content-Type` 和 `Content-Disposition`。
3. App 下载到应用缓存目录，再调用系统分享或文件保存面板。
4. 诊断页显示生成中、下载中、保存成功和失败重试状态，不直接把 URL 当作完成结果。

**验收**

真机连接电脑模拟盒子后，点击导出可得到实际文件并通过系统分享打开；地址中不得硬编码 `127.0.0.1`。

### P0-4 照片详情恢复数据后编辑框可能仍为旧值

**现象**

`photo_detail_page.dart` 使用 `_initialised` 阻止控制器重复赋值。执行撤销、冲突时采用盒子版本或重新加载详情后，Cubit 的数据已变化，但三个输入框和 `_keep` 不再更新。

**影响**

页面展示与实际版本不一致，用户再次保存可能覆盖刚恢复的数据。

**修改文件**

- 修改 `lib/bird_companion/features/review/presentation/photo_detail_page.dart`
- 修改 `lib/bird_companion/features/review/presentation/photo_detail_state.dart` 或 `photo_detail_cubit.dart`
- 新增测试 `test/bird_companion/features/photo_detail_editor_sync_test.dart`

**修改方法**

1. 在状态中增加 `detailRevision` 或当前 decision version。
2. 仅在 revision 改变且用户没有未保存编辑时同步控制器。
3. 撤销、采用远端和保存成功后明确重置编辑基线。
4. 用户有本地未保存内容时弹出确认，避免无提示覆盖。

**验收**

修改评分并保存，再撤销；评分框、保留状态、标签和版本历史必须同时恢复。

### P0-5 任务控制缺少提交锁、错误反馈和详情实时更新

**现象**

`job_detail_page.dart` 直接 await 控制接口，没有 `_controlling` 状态、try/catch 和操作结果提示。失败项 Future 在 build 中创建，页面重建时可能重复请求。详情页也没有订阅任务事件。

**影响**

快速点击可发送重复暂停/继续/取消；网络异常可能表现为按钮无反应；任务中心变化后详情页不一定同步。

**修改文件**

- 重构 `lib/bird_companion/features/jobs/presentation/job_detail_page.dart`
- 新增 `lib/bird_companion/features/jobs/presentation/job_detail_cubit.dart`
- 新增 `lib/bird_companion/features/jobs/presentation/job_detail_state.dart`
- 修改 `lib/bird_companion/core/network/event_client.dart`
- 修改 `mock_box_server/server.py`（模拟事件或轮询进度）
- 新增测试 `test/bird_companion/features/job_detail_control_test.dart`

**修改方法**

1. 将详情、失败项和控制行为统一移入 Cubit。
2. 控制提交期间禁用全部互斥按钮并显示进度。
3. 成功后立即合并接口返回的 job；失败时显示可读错误并保留原状态。
4. WebSocket 可用时订阅同一 jobId；不可用时仅在运行态进行低频轮询。
5. 单个失败项重试需有 fileId 级接口，不能把“重试此项”实现成重试整个任务。

**验收**

连续快速点击暂停只产生一次请求；断网点击显示错误；在任务中心或盒子端改变状态后，详情页无需返回即可更新。

## 四、P1：功能可用但流程体验不完整

**建议修改**

### P1-2 返回按钮缺少业务父级信息

`BirdPageBackButton` 无历史栈时统一回到 shell 的设备页。深链直达照片详情、任务详情或对比审阅时，返回位置不符合业务预期。

### P1-3 分组对比缺少连续审阅和同步查看

当前对比页能显示多张照片并快速标记，但没有上一组/下一组、当前组进度、同步缩放和同步平移。

- 修改 `comparison_review_cubit.dart`

增加组序号、前后组 ID、键盘/按钮切换和共享 TransformationController；小屏提供双图分页模式。

### P1-5 批量选择没有操作中的状态

`SelectionCubit` 只保存 ID 集合，没有 submitting、失败项和最近操作状态。用户可重复触发批处理。

**建议修改**

- 修改 `selection_cubit.dart`

批量提交期间锁定操作栏；完成后只取消成功项的选择，失败项继续保留并展示原因。

### P1-6 复制任务的结束去向不清晰

## 五、P2：质量、维护性和演示效果优化

### P2-1 诊断结果不够真实

事件通道当前固定显示“通过”，没有读取真实连接状态；页面要等待设备 API 最长四秒后才整体显示。

建议将连接会话、本地待同步数、事件通道立即显示，设备 API 单独加载；事件通道依据 EventClient 状态显示已连接、重连中或降级为 HTTP。

### P2-2 设置页状态类型不严格

`settings_page.dart` 使用 `BlocBuilder<DeviceSessionCubit, dynamic>`。建议改成 `DeviceSessionState`，减少运行时字段错误，并把清缓存/重连改为结构化 SettingsState。

### P2-3 缓存容量统计不完整

现有估算主要覆盖 Hive 元数据，不一定包含图片磁盘缓存。界面应标明统计范围，或同时统计缩略图缓存目录大小。

### P2-4 模拟盒子场景不足

模拟服务缺少 WebSocket、真实图片、401/409/500、延迟/超时、存储不足、断点复制等可切换场景；复制任务还使用固定 `job-copy-001`，重复创建会产生相同 ID。

建议为每次任务生成唯一 ID，增加 `--scenario normal|slow|conflict|storage-full|unstable`，并提供事件流或可控轮询进度。

### P2-5 错误记录没有集中化

友好错误页只能防止红屏直接暴露给用户，但多数异常没有统一写入本地诊断日志。建议新增 `AppErrorReporter`，记录路由、接口、会话和任务控制错误，同时过滤设备地址等隐私信息。

### P2-6 测试覆盖不足

拍鸟伴侣当前测试主要覆盖模型、路由参数、查询和少量 Cubit；缺少页面路由、重连、离线同步、批处理部分失败、冲突处理、任务状态机、日志下载和真机级流程测试。

建议新增：

- Widget 测试：四栏切换、详情返回、空态/错误态、按钮互斥。
- Cubit 测试：重连刷新、撤销与冲突、任务状态迁移、部分失败。
- 集成测试：连接模拟盒子 → 批量审阅 → 复制 → 暂停/继续 → 导出日志。
- 视觉测试：360/480/平板宽度、字体放大、横屏和深色模式。

### P2-7 性能与大数据验证

模拟端每次查询都会复制并过滤一万张照片，前端也尚未留下滚动位置和过滤状态的专项验证。建议增加列表滚动恢复、请求取消、防重复加载、首屏耗时和内存占用记录。

## 九、与真实盒子接口联调时的注意事项

当前前端采用 `/api/v1` 风格端点，模拟盒子只是该契约的本地实现。正式联调前需要盒子端确认：字段类型、状态枚举、错误码、分页游标、幂等键、版本冲突策略、WebSocket 事件格式及日志文件下载方式。未得到盒子端确认的接口不能仅以模拟服务“能返回”为验收依据。

建议用一份可机器校验的 OpenAPI/JSON Schema 作为真实盒子与 App 的共同契约，并为模拟服务运行同一组契约测试。这样删除 `mock_box_server` 后，前端业务代码和接口模型无需修改，只替换连接地址即可。
