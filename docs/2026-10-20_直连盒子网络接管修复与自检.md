## 已修改

1. 收到同一可信设备、同一操作的 `DirectApReady` 后，先交给手机入网等待流程，不再在 BLE 事件消费过程中强制自动加入 WLAN、兑换授权或等待第二次 BLE 确认。
2. 新增可恢复的等待/HTTP 验证/超时/连接成功/永久失败状态。显示热点名称、热点密码查看入口、WLAN 设置入口、继续验证和返回入口。无互联网提示明确要求用户选择保持连接。
3. 默认等待窗口 90 秒，失败重试间隔 1、2、3 秒封顶；仅网络不可达、连接拒绝及网络超时自动重试。身份不符、协议不兼容、401/403 等立即停止。明确的本地凭据保存失败可手动重试保存，但不再次兑换已消费的授权。
4. 前后台切换、网络变化和继续按钮共用同一个验证循环。等待时暂停旧会话自动重连，避免两个流程同时接管连接；返回时取消请求和计时器，迟到响应不能覆盖后续操作。
5. 待完成连接的设备 ID、地址、操作 ID、SSID 保存到本地。短时配对授权和热点密码仅进入 Android Keystore 加密存储的独立命名空间，不写入 Hive 或诊断；先持久化消费状态再兑换一次性授权，响应不确定时不盲目重放。Keystore 写入、删除确认实际持久化后才返回。
6. 冷启动若有待完成连接，先恢复 HTTP 接管，不自动重走蓝牙扫描/配对，也不把缓存相册显示成已连接。已有热点先读取状态并复用，重复点击不重复启动。原网络设置中的停止直连、恢复先前 Wi-Fi 入口保留。
7. 先读取 `/api/v1/device/status` 核对冻结的设备身份，再恢复/兑换授权并验证状态；最后读取受保护的项目列表（只取一条），验证 token 确实有效。不能仅凭 `/health` 或公开状态接口成功就宣布授权连接成功。
8. 增加操作 ID、阶段、时间、前后台、手机网络类型/SSID 是否可读、验证次数、首错分类、超时和成功记录。直连页面复用完整诊断文件导出/分享，不依赖手机长文本剪贴板；不记录密码、配对授权或 token。

## 主要代码

- `features/connection/presentation/direct_ap_handoff_cubit.dart`：独立的持久化、可取消 HTTP 接管状态机。
- `features/connection/presentation/pages/direct_ap_handoff_panel.dart`：手机入网引导与恢复操作。
- `features/connection/presentation/network_provisioning_cubit.dart`、`connection_page.dart`：BLE 终态接入、旧热点复用、冷启动和生命周期衔接。
- `features/connection/data/provisioning_repository_impl.dart`、`direct_ap_pending_store.dart`：延后授权兑换及加密持久化。
- `features/connection/data/connection_api.dart`、`connection_repository_impl.dart`、`app/app_dependencies.dart`：身份校验、授权接管及真实连接状态。
- `core/session/device_session_cubit.dart`、`core/network/connectivity_monitor.dart`：避免旧会话与待完成接管竞争。
- Android `BirdBoxWifiChannel.java`、`MainActivity.java`：系统 WLAN 设置、只读网络快照和 Keystore 持久化确认。没有手机品牌分支。

### 测试过程中的问题

- 旧 B7 演示测试断言热点就绪后必须再读一次 BLE 状态，与本次明确的分阶段接管要求冲突，已更新为不阻塞在额外 BLE 读取上；没有删掉操作关联和就绪事件校验。
- 任务轮询测试曾在 WebSocket 恢复后把第一个在途请求误当作最后的恢复快照，出现请求计数 3/4 不一致；独立复核亦可出现，不能简单归因于并行编译。已仅修正该测试的等待边界：连续三个轮询周期无新请求后，再验证之后仍无轮询。未改任务生产逻辑，也未放宽“恢复后停止轮询”的断言。
- 历史 BLE-05 外部交付证据不在源码仓库内；对应检查如跳过，单列记录，不算功能通过或硬件通过。
