# 复制契约与后端适配说明

本次在 `thirdtime` 的 `b726dcb6373e65e73bbe50cfaf1a4f75dc7be030` 基础上提交本地联调适配。不改动该版本已合入的 Android 蓝牙配对实现。

## 修改范围

- 复制详情进入、轮询及缺口恢复时，按 `has_more` 和末条事件 seq 连续补取分页，避免超过 1000 条事件后遗漏；分页不推进时明确报错。
- 解析可选 `export_failed_count`，XMP 单独失败不再被成功 CSV 或零复制失败数掩盖；CSV 的待执行、未开启、未知状态不再写成已导出。
- 读取 `review_export_ready`，后端未明确开放时禁用新任务的审阅导出开关，保留普通复制。读取到不支持时清除旧的开启选择，不能靠禁用 UI 但继续提交旧值。
- 逐照片识别、智能跟随及媒体路径规则集中至 `ApiEndpoints`，不改动冻结的基础接口清单。
- 检查脚本同步跟进原生上下文与按归属释放会话的实现；模拟服务日志审计允许安全的响应状态行，仍检查敏感内容不泄露。
- 历史 BLE-05 交付包未随源码分发时，其文件完整性检查明确跳过，不虚构为通过；校验器其他正反用例保留。

## 后端契约

| 字段/接口 | 要求 |
|---|---|
| `GET copy-jobs/{id}/events?after_seq=N` | 同任务 seq 从 1 连续递增；多页继续用末条 seq。任务历史未自动裁剪。 |
| `review_export_ready` | 只有显式 `true` 开放审阅导出。当前配套后端为 `false`，新 RC3 导出请求明确拒绝，不能绕过安全 v2 写入走旧流程。 |
| `export_failed_count` | 失败导出操作数，不是复制失败照片数；大于 0 时报告按部分完成显示。 |
| `csv_status` | `pending / success / failed / not_requested`；缺失或未知状态不宣称成功。 |
| `failed_files` | 仍只统计复制执行项失败，不因 CSV/XMP 失败而改写已成功复制的数量。 |

普通复制、智能跟随和旧任务报告适配，不代表完整信息更新、安全元数据 v2、全卡备份已经完成。

## 验证与复现

10-15 联调候选本地结果：Flutter 全量 915 项通过、1 项历史交付文件检查跳过；静态检查无问题；Android App 原生 173 项、虚拟外设 44 项通过。Python 后端 102 项通过。真实华为/OPPO + K7 的完整配对和业务仍待复测，不以这些自动测试替代。

`python_backend_contract_test.dart` 使用实际 `ApiClient / CopyApi / CopyJobDetailCubit` 连接独立 Python 后端，不是 Dart 模拟业务服务。需在配套后端目录运行：

```powershell
python tests/fixtures/app_contract_server.py
```

然后在 App 目录执行：

```powershell
$env:BIRDBOX_CONTRACT_BASE='http://127.0.0.1:18095'
flutter test --no-pub test/bird_companion/features/copy/python_backend_contract_test.dart
```

未设置地址时该测试明确跳过。测试服务器仅使用临时数据及模拟存储，不能部署到真实板端，也不等于物理盘写入验收。
