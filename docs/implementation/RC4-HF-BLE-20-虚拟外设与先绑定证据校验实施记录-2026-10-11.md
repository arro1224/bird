# 项目4 BLE 20 虚拟外设与先绑定证据校验实施记录

日期：2026-10-11。基线提交：c9aa4fabee60756b2cd2f40474ef06e58bff8f35；App 保持 1.14.11+176。工作区保留 BLE 17、18、19 的修改，本次实施规划中的 BLE 20。

## 已实施内容

虚拟外设改为受保护的加密写权限，正常成功通过真实系统绑定及 GATT 恢复。支持首次绑定、已绑定、认证一次或持续失败、首中末片 ATT 响应缺失、CCCD 失败、断链、业务延迟、错误请求号、重复通知及业务响应缺失，共 13 场景。

故障可指定特征、从 1 开始的分片位置、状态码 5/15 及 ATT/业务延迟。故障在分片重组前注入。认证“一次”按异常 GATT/订阅轮次计算，覆盖 Android 内部安全重发；实际断开或两路 CCCD 重新恢复后才释放一次故障。每片记录真实长度、当前允许长度、绑定状态和故障轮次。

新增 128 条有界请求账本，相同 request_id 和完整命令返回缓存响应，副作用执行一次；同一请求号更换内容会拒绝。账本跨 GATT 重建保留，进程内有效。验证码、配网业务生命周期及网络模拟闭环仍由 BLE 21 扩展。

schema 2 校验区分双 AVD 与双手机虚拟端点。它核对实际 createBond 返回与次数、父请求、完整命令 SHA-256、命令尝试与 ATT 调用数、GATT 代次与通知恢复顺序、当前分片长度、单次恢复及副作用去重。AVD 命令行接收端还会重读蓝牙 PCAP，拒绝哈希不符、缺失文件和越界路径；手机无需 netsim。schema 1 保留历史读取，新候选不得复用旧的写入触发绑定四场景。

虚拟外设为独立 debug 模块，正常构建 testOnly=true，release variant 禁用，无生产 App 依赖。新增双手机运行器与操作手册。BLE 12 工具同步当前版本、13 场景及最低检查数，并纳入新增关键源文件；本批没有冻结完整交接候选。

## 实际运行发现并修复的问题

MTU 517 时，原虚拟 Device Info 的 514 字节读片在 AVD 中被截到 512 字节，导致 BLE_FRAGMENT_INVALID。虚拟读写/通知片及生产 Dart 写入片现在同时受 MTU 减 3 和 512 字节约束，原生也在实际 API 调用前拒绝超长值。增加了大 MTU 重组与原生拒绝回归。[Android BluetoothGatt 官方实现](https://android.googlesource.com/platform/packages/modules/Bluetooth/+/refs/heads/main/framework/java/android/bluetooth/BluetoothGatt.java) 使用 512 字节属性值上限。

Emulator 37.2 的 netsim 启动参数与捕获目录不同于旧工具：修正参数传递，读取 pcaps 目录，不宣称固定 RSSI。首次绑定还需确认两边的实际系统 UI：API 36 的 positive_button、对端 Pair & connect 通知及最终 Pair。中文 Windows 后台进程须用 UTF-8 解码 adb XML；确认 App 端后停止等待其动画界面空闲，优先处理对端。

运行器只操作本次拥有的 AVD，使用真实 SMP、绑定广播、原生 GATT 回调。KeepRunning 用于保留排查现场，活跃 PCAP 未关闭时故意不给验收通过状态。原始捕获保留在本地 outputs/ble11，已排除源代码管理。

认证恢复实际运行还发现：客户端重建 GATT 时可以保留底层 ACL，对端不会逐次收到物理断开回调。虚拟故障原先按物理断开释放，因此第二次命令仍错误地失败。现在依据实际两路 CCCD 写成功识别新的订阅轮次；只有一路恢复不释放故障，同时清理旧分片和延迟通知归属。App 的独立证据仍须证明新的 GATT 代次和两路订阅恢复，不能仅凭虚拟端点推断客户端重建。

环境：Android Emulator 37.2.12，两台独立 API 36 AVD，使用 netsim 的真实虚拟蓝牙链路。以下结果只证明 Android 模拟栈与虚拟端点。

| bond_first | 集成与独立校验通过 | createBond 1 次、命令 1 次、ATT 1 次，异常重试 0 次，GATT 重建后两路订阅恢复 |
| auth_once | 集成与独立校验通过 | createBond 1 次、命令 2 次、ATT 2 次，异常恢复 1 次，GATT 恢复 2 次，业务副作用 1 次 |

恢复证据：[auth_once.evidence.json](../../outputs/ble11/20261011-221817-auth_once/auth_once.evidence.json)。该轮 JSON SHA-256 为 c8acd4eb6020e6158ca132f6f41d7084c346dc2934ad61a1efc98d921dfeaf89；App APK 为 16908eb7a71704f5d5f5ffb3feb3d406de54400d1d652f9189a174b61277bb2d，虚拟端点 APK 为 0bab30ca56bb3dd5ada53ff62e7d9b57c680770c3b9099eec06b0ee2b9aea73b。该轮实际注入一次状态码 5；同一 request_id 和完整命令哈希在恢复后匹配，完成一次业务操作，终态成功。

两轮独立校验输出为 build/ble20-main-evidence-verification.log 和 build/ble20-recovery-evidence-verification.log；包含源证据、每轮构建、调用数及 PCAP 哈希的仓库内摘要见 [execution-summary.json](ble20-evidence/execution-summary.json)。摘要是实际执行记录，不是可替代原始场景证据的 fixture；完整独立校验仍需本地原 JSON 及其 PCAP。

中间失败轮次全部按失败保留。AVD 曾在广告启动时发生系统蓝牙进程 SIGABRT，日志明确为 HCI Hardware Error 0x42。运行器只在观察到该错误、且 App 命令尚未开始时允许一次虚拟端点启动重试，原失败事件另存并记录重试原因；其他启动失败直接终止。最终通过的 auth_once 轮次启动重试数为 0。该环境缺陷不能解释为真实盒子问题或已验证的手机行为。

BLE 20 本地实施及“至少一个环境执行主成功与一次恢复”的最低退出条件已满足。正常 App 流程无异常重试；故障流程最多恢复一次。两轮是实施期间分别重建的 APK，构建身份各自记录，完整统一候选仍待 BLE 23 冻结。

复核命令与双手机操作见 [BLE 20 运行手册](../../tool/ble11/README.md)。运行目录为本地生成文件，Git 不包含原始 PCAP；交接需要另行保留脱敏结果与捕获哈希。
