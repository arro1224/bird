# RC4-HF-BLE-08 实施记录

日期：2026-09-23  
范围：BLE 失败清理、同进程重连与连接竞态隔离

## 批次目标

解决失败连接残留 GATT、安全会话、Bond 监听器或待处理操作，导致用户第二次点击
“连接此盒子”仍收到 `invalid_state`，必须删除 App 才能恢复的问题。

本批次不把 `createBond()` 放到连接前，也不改变“先执行真实加密写入，由 Android
安全错误触发配对”的既有协议策略。条件式 `createBond()` 仍属于后续兼容批次。

## 已实施

1. Android 原生桥将断开收口为统一、幂等的 teardown：

   - 取消并回调当前待处理 GATT 操作；
   - 停止扫描并取消超时任务；
   - 对旧 `BluetoothGatt` 执行 `disconnect()` 和 `close()`；
   - 注销 Bond 广播监听器；
   - 重置安全写入状态机、请求信息、通知恢复状态和 MTU；
   - 清除设备引用、地址哈希及本连接的 GATT 代次；
   - 重复调用时保持安全，不遗留未完成的 MethodChannel 调用。

2. 新连接开始前执行一次预清理。即使 Dart 侧认为当前未连接，也会向原生下沉
   `disconnect`，清理“Dart 已失败、原生仍持有半连接 GATT”的分裂状态。

3. 连接失败后在保留原始异常的同时执行 teardown。清理失败只进入诊断，不覆盖
   首个可操作根因。

4. `disconnect()` 不再因 `_connected == false` 提前返回；本地连接状态在 `finally`
   中重置，确保原生清理异常时 Dart 也不会继续声明已连接。

5. 同时发生的多个断开请求复用同一个清理 Future；重复点击连接由数据源和 Cubit
   两层 single-flight 门禁拦截，避免两个 `connectGatt()` 并行竞争。

6. 原生连接成功返回单调递增的 `connectionGeneration`，断开事件携带相同代次。
   Dart 忽略旧代次的迟到断开事件，避免旧会话回调把刚建立的新连接标记为断开。

7. 配对未开始、配对拒绝、Bond 失败/超时、GATT 恢复失败、加密重试失败和
   `pairing_open_timeout` 等终止性安全错误会关闭当前传输会话；非终止错误仍只结束
   当前安全写入会话。

8. 新增 `teardown_started`、`teardown_completed`、`teardown_failed` 和
   `stale_disconnect_ignored` 诊断节点，继续使用 BLE-07 的脱敏字段和同一 trace。

## 关键时序

```text
点击连接
  -> Dart single-flight 门禁
  -> 停止扫描
  -> 原生幂等 teardown（即使本地显示未连接）
  -> connectGatt / 服务发现
  -> 返回 connectionGeneration
  -> MTU 协商
  -> 连接可用

任一步失败
  -> 记录首个失败
  -> 原生幂等 teardown
  -> 清空 Dart 本地会话
  -> 用户可在同一 App 进程再次点击连接
```

## 回归测试

新增或增强的测试覆盖：

- 每次连接前都执行原生预清理；
- 首次连接失败后，无需重装或重启进程即可第二次连接成功；
- 旧连接的迟到断开事件不会破坏新连接；
- 并发连接只发起一次平台连接；
- 本地未连接时 `disconnect()` 仍到达原生；
- 页面连续点击同一设备只触发一次 Repository 连接。

## 板端联调验收

仍需在 OPPO 真机与实际盒子上执行：首次进入配对失败后不杀进程、不清数据、不卸载，
直接返回列表再次连接。验收要求第二次连接能重新完成 GATT 服务发现，并且诊断中
前一代连接出现完整 `teardown_started` / `teardown_completed`，新连接使用更大的
`connectionGeneration`，不得再次因旧 GATT 返回 `invalid_state`。
