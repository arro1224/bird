## 已实现行为

生产 `ProvisioningRepositoryImpl` 增加操作与原请求的双重关联。过期 request_id、已被替换的 operation_id、迟到的 command_accepted 和非请求关联的状态推送不能重新获得操作所有权；已处理终态不会再次入网、兑换或转发。BLE 异步错误在本地保留 request_id/device_id 来源，Repository 只处理当前操作的错误；没有增加 RC4 线上字段。异步确认增加连接代次检查，断开后的结果不再激活旧会话。

HTTP 临时会话从发送兑换请求起即从 App 待兑换状态移除。即使请求异常，也可能已经在盒子消费，不能盲目重发；用户通过“重新安全授权”返回应用验证码阶段。HTTP 成功、手机凭据保存失败时，在当前连接内存保留刚取得的凭据，显示“重试保存连接”。重试读取同一操作的权威终态、再次核对健康身份并保存，不发送新的配网命令或再次兑换；断开时清空内存。没有可用凭据的终态验证显式失败，不能静默返回成功。

`NetworkProvisioningCubit`、失败页及连接页接入上述两种恢复动作。保存阶段使用本地异常类型，不伪造板端错误码。既有凭据重新连接后，核对 `/health.device_id` 并更新保存地址，无须再次兑换临时会话。HTTP RC4 平铺 `code` 保留到 `ApiException`，用于识别会话已使用、无效和过期。

原生 `VirtualBirdBoxProtocol` 改为每个外设实例持有状态：固定开发验证码 246810、10 分钟窗口、5 次错误机会、到期边界、客户端归属和短期会话。重复打开未过期窗口保留剩余次数；次数耗尽不能通过再次打开解除限制；成功授权关闭窗口。配网指令必须授权，每次 AP/手动 STA/停止操作分配独立编号；command_accepted 与约 1.2 秒后的终态分开。success/failure/hold 可通过 Intent 配置，读取与 get_network_status 保留外设进程内结果，断开不取消操作。原有完整请求账本继续去重；敏感指令不记录消息哈希，日志仅保留元数据。临时网络状态不保存 Wi-Fi 密码或授权值。

Debug B7/birdSim 模拟端增加固定验证码 123456、2 分钟窗口、3 次机会及临时授权检查；每轮操作编号独立，旧连接和被替换操作的延迟事件失效。修复 DPP 成功通知与读取状态使用不同 operation_id 的问题。HTTP 兑换只取一次临时会话；成功后的首页准备失败可以复用内存中的已兑换凭据。模拟入口继续隔离在 Debug 依赖图，生产网络路由没有指向 Mock。

HTTP Mock 增加临时会话到期、进程内客户端绑定/重新授权钩子及可控服务失败。没有新增对外授权接口。身份一致测试使用 `bbx-b1e11001b1e11001b1e11001b1e11001`；原来的手机运行示例也可使用另一合法 ID，但 Fake BLE 与 HTTP 必须一致。

## 回归矩阵与失败后的处理

| 场景 | 实际覆盖 | 处理结果 |
| --- | --- | --- |
| 未开窗口、错误码、到期、次数耗尽、重复授权 | 原生状态机 + Debug 状态测试 | 使用冻结 PAIRING_* 错误，不生成有效会话 |
| 无授权/旧临时会话/会话到期 | 原生与 Repository/Debug 测试 | 禁止发起配网；重新应用授权 |
| command_accepted 与成功分开、独立 operation_id | 原生 AP/STA/停止及 Debug 测试 | 先 busy，终态与查询编号一致；hold 不声明成功 |
| 原生 operation failure | 原生 failure 状态测试 | 返回已有 AP_START_FAILED 等错误及 failed 状态 |
| HTTP 身份不一致 | 生产 Repository + 真实本机 HTTP | 兑换前 DEVICE_ID_MISMATCH，兑换次数为 0 |
| HTTP 会话过期、已用、客户端不符、重新授权 | 真实 Mock HTTP 测试 | 拒绝兑换，新的授权使旧授权失效 |
| HTTP 兑换服务失败 | 生产 Repository + Mock | 不复用同一临时会话，提示重新安全授权；新授权后可继续 |
| 本地保存失败 | 生产 Repository + Cubit + 页面测试 | 单次兑换后只重试保存；无新配网命令，成功后进入成功态 |
| 旧 request/operation、重复终态、迟到接受响应、旧状态/错误 | 生产 Repository、Cubit 与现有 BLE 测试 | 无重复兑换、无重复成功通知、不能覆盖当前操作 |
| 保存凭据重连 | 生产 Repository + 真实 Mock HTTP | 恢复查询/身份核对，无第二次临时会话兑换 |
| 验证码到首页路由 | 页面 + 真实 Mock HTTP | 完成一次健康核对和一次兑换，进入首页路由 |

## 复现及交付边界

项目根目录运行：

```powershell
.\tool\ble21\run_local_business_checks.ps1
```

脚本允许指定 `-FlutterRoot` 与 `-JavaHome`，使用已准备的离线 Gradle 与项目依赖。原生导出文件属于本地测试数据，含合成授权样例，不作为脱敏诊断或板端真实会话导出。业务模拟启动、adb reverse 和验证码说明见 `tool/mock_box_server/README.md`；原生 Intent 配置见 `tool/ble11/README.md`。

原生虚拟 BLE 和 birdSim HTTP 是独立分段，未共享随机授权、Bearer Token、网络或板端状态。原生端仅实现 AP/手动 STA/停止业务；扫描声明不支持，DPP 与未知 Token 使用现有错误拒绝。它们证明应用业务状态和 HTTP 契约，不证明 AP 广播、STA 关联、DHCP、无互联网网络选择、真实 Android 路由或固件。未在本轮安装或测试华为/vivo，也未重跑 BLE-20 无线矩阵；历史成功不能自动覆盖本批新源码。真实盒子验收继续为 pending，releasable=false。
