# P5.4 启动与批量状态 K7 验收

日期：2026-08-16

## 验收范围

- 首次启动且没有设备历史：进入设备连接首页。
- 已保存设备：盒子在线或离线都进入相册首页。
- 批量“保留、待确认、弃选、精选”的提交、显示和撤销链路。
- K7 模拟盒基础接口和渐进媒体接口回归。

## 验收环境

- Android 设备：vivo X20，ADB 序列号 `b502aabb`。
- 隔离包：`deckers.thibault.aves.bird.v1`，未清理正式包数据。
- K7 模拟盒：`http://127.0.0.1:8787`，通过 `adb reverse tcp:8787 tcp:8787` 转发。
- 为验证首次启动，仅清理过隔离包 `bird.v1` 的应用数据；之后重新建立并保留了模拟连接。

## 启动验收

| 场景 | 结果 |
| --- | --- |
| 无设备历史 | 进入“查找设备”首页，通过 |
| 已保存设备且盒子在线 | 直接进入“相册”，通过 |
| 已保存设备且盒子离线 | 直接进入“相册”并展示缓存，通过 |
| 离线后手动重连 | 进入真实重连/配对流程，通过 |

真机验收时发现 `BirdRoutes.shell` 与 `MaterialApp.home` 共用 `/`：首次连接成功后点击“进入相册”会重新构建连接首页。现已把 shell 路由改为 `/shell`，并增加路由防冲突测试。修复后连接成功页可正常进入相册，强制停止再启动仍按保存设备进入相册。

## 四种批量状态

| 操作 | 服务端状态 | 照片标记 | 真机结果 |
| --- | --- | --- | --- |
| 保留 | `keep` | 绿色圆点 | 提交成功 |
| 待确认 | `pending` | 黄色圆点 | 提交成功 |
| 弃选 | `discard` | 红色圆点 | 二次确认、提交成功 |
| 精选 | `featured` | 黄色星星 | 提交成功 |

验证要点：

- 四个动作都通过相册批量操作面板触发，不是直接修改模拟盒数据。
- 成功后界面显示“已更新 1 张照片”和“撤销”。
- 精选操作后点击撤销，界面显示“已撤销最近一次批量操作”；随后再次执行精选并提交成功。
- 模拟盒最终状态统计为：`keep=13`、`pending=33`、`discard=7`、`featured=7`，总数 60，说明状态互斥且没有丢失照片。
- 卡片组件测试逐项断言 `keep/pending/discard/featured` 的图标和颜色；`isRecommended` 和低置信度不再覆盖用户状态标记。
- P5.3 的一致性测试继续覆盖成功 ID 局部更新、失败 ID 不误改、筛选移除、缓存更新和离线队列。

## K7 接口门禁

- `progressive_media_p4_acceptance.dart`：通过。覆盖 ready/fallback、`Retry-After`、乱序事件、WebSocket 断线和缺事件轮询兜底。
- `b12a_k7_acceptance.dart`：在非渐进模式通过。覆盖 60 张照片扫描、搜索/组合筛选、场景/连拍、缩略图、任务、409/422、取消报告和日志。
- 两个门禁分别启动对应模拟模式；B12-A 的旧缩略图即时可用假设不与渐进模式混跑。

## 结论

P5.4 的模拟盒验收已通过，并在验收中修复了一个真实的首次连接跳转缺陷。当前结果适用于 K7 模拟盒；真实硬件的 Wi-Fi、权限、休眠和弱网行为仍属于 B12-B 实机发布门禁。
