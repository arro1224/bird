# RC4-HF-BLE-09 实施记录（2026-09-23）

## 目标

修复部分 OPPO Android BLE 栈在敏感特征写返回鉴权错误后仍不自动进入
`BOND_BONDING`，导致 App 一直等待并最终超时的问题。同时保持 BLE-07/08
已经建立的边界：禁止连接前强制配对、禁止无条件 `createBond()`、禁止重复发送
业务命令。

## 实施结果

Android 原生桥新增一次性的条件式 Bond 兜底，触发必须同时满足：

1. 已建立 GATT、发现服务并订阅通知；
2. App 已真实写入 Wi-Fi 配置或配网命令特征；
3. Android GATT 回调明确返回 5/8/12/15 之一；
4. 给系统自动配对保留 2 秒窗口后，设备仍是 `BOND_NONE`；
5. 当前 `request_id`、连接代次和安全会话仍有效；
6. 当前请求此前没有执行过条件式兜底。

满足以上条件后才调用一次 `BluetoothDevice.createBond()`。若系统已进入
`BOND_BONDING` 或 `BOND_BONDED`，延迟任务立即取消，不会再调用。普通写启动
失败、GATT 133、连接前阶段和第二次安全失败均不会触发该兜底。

Bond 成功后原生桥强制重建 GATT，重新发现服务；Dart 侧重新协商 MTU、恢复
Network Status 和 Provisioning Command 两个通知，然后只重发一次原始密文，
继续使用相同 `request_id`。第二次鉴权失败仍直接终止，不开启新一轮配对。

## 状态与诊断

状态机新增 `conditionalBondFallbackAttempted`，作为请求级单次门闩。诊断事件
新增：

- `conditional_bond_fallback_scheduled`
- `conditional_bond_fallback_started`
- `conditional_bond_fallback_result`
- `conditionalBondFallbackAttempted`
- `bondInitiationSource`：`none`、`system` 或 `conditional_fallback`
- `securityGattStatusObserved`

所有事件仍归类为 `security_write`，不会伪装成独立业务操作；日志不记录地址、
配对码、Wi-Fi 密码或命令明文。

## 真机验收

自动测试不能代替 OPPO + 真实 BirdBox 联调。验收时应确认：

1. 首次敏感写确实先发生，随后才出现配对交互；
2. 自动配对正常的手机不出现 `conditional_bond_fallback_started`；
3. OPPO 未自动配对时只出现一次 fallback started/result；
4. Bond 状态达到 `BONDED` 后 GATT 代次递增、两个通知恢复；
5. 重试包与首次包字节一致，`request_id` 相同，`retryCount=1`；
6. 成功进入配对开放状态；失败路径可返回上一步并在同一进程重新连接。
