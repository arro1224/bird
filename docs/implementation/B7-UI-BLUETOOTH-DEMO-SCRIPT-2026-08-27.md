# B7 UI 与蓝牙配网演示脚本

用途：按照 UI 进度汇报要求录制一段短视频，展示 App 页面跳转，并重点展示蓝牙配网部分。演示使用模拟/Fake 数据时，视频口播必须明确“这是 simulated preflight，不是真实 K7 验收”。

## 录制顺序

### 1. App 入口与设备连接

1. 打开 App 首页。
2. 进入设备连接页，展示设备发现列表和设备卡片。
3. 点击设备卡片，进入设备配对页。
4. 说明：设备身份以 GATT Device Info 为准，广播中的名称和扩展数据只用于发现，不作为最终身份。

### 2. 蓝牙配对

1. 展示配对码输入页，说明配对码只在当前蓝牙会话中使用。
2. 输入合成测试配对码并提交。
3. 展示配对成功后的 Wi-Fi 配网方式选择页。
4. 口播：配对码不进入 HTTP 请求、日志或持久化存储；本视频不展示真实配对码。

### 3. 配网方式跳转

依次展示三个入口，不需要每个都完成到底：

- 搜索附近 Wi-Fi：进入扫描结果页，展示安全的 SSID、信号强度和安全类型；
- 手动输入 Wi-Fi：展示 SSID 和密码输入校验，提交后密码字段清空；
- 使用 DPP 安全配网：展示 DPP 不可用或失败时的安全回退页，页面不显示 DPP URI 或诊断信息。

### 4. Direct AP 与恢复状态

1. 从配网方式页进入直连盒子流程。
2. 展示连接中、已连接或恢复中的状态。
3. 如演示断连模拟，展示页面保留、旧 operation 不覆盖当前状态，以及“已恢复可用网络”文案。
4. 说明：网络操作的最终状态必须由匹配的盒端事件确认；单纯收到“命令已接受”不等于成功。

### 5. 收尾页面

1. 返回设备详情或设置页，展示页面跳转栈没有进入 Demo 专用入口。
2. 口播当前状态：B7 模拟预检继续开发中，真实 K7、真实 Android 和 Release 门禁仍为 `real_pending`。

## 建议口播稿

“这段演示展示的是 B7 simulated preflight。我们先从设备连接进入蓝牙发现和配对，再进入 Wi-Fi 配网方式选择。蓝牙只负责发现、身份读取和配网命令，照片传输仍走 Wi-Fi。配对码、DPP URI、密码和 Token 不会出现在 UI、日志或证据里。当前页面跳转和 Fake BLE/Wi-Fi/DPP 流程已经通过自动化测试，但真实 K7、真实手机和 Release 门禁尚未宣称通过。”

## 录制检查清单

- [ ] 设备发现页和设备卡片清晰可见；
- [ ] 配对码输入页和配对成功后的方法选择页连续出现；
- [ ] Wi-Fi 扫描、手动输入、DPP 三个入口至少各展示一次；
- [ ] 视频中不出现真实密码、Token、完整 DPP URI、真实 MAC 或真实设备证据；
- [ ] 结尾明确标注 `simulated`、`releasable=false`、`real K7 pending`；
- [ ] 如使用模拟盒子，画面或口播明确说明不是 Release 验收。
