## 1. 本批结论

`RC4-HF-BLE-01` 已完成“可观测、可验证、可安全接管”的基础实施：

- 冻结首次加密写的原生状态机、GATT 代际和只重试一次规则；
- 扫描与连接诊断升级到 schema v2；
- 零扫描结果也能复制诊断 JSON；
- 增加 A/B 扫描权限构建，A 保留 `neverForLocation`，B 移除；

本批**没有**把新状态机接入生产命令链，也**没有**删除现有
`ensureBonded() -> createBond() -> write` 前置流程。这一接管动作属于
`RC4-HF-BLE-02`，必须结合真实 BirdBox 和 OPPO/Huawei 日志实施。因而本批不能
宣称 OPPO 首次配对问题已修复，也不能宣称 Huawei 扫描问题已闭环。

## 2. 已实施内容

### 2.1 安全写状态机基础

新增纯 Java `BirdBoxSecurityWriteStateMachine`，覆盖：

- `gatt_ready -> security_write_starting`；
- 快速到达的 `BOND_BONDING`；
- Bond 后保留或重建 GATT；
- 通知恢复后使用原请求重试一次；
- GATT 代际校验，拒绝旧实例回调；
- matching `request_id` 响应完成；
- 配对未启动、配对拒绝、GATT 恢复失败、加密重试失败和响应超时。

该类没有接入 `BirdBoxBleChannel`，用于先冻结行为和测试边界，避免在没有真实
盒子时把未经硬件验证的安全流程直接投入生产。

### 2.2 扫描诊断 schema v2

每轮扫描现在记录：

- `trace_id`、起止时间、低延迟扫描模式；
- 手机厂商/型号、Android/SDK、App 版本、Git commit、运行时 APK SHA-256；
- SCAN/CONNECT/定位权限、蓝牙状态、旧 Android 定位服务状态；
- `raw_result_count`、`unique_device_count`、接受/过滤计数和原因；
- 每条回调的会话加盐 `address_hash`、name、alias、RSSI、服务 UUID；
- 厂商数据是否存在及长度；
- scan record 长度与 SHA-256；
- `onScanFailed` 错误码。

存储键升级到 v2，并保留读取 v1 的兼容路径。单轮最多落盘 500 条观测，超过后
继续保留总计数并写入 `diagnostic_observation_limit_reached`。

### 2.3 连接诊断 schema v2

原生/Dart 事件可记录：

- 脱敏设备地址、GATT 实例编号、连接状态、服务发现结果和 MTU；
- 通知订阅状态、操作名、特征 UUID、Write With Response 和写回调状态；
- 当前/前一 Bond 状态、系统配对交互、是否重建 GATT；
- 重试次数、`request_id`、安全触发、命令/响应类型和最终结果码。

状态码 5、8、12、15 均纳入安全错误识别基础。生产流程仍沿用旧行为，状态机
接管后再依据操作阶段区分“ATT 授权不足”和连接超时。

### 2.5 错误码和 UI

新增：

- `BLE_GATT_NOT_READY`；
- `BLE_LE_PAIRING_NOT_STARTED`；
- `BLE_PAIRING_REJECTED`；
- `BLE_GATT_RECOVERY_FAILED`；

每个错误码都有独立中文说明和可执行操作，不再只能落到统一的“盒子连接未完成”。

## 4. 当前不能验证的内容

当前只有 vivo 真机，没有 Huawei、OPPO 和真实 BirdBox，因此以下项目保持未验收：

- A/B 包在 Huawei 上的 `raw_result_count` 差异和 10 次扫描稳定性；
- OPPO API 36 首次加密写能否触发 `BOND_BONDING/BONDED`；
- BirdBox PairingAgent 是否收到回调；
- Bond 后 GATT/MTU/两路通知恢复；
- 同一 `request_id` 重试一次后收到 `pairing_opened`；
- vivo 只能用于安装、权限恢复、零结果诊断复制和普通扫描回归，不能替代上述验收。
