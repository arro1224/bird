# RC4-HF-BLE-02 实施记录

日期：2026-09-20
基线分支：`thirdtime`
基线提交：`6f78bc67fbac2f042d09f4d8367806e69542e557`
应用版本：`1.14.8 (172)`

## 1. 本批次结论

`RC4-HF-BLE-02` 已在代码侧完成：生产链路不再在 `open_pairing` 前调用无参数 `BluetoothDevice.createBond()`，也不再以 `bondState=not_bonded` 阻止加密特征写入。新的主流程为：

```text
GATT/服务/两路通知就绪
→ 写前注册 Bond 监听
→ 对加密特征执行真实 Write With Response
→ 识别 5/8/12/15 安全错误或配对期间断连
→ 等待 BOND_BONDING/BOND_BONDED（60 秒）
→ 确认当前 GATT 服务，或只创建一个新 GATT 并重新发现服务
→ 新 GATT 时重新协商 MTU
→ 重新订阅 Network Status 与 Scan Results
→ 使用原 request_id、原 JSON、原 message_id、原分片字节重试一次
→ 等待 matching request_id 的响应
```

本记录只声明代码实现与自动化验证完成。由于当前没有 OPPO、华为和真实 K7，本批次尚不能声明真机 BLE 首次配对问题已经最终验收通过。

## 2. 原生 Android 修改

- `BirdBoxBleChannel` 删除生产 MethodChannel 中的 `ensureBonded`、`isLinkEncrypted` 与 `createBond()` 主路径。
- 新增一次性安全写会话接口：
  - `beginSecurityWrite`
  - `awaitSecurityReady`
  - `beginSecurityRetry`
  - `markSecurityWriteSent`
  - `completeSecurityWrite`
  - `failSecurityWrite`
- 在首次加密写之前注册 `ACTION_BOND_STATE_CHANGED`，避免遗漏快速的 `BOND_BONDING/BOND_BONDED` 回调。
- 支持 Bond 回调先于写回调、重复 Bond 回调、Bond 后旧 GATT 仍可用、Bond 后 GATT 断开四类时序。
- 安全相关 GATT 状态覆盖 5、8、12、15；首次命中进入恢复，重试阶段任何写失败统一返回 `ble_encrypted_retry_failed`，不再启动第二轮恢复。
- GATT 恢复串行化：同一时间只保留一个 `BluetoothGatt`；旧连接失效时先关闭，再通过保留的 `BluetoothDevice` 建立新连接。
- 诊断事件关联 `requestId`、实际重试次数、`securityTrigger=encrypted_characteristic_write`，并将写操作标记为 `write_<command_type>`，例如 `write_open_pairing`。

## 3. Dart/业务层修改

- 所有 RC4 命令在通知就绪后直接开始真实加密写，不再先检查 Bond 或伪造“链路已加密”状态。
- 首次安全失败只允许一次恢复：等待原生 Bond/GATT → 必要时重新请求 MTU 517 → 恢复两路通知 → 启动精确重试。
- 重试复用第一次已经生成的请求字节和分片列表，因此 `request_id`、JSON、message id 与所有 fragment 字节保持不变。
- 全部分片写成功后才进入 matching response 等待；`open_pairing` 超时映射为 `pairing_open_timeout`。
- 恢复、通知订阅或重试失败分别映射到 `ble_gatt_recovery_failed`、`ble_encrypted_retry_failed` 等独立错误码与既定用户提示。

- 原生安全写状态机新增并覆盖：
  - 首次写直接成功；
  - 写回调前收到 Bond；
  - 新 GATT generation 与陈旧回调隔离；
  - Bond 后 GATT 丢失；
  - 重复 Bond/迟到安全回调；

## 6. 尚未完成的硬件验收

以下结论必须等待设备，不能由 vivo 单机或自动化测试替代：

1. OPPO API 36 首次写是否触发真实 `BOND_BONDING/BOND_BONDED` 与 K7 PairingAgent 回调；
2. 配对期间 OPPO/Huawei 保持 GATT 与主动断开两种分支是否都能恢复；
3. K7 是否只接收到同一 `request_id` 的一次业务成功及最多一次精确重试；
4. matching `pairing_opened`、输入应用层 `123456`、`authorize_pairing` 与 `pairing_session_id` 是否闭环；
5. Huawei A/B 各 10 轮扫描对比及原始诊断 JSON；
6. OPPO 首次配对连续 5 次、OPPO/Huawei 扫描各连续 10 次的验收记录。

在这些记录完成前，当前状态应标记为“BLE-02 代码完成，硬件验收待办”，而不是“问题已彻底修复”。
