## 实施内容

新增 `tool/ble12`，提供：

- `build_ble12_candidate.ps1`：在 Windows PowerShell 5.1/PowerShell 7 下重跑
  测试、构建两个 APK、冻结源码和环境并生成包；
- `ble12_candidate_validator.dart`：对候选状态、来源、APK 身份、测试数量、
  BLE-11 状态、材料引用和哈希执行 fail-closed 校验；
- `validate_ble12_candidate.dart`：仓库侧命令行入口；
- `verify_package.ps1`：交接后无需仓库即可执行的离线逐文件校验；
- 外场联调手册、诊断回传说明和 BLE-12 回传模板。

生成过程使用临时 staging 目录；语义和完整性校验全部通过后才移动到
`outputs/RC4-HF-BLE-12`。失败 staging 不会成为正式候选。生成器不会覆盖同一
候选 ID，避免旧包被静默替换。

## 冻结和防伪门禁

候选清单和校验器共同约束：

- 候选 ID 必须等于源码总指纹前 16 位；
- 源码路径必须安全、逐文件哈希必须与当前仓库一致；
- Git SHA、分支、干净/未提交状态必须显式记录；
- App 与虚拟 BirdBox APK 均记录 SHA-256，并用 `apkanalyzer` 从 APK 本体导出
  Manifest，反查包名、版本号、debuggable 和 test-only；
- 实际文件集合必须与 `artifacts` 精确一致，禁止未登记附件；
- `SHA256SUMS.txt` 同时保护候选清单和 14 个登记产物；
- 模拟证据中出现完整 MAC、凭据、`hardware_status=verified` 或
  `releasable=true` 时直接失败；
- Emulator 已达到 36.5+ 时，不允许再以 `pending_environment` 跳过 BLE-11
  四场景；接收四场景证据时必须逐份通过 BLE-11 校验并核对 PCAP SHA-256。

## 模拟环境边界

本机 Android Emulator 为 `36.2.12.0`，已有
`Medium_Phone_API_36.1`、`codex_b6_api34` 两个 AVD，但版本仍低于 BLE-11
双 AVD Bluetooth 互联要求的 36.5+。因此本包没有伪造四场景结果，而是生成
可交接的候选基线并保持：

```text
simulation_status=pending_environment
hardware_status=pending
releasable=false
```

升级 Emulator 后，应先完成 BLE-11 的 `success`、`auto_bond`、
`fallback_once`、`disconnect_once` 四场景，再把四份通过校验的证据传给 BLE-12
生成器重新出包。即使四个模拟场景全部通过，真实硬件门禁仍保持 pending。
