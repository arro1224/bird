# RC4-HF-BLE-03 真机证据验收手册

本手册只用于 `RC4-HF-BLE-03` 热修闭环，不把模拟测试、vivo 单机测试或
人工口头结论当作 OPPO/Huawei/K7 验收证据。

## 1. 证据文件

从模板复制一份真机证据文件：

```text
docs/acceptance/rc4-hf-ble-03-evidence.template.json
```

把 APK、K7 脱敏日志、重连记录和审批记录放在证据 JSON 同目录或其子目录下。
JSON 内使用相对路径，校验器会核对 APK 真实 SHA-256，并确认每个引用文件存在。

## 2. 扫描采集矩阵

`scan_runs` 每项包含 `device_role`、`variant`、`scenario` 和 App 复制出的
`session` JSON。计数门禁为：

| 手机 | APK | 场景 | 最少连续成功次数 |
|---|---|---|---:|
| Huawei | A | `baseline` | 10 |
| Huawei | B | `baseline` | 10 |
| Huawei | 最终选定 A/B | `bluetooth_toggled` | 10 |
| Huawei | 最终选定 A/B | `permission_regranted` | 10 |
| Huawei | 最终选定 A/B | `foreground_resumed` | 10 |
| OPPO | 最终选定 A/B | `baseline` | 10 |

最终选定包的 Huawei `baseline` 可直接复用 A/B 对比中的同一组 10 次数据。
每次必须同时满足：原始回调大于 0、App 接受 BirdBox 候选、权限已授予、
蓝牙已开启、低延迟扫描、APK SHA 和 A/B 权限策略匹配。

## 3. OPPO 首次配对

清除 App 数据和旧 Bond 后，在 OPPO PKC110 / API 36 上连续完成 5 次。每次：

1. 扫描并连接 K7，读取 Device Info；
2. 点击“开始配对”，等待进入验证码页；
3. 在验证码页点击“复制本次配对诊断”，先保存 `pairing_opened` 前后的记录；
4. 输入应用层验证码，完成 `authorize_pairing`；
5. 在“选择连接方式”页点击“复制完整配对诊断”，把完整 JSON 放入
   `pairing_runs[n].diagnostic`；
6. 保存相同时间窗口的 K7 脱敏日志，记录 PairingAgent、`open_pairing`、
   `authorize_pairing` 和相同 `request_id` 的复核结论。

校验器会硬性检查：

- `open_pairing` 实际写入 `6f7d0005-...` 且使用 Write With Response；
- 安全触发为 `encrypted_characteristic_write`；
- 存在 `BOND_BONDING` 和 `BOND_BONDED`；
- 遇到 5/8/12/15 安全错误时只允许一次重试；
- 安全恢复后已重新订阅 Network Status 和 Scan Results；
- `pairing_opened` 必须匹配原 `request_id`；
- `authorize_pairing` 必须返回 `pairing_authorized`；
- K7 日志的 `request_id` 必须与 App 诊断相同；
- 证据中不得出现验证码、session id、Token、Wi-Fi 密码或明文 MAC。

## 4. 已配对重连

`reconnect_check` 必须记录：

- 重启 App 后复用已有 Token；
- 没有再次显示验证码页；
- BLE 临时断开后，K7 已接受的任务继续执行；
- 至少一份脱敏证据文件。

## 5. 执行门禁

```text
dart run tool/acceptance/rc4_hf_ble_03_evidence_validator.dart <evidence.json>
```

只有输出同时为 `status=passed` 和 `hardware_status=verified` 才能将本热修标记为
真机已修复。模板默认 `pending`，缺少任何一台手机、K7、日志、APK 或审批时都会
闭锁失败。
