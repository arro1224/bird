日期：2026-09-03

结论：**代码与自动化门禁已完成；真机验收项转入 RC4-B6，当前不得据此宣称可发布。**

## 1. 实施范围

本批次只修改 App 仓库中的 Android BLE、local-only Wi-Fi、Easy Connect（DPP）桥及其 Dart 边界，不修改 rc4 冻结 UUID、字段、枚举、超时，不代替盒子端 RC4-B5，也不生成虚假的真机证据。

## 2. 已实施内容

### 2.1 BLE 原生桥

- GATT 回调必须来自当前 `BluetoothGatt`，旧连接的迟到回调不能完成新连接的操作。
- 连接重复调用返回 `invalid_state`，单次 GATT 操作继续使用忙状态和超时保护。
- 认证不足、加密不足、密钥长度不足统一映射为 `ble_link_not_encrypted`，与普通传输失败分离。
- Wi-Fi 凭据 characteristic 在 Android 侧增加 bonded 前置拒绝；盒子端 characteristic 权限仍是最终安全权威。
- 断线事件增加 `reason`、`gattStatus`、`unexpected`，显式断开不再因迟到回调重复上报。
- service discovery 失败、扫描失败、连接关闭和 dispose 的资源释放路径补齐。

### 2.2 Wi-Fi 原生桥

- 新增 `bird_companion/birdbox_wifi/network_events` EventChannel。
- `NetworkCallback.onLost()` 立即解除进程绑定并发送脱敏丢网事件；事件不包含密码、Token、配对码、DPP URI 或 MAC。
- 使用请求代际和 callback 身份阻止旧 `onAvailable/onUnavailable/onLost` 污染新请求。
- `onUnavailable`、权限失败、请求失败、绑定失败使用不同稳定错误类别。
- release、callback 注销、进程解绑和 dispose 均可重复调用；异常清理不覆盖原始结果。
- Dart `BirdBoxWifiPlatform` 暴露 `networkLosses`，严格校验事件结构，匹配丢网时清除 `boundNetwork`。
- `ProvisioningRepositoryImpl` 消费丢网流，并向状态机发出可重试的安全错误。

### 2.3 DPP 原生桥

- 每次 Easy Connect 启动使用代际化 request code，超时后的旧 Activity 结果不能完成后续新请求。
- 完成、超时、启动异常、宿主销毁和 dispose 都会清除临时 URI 与 timeout。
- 旋转由现有 `configChanges` 配置承接；非配置变更销毁返回稳定的 `host_destroyed` 类别。
- 系统返回只暴露白名单类别；异常类名和厂商原文不再进入 Dart/UI。
- DPP URI 增加最大长度及 CR/LF 拒绝，URI 从不写日志或持久化。

### 2.4 门禁与测试

- 新增 `BirdBoxBleChannelTest.java` 与 `BirdBoxWifiChannelTest.java`。
- 扩展 `BirdBoxDppChannelTest.java`，覆盖结果分类和连续启动 request code 隔离。
- 新增 Dart Wi-Fi 平台边界测试，覆盖丢网、畸形事件和绑定错误映射。
- 增加 Repository 丢网传播回归。
- 生产完整性门禁新增 B4 原生/Dart 接线与原生日志禁用检查。

## 5. 验收边界

以下项目依赖真实 BirdBox、真实路由器、Android 手机和盒子端实现，本批次只能提供待验收代码，必须在 RC4-B5/B6 完成后验证：

- Android 近三个主要版本及 OPPO/vivo/小米/华为/荣耀/三星矩阵；
- 蜂窝网络开启时 Direct AP 的 REST、WebSocket、媒体请求持续走绑定 Network；
- 真实 `NetworkCallback.onLost` 到 Dart/页面可恢复状态小于 1 秒；
- 盒子 GATT characteristic 权限确实拒绝未加密敏感写，与 App 前置拒绝形成双重保护；
- DPP 成功、取消、超时、返回、锁屏、前后台与厂商 ROM 行为；
- 真机日志扫描确认无验证码、Wi-Fi 密码、Token、完整 DPP URI 和完整 MAC。

因此 RC4-B4 的准确状态是：**实现完成、自动化通过、真机验收待 RC4-B6；不可发布。**
