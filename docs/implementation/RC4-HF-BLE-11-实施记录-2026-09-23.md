## 实施内容

新增独立 Android 应用模块 `android/virtualBirdBox`，由 AVD-B 充当 BLE
Peripheral/GATT Server。模块冻结了 RC4 的 Service UUID、五个特征、12 字节
小端分片头、最大消息尺寸、Device Info 和响应信封，并提供：

- Service UUID 广播、设备名和 8 字节厂商数据；
- Device Info、Network Status 读取；
- Network Status、Scan Results 两路 CCCD；
- Wi-Fi Config、Provisioning Command 两个 Write With Response 特征；
- `request_id` 原样返回和 `pairing_opened` 响应；
- MTU 感知分片、重复分片幂等和脱敏 JSONL 事件。

虚拟模块仅存在 debug variant，Manifest 同时声明 `android:testOnly=true`；生产
App 不依赖该模块。隔离测试会持续阻止虚拟外设进入发布 APK。

## 四个确定性场景

| 场景 | 虚拟盒子行为 | App 侧断言 |
| --- | --- | --- |
| `success` | 普通写入并返回匹配响应 | 发现、连接、读信息、两路订阅、命令完成 |
| `auto_bond` | 特征声明加密写权限，让系统触发 SMP | 安全恢复、GATT 重建、通知恢复、原字节仅重试一次，禁止条件式兜底 |
| `fallback_once` | 第一次完整命令返回 GATT 5，Bond 后才接受 | 2 秒条件式 Bond 兜底、GATT 重建、盒端确认同一 SHA-256 且只重试一次 |
| `disconnect_once` | 首个请求写成功后主动断链；重连时先注入旧请求响应 | 至少两个连接代次，旧 `request_id` 不能完成新请求，新响应正常完成 |

集成测试直接实例化生产 `PlatformBirdBoxBleDataSource`，并经过生产
`BirdBoxBleChannel`，没有另建一套 App BLE 实现。

## 双 AVD 运行器和证据

`tool/ble11/setup_ble11_avds.ps1` 负责版本检查、离线复用现有系统镜像并创建
`ble11_app_api36`、`ble11_box_api36`。`tool/ble11/run_ble11_dual_avd.ps1`
负责：

- 固定 AVD-A 为 `emulator-5554`、AVD-B 为 `emulator-5556`，并核对实际 AVD
  名称，防止把其他正在运行的模拟器误当测试目标；
- 隐藏启动两台 AVD，向 netsim 传入 `--pcap --rssi=ble:-55`；
- 构建、安装、授权并执行指定场景；
- 收集 App 脱敏诊断、盒端事件、模拟器/API 身份和 netsim PCAP SHA-256；
- 输出 `evidence_kind=simulated`、`hardware_status=pending` 的证据 JSON。

证据校验器 fail-closed：缺少 PCAP、场景断言、恰好一次重试、GATT 重建、
陈旧响应注入，JSON/文本证据出现完整 MAC/凭据，或者尝试把 AVD 证据提升为
硬件通过，都会使运行失败。原始 PCAP 可能含链路层标识，只能作为本地受限调试
产物保管；可外发 JSON 只记录其相对路径和 SHA-256，不能把 PCAP 本体当作脱敏
附件。

Android 官方文档说明，Emulator 36.5+ 的 netsim 支持 BLE RSSI 控制、PCAP
以及多模拟器共享虚拟网络。本实现按该边界主动拒绝 36.2.12，而不是运行一个
不具备目标能力的弱化测试：

- https://developer.android.com/studio/run/emulator-networking-interconnect
- https://developer.android.com/studio/run/emulator-networking-advanced

