## 1. 当前结论

当前可以继续完成正式 App 的权限、扫描、配对页面、生命周期、验证码、HTTP 业务、首页及诊断文件验收。两台手机可交替充当 App 和手机虚拟外设；HTTP 业务另用电脑 Mock 服务配合。

蓝牙已有明显进展：**同一候选的两方向七项定点矩阵共 14 项通过，双向首次绑定成功、系统配对取消和超时均有真实记录。** 但补充首次绑定出现一次 vivo 新 GATT 连接 status 133，尚未关闭。**BLE-22C 仍未通过，不能直接把 BLE-22D/E 登记为完成。**

下一步优先级：

1. 复现并处理 vivo 首次绑定后的 GATT 133，确认正常首绑稳定性。
2. 补正式入口的权限、设置返回、页面重试、取消和生命周期验收。
3. 补验证码到 HTTP 会话、首页的 App 业务验收，以及完整诊断保存/分享验收。
4. 整理测试工具与构建身份，再按同一候选完成双方向数量和场景要求。

## 2. 两台手机如何使用

| 组合 | 用途 | 可取得的证据 |
| --- | --- | --- |
| P1：华为 App → vivo 手机虚拟外设 | SDK31 的原生 BLE 与正式连接页面 | 扫描、绑定、GATT、通知、命令、失败终止 |
| P2：vivo App → 华为手机虚拟外设 | SDK27 的原生 BLE 与正式连接页面 | 老系统安全重建、认证恢复、分片超时、首次绑定 |

| 两手机分别运行 birdSim → 电脑 HTTP Mock | App 业务与首页 | 验证码、模拟网络状态、HTTP 身份/会话、REST/WebSocket、三标签首页 |

华为为 FIN-AL60，Android 12 / SDK31；vivo 为 X20，Android 8.1 / SDK27。两台均已实际启动五特征 GATT Server 并获得广播成功回调。

**原生手机 BLE 和 birdSim HTTP 是两条独立测试路径。** 不能把它们的分段通过拼成一次真实完整配网通过。当前结论也只适用于这两个手机组合，不推断其他型号或 Android 版本。

## 4. 蓝牙已经实施的修改

这些改动已在当前工作区和第 18 轮候选中，后续应验证其适用范围。

| 已实施修改 | 解决的问题或目的 |
| --- | --- |
| SDK≤28 安全重建先完成 MTU 操作，再发现服务 | 将旧系统的准备步骤串行化；无回调时有界失败；同步拒绝时保留 MTU 23 |
| 已断开的旧 GATT 登记保留到完整会话拆除 | 避免旧客户端注销干扰新连接映射；历史登记有上限，旧回调不能推进当前请求 |
| 会话拆除先断开/关闭当前 GATT，再释放旧登记 | 改善 teardown 顺序，取消和失败均释放资源 |
| 修复普通连接 15 秒计时器的归属判断 | 新 GATT 创建后不再跳过超时处理；缺少连接/服务回调及迟到回调有界处理 |
| 补关键诊断及保留策略 | 区分系统绑定、GATT 连接、MTU、服务、CCCD、ATT 和业务失败 |
| 修正测试权限、广播事件 scenario 字段、脚本退出码 | 避免启动工具错误阻断测试或使后续场次被跳过 |

早期“SDK≤28 服务发现前固定等 1 秒”的调整在手机上无效，已经移除。旧连接断开确认后的 settle gate 属于另一阶段，仍存在。

当前没有使用隐藏刷新接口、反射清空绑定或额外受保护命令重试；也没有加入尚未经本轮验证的 `autoConnect=true` 改动。

## 5. 蓝牙接下来应修改或核查哪些地方

### M01：首次绑定后的 GATT 133 —— 第一优先级

**已观察到的失败：** `20261012-213905-P2-bond_first-3-c18f4b`。

vivo 从未绑定起点发起一次系统绑定，绑定完成；旧 GATT 确认断开后创建新客户端。新客户端注册成功，但连接回调立即返回 status 133，最终为 `BLE_GATT_RECOVERY_FAILED`，没有受保护写入。实际失败文件已经接收。

这次停在 `gatt_connect`，不能继续按“服务发现或 MTU 无回调”处理。一次后续首绑因未确认系统请求而超时，没有进入新 GATT，也不能用来证明 133 消失。

实施顺序：

1. 固定角色、APK 和两端测试绑定基线，在两端实际确认系统配对后重复 P2 首绑。
2. 核对旧断开确认、客户端注册、新连接回调及外设生命周期；区分注册失败、连接失败与迟到旧回调。
3. 若重现，针对证据做最小改动，先复测触发场景，再回归两方向矩阵。具体连接策略目前待确定，不能先写成“已修复”。
4. 保持取消、超时、连接代次归属和受保护命令恢复上限；失败时完成资源释放，重试从新会话开始。

主要代码：`android/app/src/main/java/deckers/thibault/aves/BirdBoxBleChannel.java`、`BirdBoxBlePlatform.java`；对应 `BirdBoxBleBridgeTest.java`。

完成标准：实际完成系统绑定后，稳定进入新连接、MTU/服务、两路通知和命令终态；没有未解释的同类关键失败。

### M02：修正“绑定成功”等同于“安全连接已建立”的错误提示

`lib/bird_companion/core/errors/user_message_mapper.dart` 当前将 `bleGattRecoveryFailed` 显示为“安全连接已建立，但重新连接盒子失败”。本轮失败时系统绑定确已完成，但新 GATT 和通知尚未准备好，没有成功受保护写入。

建议修改为“蓝牙连接未能恢复，请重新连接后重试”等与实际结果一致的表述；保留错误码、失败阶段和首个根因，按钮实际执行拆除旧会话后的重新连接。

同时分别验收 `BLE_PAIRING_REJECTED`、`BLE_PAIRING_TIMEOUT`、GATT 恢复失败、加密写入重试失败和业务响应超时。错误提示不能用同一句话覆盖所有阶段。

### M03：正式页面取消、重试与设置返回的会话归属

这是**源码核查与待测项，尚未登记为真机缺陷**。

当前 `ProvisioningCubit` 已有 action generation、session owner、首个失败保留和重试拆除逻辑；需要在正式页面证明这些机制完整生效。

具体核查：`reset()` 清除了位置设置等待，但没有对称清理权限设置等待及两类“已经离开设置”标记。应补 reset/重新进入页面/设置打开失败/迟到返回回调的回归，确认旧设置返回不会重启旧扫描，也不会阻止下一次打开设置。按复现结果统一清理标记。

主要代码：`provisioning_cubit.dart`、`connection_page.dart`、`provisioning_repository_impl.dart`、`platform_birdbox_ble_data_source.dart`。

### M04：完善配对和双机测试工具

这是明确需要完善的**测试工具工作**，不能据此判定 App 蓝牙本身错误。

- 补华为弹窗的实际资源 ID，例如 `com.android.settings:id/message_subhead`。仅补文案或按钮匹配还不足以核对地址型对端身份。
- 对只显示地址的弹窗，先建立当前运行的对端身份依据，例如虚拟外设连接事件的对端地址哈希；匹配不到时保留人工操作，不能按任意“配对”按钮代点。
- 将配对成功、取消、超时作为独立专项结果，保留原始集成测试退出码；未知界面、未授权、设备中断均不得登记通过。
- 手机身份使用可核对的物理身份，ADB USB/网络选择器另记，避免同一 vivo 被算成两台设备；调试运输方式也应准确记录。
- 把本次 `build/` 中经验证的角色切换、观察、精确测试绑定清理和已接收副本清理流程整理到 `tool/ble22/`；手机未在线时不得因 Optional ADB 返回空值而误报清理成功。
- 每场启动前核对两机在线、APK hash 和当前广播；设备重启或掉线时停止该场，保存实际阶段并重新建立基线。

修改维护工具或虚拟外设后记录新的身份和 APK hash，按新候选组织后续验收。

### M05：诊断缓存满后的可恢复性

本次重复测试真实碰到 `diagnostic_cache_full`，两场未能准备导出文件。当前策略为最多 32 份/128 MiB，并保护近期文件；这不是“已有完整导出，只是工具没收到”。

应完善测试副本释放和 App 的恢复提示/入口，验证已保存文件后的缓存管理、失败重试和容量边界。不能默认分享面板打开就代表文件送达，也不能为让测试通过直接清空所有诊断、删除尚未接收文件或扩大配额。

主要代码：`BirdBoxDiagnosticFileWriter.java`、`BirdBoxBleDiagnosticFileChannel.java`、`ble_diagnostic_export_dialog.dart` 及接收工具。

## 6. 正式 App 还应在两手机上测试什么

以下主要属于 BLE-22D/E。测试发现失败后修改对应模块；仅有本地回归的项目，当前均保留待手机验收状态。

### A. 权限与扫描环境

| 场景 | 预期结果 | 失败时修改方向 |
| --- | --- | --- |
| 华为附近设备权限；vivo 定位权限：允许、拒绝、重复拒绝 | 提示符合实际权限状态，不转成通用 GATT 错误 | 原生权限映射、环境读取、页面错误映射 |
| 永久拒绝后打开 App 设置，授权并返回 | 重新读取权限，按当前页面和会话扫描一次 | 设置等待标记、generation 与生命周期回调 |
| 设置未授权就返回，或设置无法打开 | 不假装已获授权，仍可再次操作 | 打开失败与返回分支 |
| vivo 位置服务关闭、打开并返回 | 适用的兼容条件正确提示和恢复 | 位置环境判断及自动扫描条件 |
| 华为位置开关变化 | 按当前 SDK/机型实际要求处理，避免不必要地要求权限 | 平台条件与机型兼容规则 |
| 蓝牙关闭、打开并重试；扫描取消/超时/再次扫描 | 无卡死、无并行扫描、旧结果不污染新列表 | 扫描停止、所有者和代次 |

这组必须使用正式入口和真实系统界面，不能通过 `-g` 或 `pm grant` 代替权限验收。

### B. 连接页面与生命周期

- 点击设备、连接、系统配对、应用验证码、失败重试的页面顺序与实际阶段一致。
- 系统弹窗导致 Activity 暂停时，不误取消当前绑定；返回后不重复打开窗口。
- 页面返回、主动取消、快速重复点击、连接中切换前后台、锁屏再解锁、对端退出和蓝牙关闭后可恢复。
- 新页面/新请求不会被旧扫描、旧 GATT、旧网络事件推进；同一按钮不产生两次命令。
- 失败后点击重试重新建立会话并核对 Device Info，首个根因不被后到的断开错误覆盖。
- 若模拟 App 进程重启，重新进入页面后的会话恢复符合入口规则，没有恢复旧验证码或失效临时授权。

主要模块：`connection_page.dart`、`provisioning_cubit.dart`、BLE data source 与原生生命周期插件。

### C. 完整 BLE 数量与故障矩阵

两方向各执行：首次未绑定至少 5 次、已有绑定至少 5 次，总计至少 20 次正常完整路径，另外执行故障和生命周期场景。

当前 C 的首绑定点通过和 14 项矩阵不是这 20 次。旧候选成功不得合并；C 记录能否计入须先核对候选、基线与完整操作要求。

补充场景：对端断开、延迟响应、错误 request_id、重复响应、业务响应超时、页面取消、连接中关闭蓝牙、重新扫描，以及完整数量复测。已通过的认证/ATT/通知场景在最终候选上按要求回归。

小 MTU 需要区分真实协商结果与测试分片上限：当前 ATT 场景将消息片限制为 20 字节，**不能因此登记实际链路 MTU=23 通过**。若当前手机组合无法构造实际小 MTU，明确记录该项覆盖限制，保留编码/边界回归，不伪填手机验收结果。

### D. 应用验证码与授权

- 错误码到正确码、错误次数耗尽、窗口过期、重新打开窗口、重复提交和重试。
- 过期/拒绝后不进入方式选择；重新开窗口不错误重置仍有效窗口的错误次数。
- 验证码、密码、临时会话和 Token 不进入页面状态、日志或诊断明文；HTTP 会话兑换不发送应用验证码。
- 旧授权响应不能推进新连接，重复 request_id 不重复执行业务。

原生虚拟外设应用验证码为 `246810`；birdSim 为 `123456`，窗口/次数按各自实现核对。**二者均不能填入系统蓝牙 PIN 请求。**

### E. birdSim + HTTP Mock 的业务验收

两手机分别使用独立新 Mock 会话，执行真实手机页面和真实 HTTP：

| 检查 | 预期结果 |
| --- | --- |
| 模拟 AP/STA 成功、失败、等待、取消与返回 | 页面跟随当前 operation_id，不被旧事件误推进 |
| `/health` 超时、暂不可达、身份不匹配、协议异常 | 有界失败；失败时不激活成功会话或进入首页 |
| 临时会话到期、已消费、client/device 不匹配 | 严格拒绝，重新授权或重试入口可用 |
| 正常会话兑换 | 身份核对成功后激活 REST/WebSocket，进入相册/任务/设备三标签首页 |
| Mock 停止/恢复，HTTP 或 WebSocket 断开 | 错误提示、重连和旧请求失效行为正确 |
| 模拟会话与已保存凭据隔离 | 不覆盖或错误恢复其他入口的凭据 |

主要模块：`network_provisioning_cubit.dart`、`provisioning_repository_impl.dart`、`health_api.dart`、`pairing_api.dart` 及 `core/session/`。

原生虚拟外设有自己的能力声明，不支持的扫描/DPP 操作应按协议拒绝；不能为展示成功页面硬填事件。HTTP Mock 的网络状态模拟仅用于这组 App/HTTP 业务证据。

### F. 完整诊断文件的正式页面验收

- 从正式页面导出一次成功、一次失败的完整记录，包含扫描历史和连接历史。
- 核对 retention：记录保留量、裁剪、历史缺失和关键事件缺失均准确标注。
- 两手机分别实际保存 JSON/ZIP、取消保存、改选位置、失败后重试；以保存后的内容重新读取校验。
- 打开分享面板、取消、重复导出，并在约定的测试接收位置核对实际收到的文件。打开面板不等于送达。
- 接收端独立核对长度、文件 SHA-256、payload hash、JSON/ZIP 内容和构建身份。
- 测试容量边界、进程/页面退出和读写失败，不能提示“成功”但实际没有文件。

当前 transport 的 26 份已接收文件主要覆盖连接事件，**尚不能代替正式页面的完整扫描历史、保存和分享验收**。

### G. 首页和 App 基础体验

HTTP Mock 已覆盖正式 Repository 使用的相册、审阅、任务、复制、存储、设备状态与设置，可在两手机上继续测试：

- 相册分页、快速滚动、刷新、详情、图片资源待就绪/失败/重试。
- 审阅与批量选择、任务进入/返回、复制任务进度、取消和重试，按 Mock 实际支持的行为核对。
- 断网/服务器重启时各页面的错误和恢复，重复推送不重复添加记录。
- 大字体、键盘弹出、验证码/STA 表单滚动、长错误信息和诊断弹窗布局。
- 在 Android 8.1 与 Android 12 上核对文件选择器、分享面板和系统返回，避免只根据 Widget 测试登记通过。

这些是 App 页面与客户端行为测试；无已证实缺陷的页面先实测，再按结果修改。

## 7. 接下来按什么顺序实施

| 顺序 | 对应批次 | 工作 | 完成条件 |
| --- | --- | --- | --- |
| 1 | BLE-22C 续测/收尾 | 关闭 M01；安排 M02；整理 M04，补与改动相关的回归 | 首绑关键失败关闭、正常和预期终止结果明确 |
| 2 | BLE-22D | 冻结候选，两方向正常次数及完整故障/生命周期 | 至少 20 次正常路径和要求的专项场景满足；无未解决关键失败 |
| 3 | BLE-22E：权限与页面 | A/B/D，包含 M03 设置等待与 reset 核查 | 两手机真实权限、设置、页面、取消、重试记录完整 |
| 4 | BLE-22E：业务与文件 | E/F/G，包含 M05 缓存恢复 | 独立 Mock 会话到首页，实际文件保存/接收校验，页面问题已处理 |
| 5 | BLE-22F：App 范围汇总 | 对齐 APK、源码指纹、场景、次数和文件结果 | 成功、预期失败、未完成、覆盖限制均按事实登记 |

涉及 BLE/共同会话逻辑的修改，需要在新冻结候选上回归受影响的两方向场景；纯 UI 提示改动也要核对最终 APK 身份和相应页面行为。不要把不同构建的成功记录拼在一起。

现在的具体起点是 **BLE-22C 续测与工具整理**。正式权限、页面和 HTTP 模拟业务可以独立准备；完整 BLE 验收通过统计应在关键失败关闭、候选冻结后进行。
