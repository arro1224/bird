## 3. 晋级条件

新门禁只有在以下条件同时满足时返回 `releasable=true`：

1. BLE-03 证据校验器返回 `hardware_status=verified`；
2. BLE-03 明确选择 A 或 B，正式包扫描策略与选择一致；
3. A 对应 `never_for_location`，B 对应 `full_scan`；
4. 合并后的正式 Manifest 中只有一个 `BLUETOOTH_SCAN`，其
   `neverForLocation` 状态与 A/B 结论一致；
5. 生产 `BuildConfig.BLE_SCAN_PERMISSION_POLICY` 与 Manifest 一致，避免诊断日志
   报告错误策略；
6. 包名为 `deckers.thibault.aves.bird`，不是 `.bird.v1` 或 A/B 调试包；
7. APK 为 `app-bird-release.apk`，版本、APK SHA、Git SHA、签名证书均匹配；
8. Git 工作树干净，正式签名和 `apksigner` 验签均已确认；
9. 生产源码不存在 `createBond()`、`ensureBonded` 或
   `disconnectGattBeforeBond` 旧前置路径；
10. 发布审批和真实回滚记录存在，文本证据不含密码、Token、配对码、完整 DPP URI
    或完整 MAC。

任一项失败时，进程非零退出，并输出 `status=blocked`、`releasable=false`。

## 4. 与既有发布门禁的关系

B7 Release 现在要求四组材料，互不替代：

1. 通用真实盒子 E2E；
2. 既有 BLE RC4 K7-01～K7-10 证据；
3. 本次 RC4-HF-BLE-03/04 热修证据与正式包晋级记录；
4. B12-B 真实硬件证据。

只有四组门禁和签名验证全部通过，B7 最终证据才会记录
`environment=real_k7`、`releasable=true`。
