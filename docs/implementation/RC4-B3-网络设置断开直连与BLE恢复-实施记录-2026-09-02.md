## 1. 本批次目标

1. 在正式设置体验中增加“网络设置”入口，统一承载切换 Wi-Fi 和停止盒子直连。
2. 停止直连固定发送 `stop_direct_ap(restore_previous_sta=true)`，不把 `command_accepted` 或热点消失判为成功。
3. 按冻结协议区分恢复原 Wi-Fi、回退直连热点、无已保存 Wi-Fi、双重恢复失败四种结果。
4. BLE 中断不取消盒子已接受的网络操作；同设备重连后读取 `get_network_status`，按 `operation_id` 恢复界面并忽略旧事件。
5. 恢复到可用网络后继续执行 `/health.device_id` 一致性校验，再更新业务会话。

## 2. 实施结果

### 2.1 正式网络设置入口

新增 `NetworkSettingsPage`，并接入：

- 设备设置首页“网络设置”；
- 旧设置页“连接方式”；
- 网络诊断页“切换网络”；
- `BirdRoutes.settingsNetwork` 正式路由与全局 `ProvisioningRepository`、配网完成处理器。

当前存在可信 BLE 会话时，页面先读取盒子权威网络状态；不存在或中途丢失 BLE 时，展示“重新连接并恢复状态”，明确提示盒子操作仍会继续，断线不等于成功。

### 2.2 停止直连终态

点击“停止盒子直连”先显示二次确认，明确告知盒子将关闭热点、尝试恢复旧 Wi-Fi，且图片传输可能短暂中断；只有用户确认后才发送命令。

状态机现按以下规则处理：

| 盒子终态 | App 处理 | 页面结论 |
| --- | --- | --- |
| `sta_connected`，同 `operation_id` | 再读 Network Status，并确认 `infrastructure_sta + sta_connected + base_uri` | 原 Wi-Fi 已恢复；完成后更新业务会话 |
| `network_recovered(recovered_mode=direct_ap)` | 使用事件返回的实际热点参数重新加入、绑定并校验 `/health` | 之前的 Wi-Fi 恢复失败，盒子已重新开启直连热点 |
| `direct_ap_stopped(reason=no_saved_sta_profile)` | 释放旧直连绑定，保留 BLE | 热点已关闭但没有可恢复 Wi-Fi，引导重新配网 |
| `NETWORK_RECOVERY_FAILED` | 不伪报成功，保留安全错误结果 | 原 Wi-Fi 和直连热点均未恢复，保留 BLE 并重新配网 |

`DirectApStopped.reason` 已进入非敏感展示状态，避免把“无保存配置”误写成普通停止成功。

### 2.3 BLE 中断与状态恢复

新增可选的 `ProvisioningSessionRepository` 生命周期边界：

- 只读当前可信 `connectedDeviceInfo`；
- 暴露只读 `disconnects` 流；
- 标记本次连接是否属于同设备重连。

生产 Repository 在 BLE 断开时只清理 App 侧瞬态会话，不向盒子发送取消命令。连接同一 `device_id` 后，Repository 读取 Network Status 并恢复当前 `operation_id` 的事件过滤表；展示层的 `resumeAfterBleReconnect` 只接受该操作的后续进度和终态，旧 operation 事件继续被丢弃。

首次配对不会被误判为“重连恢复”，仍进入正常连接方式选择；恢复动作在一次连接会话中只消费一次，避免返回页面后循环恢复。

### 2.4 终态可达性与身份校验

新增可选的 `ProvisioningNetworkStatusVerifier`。生产实现只验证非 busy 的稳定终态：

- Direct AP：保持现有 Android Network 绑定并校验 `base_uri`；
- STA：释放旧 Direct AP 绑定后校验新的 `base_uri`；
- 两者均通过 `/health.device_id == BLE device_id` 和安全会话交换后，才允许展示为成功。

非终态、缺失 `base_uri` 或身份不一致会失败关闭，不会根据手机当前 Wi-Fi 图标推断成功。

### 2.5 页面结果与错误文案

- STA 稳定终态增加“切换 Wi-Fi”入口；
- Direct AP 稳定终态保留“停止盒子直连”；
- 回退 Direct AP、无保存 STA 和网络恢复失败使用不同文案；
- `NETWORK_RECOVERY_FAILED` 明确提示蓝牙连接会保留并要求重新配网；
- DPP/Wi-Fi 二维码三入口及 B7 演示文案兼容性保持不变。

## 6. 真实设备验收清单

1. Direct AP 下点击停止，盒子存在 last-good STA：确认返回 `sta_connected`，手机回到同一 Wi-Fi，`/health.device_id` 一致。
2. 旧 STA 不可用：确认收到 `network_recovered(direct_ap)`，手机按事件返回热点重新加入，业务请求仍走绑定 Network。
3. 无保存 STA：确认 `direct_ap_stopped(no_saved_sta_profile)`，热点关闭、BLE 保留并可立即重新配网。
4. STA 和 AP 均恢复失败：确认 `NETWORK_RECOVERY_FAILED`，不得显示成功，不得丢失 BLE。
5. 分别在 `command_accepted` 后、`stopping_ap`、`recovering`、终态到达前关闭蓝牙，再打开并重连；确认恢复同一 operation。
6. 注入旧 `operation_id` 的迟到进度/终态，确认 App 忽略。
7. 开启蜂窝网络、锁屏/前后台切换、不同 Android 厂商系统重复上述矩阵。
8. 抓日志确认无 Wi-Fi/AP 密码、验证码、Token、完整 DPP URI 和完整 MAC。
