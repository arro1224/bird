# BLE-22A、BLE-22B 实施与离线验证记录

日期：2026-10-12（北京时间）。在项目 4 现有工作区上实施，保留 BLE-17～21 和前十轮实测改动。本次范围为离线代码、工具、回归和 APK 准备；双手机 BLE 测试仍按用户要求暂停。

## BLE-22A 已实施

服务发现 API 的实际调用、同步接受/拒绝、权限/运行时异常、接受后缺失有效回调和服务属性不匹配分别记录。事件关联请求、连接/GATT 代次、阶段与发现耗时。旧 GATT、已结束操作和错误阶段的服务回调有明确丢弃原因，每次连接最多记录 8 条，仍然不能推进当前请求。新增实现使用旧 Android 支持的集合 API。

现有五特征/属性/CCCD 校验、请求归属、取消清理、恢复次数与等待策略保留；SDK27 的 1 秒发现等待仍是待真机验证的兼容调整。这批增加了定位能力，不代表已关闭 vivo 服务发现阻塞。

集成入口将扫描、初始连接、设备信息读取、初始通知和安全准备失败纳入统一证据收集。早期失败保存实际阶段、错误类型与已发生的事件；尚未执行命令时不填请求/命令完成事实。导出失败记录 `export_status=failed` 并保存已有结果，保留原始传输异常。证据校验器拒绝早期失败或运行器失败登记为场景通过。

涉及生产原生桥、原生桥回归、Dart 诊断模型和关键事件保留策略、BLE-11/BLE-22 集成入口、失败收集助手和先绑定证据校验器。

## BLE-22B 已实施

| 工具 | 行为 |
| --- | --- |
| `tool/ble22/Ble22.Tools.psm1` | 原生进程参数按独立 ArgumentList 传递；安装/驱动超时终止自有进程；设备界面互斥；系统窗口/目标/控件检查；实际二进制文件接收和 SHA-256 核验 |
| `run_phone_round.ps1` | 双端安装与实际 hash 校验；启动、VM、转发、测试和清理纳入失败记录；未执行测试用 null exit code；只清理自有资源；最终事件收集和清理后再校验 |
| `install_phone_apk.ps1` | 分开 Ui 与 Transport 权限模式；正式 Ui 安装不自动授权；安装结果明确留存 |
| `operator_ui.ps1` | 安装、目标配对、120 秒可发现及指定页面应用按钮的单步操作；系统 PIN 或歧义控制不猜测 |
| `prepare_round.ps1` | 四类 Debug APK 顺序构建、包名/版本/hash 和源码指纹检查；轮次目录不可覆盖；无手机操作 |
| `verify_received.py` | 独立工作目录运行；成功/失败文件均可验证；校验 final/payload hash、字节数、结构与关键记录完整性；无文件为 skipped |
| `summarize.py` | 显式输出位置，保留已有暂停/当前轮/交接状态；启动、清理失败不能借旧通过日志；硬件门禁保持关闭 |

原 `build/` 临时助手保留为历史文件，后续使用 `tool/ble22/` 的维护版本。没有迁移泛化自动删除绑定的操作；首次绑定测试仍需确认目标及两端真实系统基线。

安装与配对 UI 策略目前通过离线 XML 检查，真实厂商窗口匹配留待 BLE-22C。匿名 `null` 请求不被猜测为测试对端；外设侧自动配对需要明确 App 手机蓝牙名称。正式权限测试不得沿用 transport 自动授权结果。完整扫描历史及正式页面保存/分享仍待 BLE-22E。

## BLE-22C 接机与定点复测

离线构建及身份核验完成后可以接回华为 FIN-AL60 与 vivo X20。首先恢复 vivo 上轮未还原的临时日志标签，核对转发归属与安装包；不沿用手机原先已安装版本的假设。

先执行 P2（vivo App→华为外设）普通已绑定连接，确认发现 API 调用和回调；再执行 `auth_once`、持续认证失败、ATT 首/中/末片及通知重建故障，随后检查 P1 方向。关键失败关闭后再进入双向各 5 次首次绑定、5 次已绑定的完整验收。当前 APK 构建成功不能计入这些次数。

依据：[子批次计划](RC4-HF-BLE-22-修复实施批次与双手机续测安排-2026-10-12.md)。工具操作与正式入口测试准备见 [BLE-22 README](../../tool/ble22/README.md)。
