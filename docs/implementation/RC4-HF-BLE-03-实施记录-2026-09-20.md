## 2. 诊断导出收口

新增两个用户可见入口：

1. `pairing_opened` 后的验证码页：“复制本次配对诊断”；
2. `pairing_authorized` 后的连接方式页：“复制完整配对诊断”。

导出内容沿用 schema v2，同时包含扫描 session 和同 trace 的连接事件。这解决了
配对成功后无法从页面取出 `authorize_pairing` 完整证据的缺口。

## 3. 专用验收门禁

`tool/acceptance/rc4_hf_ble_03_evidence_validator.dart` 要求：

- Huawei A/B `baseline` 各 10 次；
- 最终候选包在 Huawei 的蓝牙重开、权限重授、前后台恢复场景各 10 次；
- 最终候选包在 OPPO 连续 10 次发现 BirdBox；
- OPPO PKC110 / API 36 连续 5 次首次配对；
- 安全特征写、Bond 转换、最多一次重试、两路通知恢复、matching response、
  `authorize_pairing` 和 K7 同步日志全部匹配；
- 已配对重连不再显示验证码，已接受任务不因 BLE 临时断开而停止；
- App、板端和 QA 三方审批；
- APK SHA 真实性和证据脱敏性。

模板 `docs/acceptance/rc4-hf-ble-03-evidence.template.json` 默认是 `pending`，
空证据、占位符、缺少硬件或不匹配的 APK 都不会通过。
