# RC4-HF-BLE 后续实施批次规划（2026-09-23）

## 当前基线

BLE-07～09 已完成诊断、幂等清理和条件式 Bond 兜底的 App 代码实现。当前缺少
OPPO/Huawei 真机和真实 BirdBox，因此后续批次以“提高可验证性、冻结候选行为”
为目标，不继续猜测性修改生产配对策略，也不把模拟结果登记为真机通过。

## BLE-10：原生确定性模拟与可测试性加固

目标：把条件式 Bond 兜底的时间、会话和状态判定抽成无 Android 框架依赖的纯
Java 策略，使其可以使用假时钟稳定验证。

实施范围：

- 生产桥继续负责 `BluetoothDevice`、Handler、广播和 GATT 副作用；
- 策略组件负责 2 秒宽限期、明确 GATT 鉴权状态、请求 ID、连接代次、Bond 状态
  以及“每请求只执行一次”的决策；
- 覆盖系统先进入 BONDING/BONDED、普通写失败、过期请求、连接代次变化、会话
  清理和新请求重置；
- 不新增生产入口，不改变协议、UUID、超时、密文或重试次数。

退出条件：Android 单测、App Java 编译、Flutter 静态分析和全量测试通过。

## BLE-11：双 AVD 虚拟 BirdBox 集成

当前状态（2026-09-23）：实现、离线测试和 APK 编译已完成；本机 Emulator
36.2.12 不满足 36.5+ 前置条件，四个双 AVD 场景运行验收保持 pending。详见
`RC4-HF-BLE-11-实施记录-2026-09-23.md`。

前置：把本机 Android Emulator 从 36.2.12 升级到 36.5+，创建两台 API 31+
AVD。升级和系统镜像下载需要单独执行，不属于 BLE-10。

实施范围：

- AVD-A 运行当前 BirdBox App，作为 BLE Central；
- AVD-B 运行 test/debug-only 虚拟 BirdBox，广播冻结 Service UUID 并提供五个
  GATT 特征；
- 虚拟盒子支持加密写、两路通知、匹配 `request_id` 的 `pairing_opened`、主动
  断链和可控错误；
- 自动断言 Bond 后 GATT 代次递增、MTU/服务恢复、两个通知恢复、原密文只重试
  一次；
- 采集脱敏诊断和 netsim PCAP，证据标记为 `simulated`。

退出条件：双 AVD 正常路径、自动 Bond 路径、一次兜底路径、断链恢复和陈旧回调
隔离全部通过。该结果只能证明 AOSP 模拟栈，不证明 OPPO ColorOS 兼容性。

## BLE-12：候选冻结与模拟证据包

当前状态（2026-09-23）：已生成并通过完整性校验的候选
`ble12-7d0bd5022c38c760`。本机 Emulator 36.2.12.0 仍低于 36.5+，因此
`simulation.status=pending_environment`；真实硬件状态保持 pending，正式发布
门禁保持阻断。详见 `RC4-HF-BLE-12-实施记录-2026-09-23.md`。

实施范围：

- 固定 Git SHA、APK SHA、构建环境、自动测试报告和双 AVD 诊断；
- 增加 fail-closed 模拟证据校验，禁止把 AVD 序列号或模拟结果写成
  `hardware_status=verified`；
- 生成将来外场联调所需的 APK、操作手册、诊断复制说明和回传模板；
- 冻结 BLE 生产行为，只接受由新证据证明必要的修改。

退出条件：模拟证据包可重复生成并通过完整性校验，正式发布门禁仍保持
`hardware_status=pending`。

## 最终不可替代门禁

未来硬件到位后，仍须按 BLE-03/04 门禁在 OPPO、Huawei 和真实 BirdBox/K7 上
完成首次配对、板端 PairingAgent、Bond 后重连、通知恢复、相同请求单次重试和
同进程再次连接验证。BLE-10～12 均不能替代该门禁。
