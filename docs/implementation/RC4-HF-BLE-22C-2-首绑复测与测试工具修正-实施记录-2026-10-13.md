## 实施内容

| 改动 | 目的与限制 |
| --- | --- |
| `BirdBoxBleChannel.failNativePreparation(code, status)` | 将连接、服务、CCCD 回调的实际失败状态保留到错误详情、诊断及释放记录；133 与阶段仍可关联。未收到回调的超时没有实际 status，不把释放时使用的 257 当成连接回调。 |
| `New-Ble22PairingPump` | 修复逃逸闭包无法调用脚本局部 `Read-BoxEvents` 的问题；仍要求本场外设连接及唯一对端哈希。 |
| 配对 UI 识别 | 普通“已配对的设备”列表不会误触发未知配对弹窗阻断；未知实际请求和 PIN 输入仍不自动处理。 |
| `-ForegroundPairingSettings` | 本场连接后，两端各打开系统设置一次，使厂商配对请求可见；实际确认动作单独记录。只是虚拟手机外设测试条件，不能变成正式产品的手工预配对要求。 |
| `phone_inspection_semantics.dart` | 在 testWidgets 记录基线前固定测试平台 semantics，结束恢复；保留测试自有句柄的计数和释放检查。正式 App 不使用该帮助函数，不代表生产辅助功能验收。 |
| 原生日志收集 | 停止进程前收集自有 App / 外设进程日志并记录 SHA-256；empty、missing_process、failed 分别保留。华为部分标签为空，不能据此断言没有原生行为。 |
| 导出检查点 | 连接收集完成后，先同步写临时文件并在 Android 上 rename 替换实际 App 结果，再按事件存储、快照、构建身份、Native prepare 记录阶段；pending 不是 prepared 文件。避免读到半写 JSON，不回写已有缺文件场次。 |
| 已收集结果的前台返回 | 已知系统设置前台测试条件下，只有同 run_id / scenario、自有包、已收集的 transport 结果及已知 pending 阶段才返回测试 App 一次；校验前后 PID，单独记录环境动作。旧请求、未知阶段、prepared 结果不触发，未作为正式产品步骤。 |
| `open_test_bond_detail.ps1` / `reset_test_bond.ps1` | 有界遍历观察到的测试名称及详情按钮，校验当前系统详情 Fragment 地址哈希和唯一解绑控件。华为“更多”按观察控件展开；vivo 不可点击的 Preference 标签只在精确 Native 身份匹配时点击。未知条目不清理，不使用隐藏解绑接口。 |

连接策略、一次加密恢复上限、原生时限和代次归属未改动；没有以增加固定等待、恢复次数或隐藏 refresh 来宣称修好 133。

## 绑定身份与环境

实际 BLE 地址与系统身份地址不同。系统详情中的同名条目可能属于不同地址，因此失败的查找和解绑动作均保留；只点击了实际 GATT 对端匹配项或已验证物理测试手机的自身身份匹配项。

vivo 自身身份来自已选物理手机的 secure Bluetooth address；华为拒绝 ADB 读取该 secure 设置，公开 dump 也遮蔽部分地址，随后通过自有系统“状态信息 / 蓝牙地址”页面核对，仅保存哈希。系统详情 Fragment 参数精确匹配后才清理对应测试绑定。点击动作不证明未绑定，下一场仍检查两端实际原生状态。一次双端清理后成功与前一场失败的差异不能直接解释为 133 的根因。

手机有过锁屏及前台离开测试页面的情况；用户确认解锁、提供专用测试窗口并授权由工具点击测试配对请求。未认定用户点击错误。系统 PIN 与 App 验证码没有混用。

临时日志标签和亮屏超时已保存原值。两台手机一度离线，后续恢复检查时重新在线，四项日志标签与两项超时均恢复原值并回读一致，自有测试 App/外设进程停止已核验，错误列表为空。用户随后明确停止真机测试并要求文档交接与工作区整理，停止后没有继续 BLE 场景。恢复审计见 `outputs/ble22/ble22c2-20261013-observation/cleanup-verification.json`。恢复脚本只处理已记录的标签、原超时、自有测试进程与精确任务临时文件，不改 ADB 后端或清空诊断目录。
