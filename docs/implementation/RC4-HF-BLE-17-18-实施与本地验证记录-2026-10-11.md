## BLE17绑定状态推进

`BirdBoxPairingCoordinator` 先建立 owner、清除旧等待并注册 receiver，再读取实际 bond。该次读取同时用于初始化状态机和选择动作，消除原来的两次读取不一致。

| 注册后的实际状态 | 动作 | 等待结束条件 |
| --- | --- | --- |
| NONE | createBond 最多一次，受保护写入为零 | BONDED、拒绝、启动失败或 30 秒期限 |
| BONDING | 等待已有系统绑定，不重复 createBond | BONDED、拒绝或 30 秒期限 |
| BONDED | 直接建立新的 GATT，不重复 createBond | GATT 各阶段结果或各自 15 秒期限 |
| 未知状态 | `bond_state_unknown` | 立即结束 |

绑定等待使用独立事实 `waitingForBond`，不再仅凭状态机阶段决定是否忽略超时。进入 GATT 重建后结束绑定等待，旧绑定 timer 无法误杀恢复流程；重复广播、旧 owner timer 和取消后的广播均不能再次推进终态。

注册前后发生 BONDED→NONE 时，新的绑定可正常推进或确定超时。旧绑定丢失广播若晚于新绑定启动到达，且本次仍处于绑定等待，不再误取消新 attempt；已经进入绑定后 GATT 阶段的真实绑定丢失仍结束会话。绑定期间旧普通 GATT 断开会被隔离，保留设备与绑定期限，待成功广播后连接新 GATT。

正式协调器回归覆盖注册前后 3×3 状态组合、未知状态、同步返回前完成绑定、false、权限及运行时异常、拒绝、超时、重复广播、旧 owner 和取消。原先 BONDED→NONE 导致停留在恢复阶段的复现已转为正式测试。

## BLE18生命周期归属

新增 `BirdBoxBlePlugin`，由 Flutter Engine 插件注册表持有 BLE 通道。`MainActivity` 在同一 Engine 上只注册一次；Activity 清理不再直接销毁 BLE 通道。插件通过 `ActivityAware` 接入 Activity 和权限回调，在 Engine 销毁或插件移除时统一释放会话。

| 生命周期情形 | 行为 |
| --- | --- |
| 系统配对弹窗、inactive、paused、短暂后台切换 | 保留当前 attempt、receiver、GATT 和有界期限 |
| 同一 Engine 的 Activity 重建或暂时分离 | BLE 会话继续；清除旧 Activity 引用，新 Activity 接入原通道 |
| Activity 分离时尚有权限弹窗等待 | 权限等待以 `ble_host_unavailable` 结束；旧返回不能重复完成 Result |
| Engine 真正销毁、插件移除 | 以 `ble_session_ended` 结束 pending Result，记录 `engine_destroyed`、阶段及 teardown；清理幂等 |
| 用户取消 | 校验 request、可用的 attempt 和 connection owner 后结束；旧页面取消被拒绝 |
| 新进程或新 Engine 会话 | 新建通道和请求，重新读取系统实际 bond；不恢复旧 pending Result |

Bluetooth、receiver、权限状态检查和包信息读取使用 application Context；Activity 仅用于权限请求及打开系统设置。Dart 增加两类 App 生命周期错误及可操作提示，断开事件与恢复分支保留生命周期分类，避免收口为网络内部错误。准备失败携带 `preparationStep`、`failurePhase` 和 `teardownReason`，便于定位。

## 生产原生桥验证

新增 `BirdBoxBlePlatform` 最小可替换边界，控制 bond 读取、createBond、receiver 和 connectGatt；通道构造注入 Handler 与 adapter。GATT 方法由 Android 对象测试替身控制，回调进入生产 `BluetoothGattCallback`，期限由 Robolectric 主线程时钟推进。

`BirdBoxBleBridgeTest` 实际调用生产 `onMethodCall`、绑定 receiver、GATT 回调和 Engine 插件回调。测试执行了生产副作用路径，不依靠单独调用状态机证明桥的行为。

覆盖内容包括：

- receiver 先于 createBond 注册，false、异常和无广播均确定结束。
- 旧 GATT disconnect/close，新服务发现及两路 CCCD 完成后才允许受保护写入；旧实例回调不会推进新实例。
- 新连接失败、连接回调失败、服务错误、MTU 回调缺失、第一及第二路 CCCD 失败、权限撤销。
- 绑定中旧 GATT 断开，以及旧绑定丢失广播与新绑定启动的竞态。
- 写回调超时后隔离迟到回调，只允许一次绑定后恢复；第二次无回调确定失败。
- 旧 owner 取消、取消后的广播与 timer、Result 单次完成和重复清理。
- 保留 Engine 的 Activity 插件重新接入、引擎销毁、权限等待收口，以及新通道读取已有绑定。
- API 27、31 的整组回归和 API 33 新 descriptor/write API 的就绪门禁。

Engine 和 Activity 生命周期测试通过真实插件回调及模拟 binding 执行，尚未在手机上执行系统触发的 Activity 重建。现有 instrumentation 的分类用例本轮仅编译；本轮生产桥行为证据来自 Robolectric。
