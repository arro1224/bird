## 1. 本批次目标

修复 BLE 双模式配网在“网络配置成功”之后没有进入正式应用会话的问题，并明确配网页面的资源生命周期：

1. 盒子返回终态网络状态后，App 使用已确认的 `base_uri` 建立正式 HTTP 会话。
2. 正式会话连接成功后，将设备写入全局 `DeviceSessionCubit`，再进入三页签主界面。
3. 直连热点成功交接时保留 Android 网络绑定，避免进入首页后立即断开盒子流量。
4. 用户取消、系统返回或配网页面未完成退出时，释放 BLE 和网络绑定。
5. 完成操作具备防重复提交和安全错误提示。
6. 生产完整性门禁锁定上述接线，防止后续回归为“配网成功但无法进入业务页”。

## 2. 实施结果

### 2.1 正式会话激活

新增 `ProvisioningCompletion` 交接对象，携带：

- BLE 可信链路读取的稳定 `device_id`；
- 盒子终态网络状态确认的 `base_uri`；
- 已确认的 `direct_ap` 或 `infrastructure_sta` 网络模式。

`BirdCompanionDependencies.completeProvisioning()` 负责：

1. 将配网网络模式转换为应用 `NetworkMode`；
2. 调用正式 `ConnectionRepository.connect()` 完成 HTTP 握手和会话恢复；
3. 比对 HTTP 返回设备身份与 BLE 可信设备身份；
4. 调用 `DeviceSessionCubit.setConnectedFromStatus()` 更新全局设备会话；
5. 仅在全部成功后允许页面跳转至 `/shell`。

### 2.2 页面交接状态

BLE 连接页新增有状态宿主，维护：

- `completing`：正在激活正式会话，禁用“完成”按钮并显示“正在进入首页…”；
- `handoffCommitted`：正式会话已完成交接，页面销毁时不得再断开网络。

会话激活失败时保留成功页，恢复“完成”按钮并展示安全错误信息，用户可以直接重试。

### 2.3 连接清理职责拆分

调整前，`ProvisioningCubit.close()` 在页面销毁时无条件调用 `repository.disconnect()`，这会同时释放 Android Wi-Fi 网络绑定，导致直连模式进入首页后失联。

调整后：

- `ProvisioningCubit.close()` 只停止发现并关闭展示层订阅；
- BLE 页面未完成退出时，由页面宿主显式调用 `repository.disconnect()`；
- 正式会话成功交接后，页面销毁不调用 `disconnect()`；
- 用户在流程中执行重置时仍调用 `disconnect()`，原有取消语义保持不变；
- 应用整体退出时仍由全局依赖容器释放配网 Repository。

### 2.4 生产入口和路由

正式 App、启动首页的嵌套路由、根路由以及设置演示入口均转发 `completeProvisioning`，保证从首次连接、添加/切换设备等入口进入时使用同一条正式交接链路。

### 2.5 发布门禁

生产完整性检查新增以下强制项：

- 必须存在正式配网完成处理器；
- 必须更新全局设备会话；
- 正式 App 必须把处理器传给路由；
- 路由必须继续转发处理器；
- 未完成页面必须保留显式资源释放逻辑。

## 6. 真实设备验收清单

本批次代码完成不等于真实硬件发布完成。进入下一发布阶段前必须补齐：

1. Android 真机 + K7，首次配对后选择“直连盒子”。
2. 盒子热点启动成功，点击“完成”进入首页。
3. 首页立即调用 `/health`、相册和任务接口，确认没有因页面销毁导致网络解绑。
4. 杀进程并重启，验证保存的设备身份和地址提示可以恢复。
5. 在配网中途按系统返回，确认手机恢复原网络且 BLE 断开。
6. 选择家庭/工作室 Wi-Fi，成功后进入首页并验证同一 `device_id`。
7. 故意关闭盒子 HTTP 服务，确认“完成”失败后仍停留在成功页，可恢复服务后重试。
8. 用另一台盒子占用相同地址进行负向测试，确认设备身份不一致时不进入首页。
