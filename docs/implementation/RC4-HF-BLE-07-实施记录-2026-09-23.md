# RC4-HF-BLE-07 实施记录

日期：2026-09-23  
范围：BLE 连接失败可观测性与问题基线

## 批次边界

本批次只补充诊断和脱敏，不修改配对触发条件、Bond 策略、GATT 重试次数、
业务命令字节或 `request_id`。条件式 `createBond()`、幂等连接清理和失败后免重装
重试仍分别属于后续批次。

## 已实施

1. Android BLE 平台错误统一附带结构化状态快照。`invalid_state`、`gatt_busy`、
   GATT 超时和安全恢复失败等错误现在可以识别具体平台方法与失败时状态。
2. 新增单调递增的 `connectionGeneration`，并保留既有 `gattInstanceId`，用于区分
   App 进程内不同连接尝试和同一次安全恢复中的 GATT 重建。
3. 原生诊断事件与 `PlatformException.details` 新增以下字段：

   - `platformMethod`
   - `operationName`
   - `pendingOperation`
   - `nativeState`
   - `securityPhase`
   - `gattPresent`
   - `linkReady`
   - `scanning`
   - `connectionGeneration`
   - `gattInstanceId`
   - `bondState` / `actualBondState`
   - `traceId`
   - `deviceAddressHash`
   - `errorCode`
   - `sanitizedMessage`

4. Dart 连接诊断模型向后兼容地保存上述可选字段，现有 schema v2 记录仍可读取。
5. Dart 平台错误文案改为白名单式字段拼装，不序列化未知 `details`。错误消息最大
   保留 240 个字符，并脱敏 MAC、密码、口令、令牌、授权信息、配对码和 DPP URI。
6. 新增 `platform_error` / 增强 `operation_failed` 事件，使即时失败和异步失败均可
   进入同一条连接诊断时间线。

## 典型诊断结果

当再次连接被旧 GATT 拒绝时，联调诊断将能出现类似字段：

```text
platformExceptionCode=invalid_state
platformMethod=connect
nativeState=gatt_present_not_ready
pendingOperation=none
gattPresent=true
linkReady=false
securityPhase=idle
actualBondState=not_bonded
connectionGeneration=1
```

这些字段可以区分“原生仍持有 GATT”“正在执行其他操作”“Bond 尚未开始”和
“安全恢复阶段未结束”，不再只剩单独的 `invalid_state`。
