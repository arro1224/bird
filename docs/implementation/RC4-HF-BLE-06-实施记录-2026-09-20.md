# RC4-HF-BLE-06 实施记录

日期：2026-09-20
范围：BLE-01～05 后续 App 端静态复核问题闭环

## 已实施

1. BLE 命令自动重试只由 `BirdBoxBleDataSource.writeCommand` 管理，Repository
   不再叠加第二轮完整命令重试。同一请求仍复用原 `request_id` 和原始分片，安全
   恢复后的自动重试最多一次。
2. 单轮扫描按 Android 连接句柄合并重复回调：名称采用后续非空值，Service UUID
   取并集，Manufacturer Data 保留后续有效补充，RSSI 使用最新值。
3. 扫描诊断升级到 schema v3。新增最多 512 字节的
   `scan_record_redacted_hex`：保留 AD 结构、名称和 Service UUID；Manufacturer
   Data / Service Data 只保留标识前缀，其余载荷清零。
4. App 进入 inactive、paused、hidden 或 detached 时主动停止 BLE 扫描。
5. 原生层拒绝在旧扫描仍活动时静默接受新 scan session。
6. 删除未被生产流程使用的旧 `BirdBoxBondStateMachine` 和对应仪器测试，防止旧
   通用 Bond 设计回流。
