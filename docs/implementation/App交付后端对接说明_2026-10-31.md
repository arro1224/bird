## 3. 当前 App 已消费的接口

以下是现有 App 代码行为清单，待正式契约逐项核对；不是要求对方直接照此上线未经双方确认的接口。

| 方法与路径 | App 用途 / 关键点 |
| --- | --- |
| GET /api/v1/recognition-capabilities | incremental、copy、metadata 总能力；缺失即禁用相关操作 |
| POST /api/v1/projects/{batchId}/analysis-jobs | 未识别时原子创建；body 的 smart_follow 携带配置；幂等键在头中，不顺序创建两个任务 |
| POST /api/v1/jobs/{recognitionJobId}/smart-follow-sessions | 已运行识别开启跟随，固定同次意图参数；已有会话优先接管 |
| GET /api/v1/jobs/{recognitionJobId}/recognition-events | 读取 smart_follow_session_id 关联；沿既有 job 列表/详情找回，未自造会话列表查询 |
| GET /api/v1/smart-follow-sessions/{sessionId} | 权威状态、state_version、allowed_actions、各项计数及活动 metadata ID |
| GET /api/v1/smart-follow-sessions/{sessionId}/copy-jobs | 全分页读取，按 copyJobId 去重，核验总数，关联 RC3 详情/报告 |
| POST /api/v1/smart-follow-sessions/{sessionId}/actions | action + expected_state_version；只用 pause、resume、finish_current_results、stop_following、retry |
| GET /api/v1/smart-follow-sessions/{sessionId}/metadata-update-availability | 是否有信息可更新及 active_update_id；session 也有 active ID 时不可忽略它 |
| POST /api/v1/smart-follow-sessions/{sessionId}/metadata-updates/preview | 当前 UI 发空对象，后端生成用户可核对的范围；同步 ready 或 building + preview_id |
| GET /api/v1/smart-follow-metadata-previews/{previewId} | 预览生成与最终确认前重读；变化、过期、未知统计须重新核对 |
| POST /api/v1/smart-follow-sessions/{sessionId}/metadata-updates | 最终明确确认后发送 preview_token、target_media_id；部分确认时加 confirm_partial=true |
| GET /api/v1/smart-follow-metadata-updates/{updateId} | 父任务与 child_jobs，同原 CopyJob 映射；只读恢复，不重提交 |

创建配置现有字段：target_media_id、eligibility_mode=recognized_only_v1、pair_policy、conflict_strategy、review_export（enabled / prefer_embedded）。该枚举沿现有 SmartFollowContract；其筛选语义为 high 且有效鸟种，不允许 App 自行根据置信度或 keep/featured 判断资格。

## 4. 状态、恢复与统计规则

1. 仅复制确认时已识别结果的是普通 recognized_assets；SmartFollow 是独立会话，跟随本轮识别。识别结束后处理完剩余队列才结束，不把一个 child 完成当整体完成。
2. 原子创建用持久化 sf-atomic-* 键；运行中开启用 follow-start-{recognitionJobId}；动作按 session/action/state_version；metadata 用 md-create-{sessionId}-{previewToken}。超时/未知/429 保留原意图及原参数，不换键盲建；查询不能确定时明确“结果待确认”。请确认服务端键的作用域、保留期与可查询性。
3. 所有页面计数来自权威快照。事件只唤醒重新读取，重连/前台恢复补拉，旧 state_version 不覆盖新状态；不按时间生成进度。
4. 子任务报告缺失、数量不符、未知状态不计为零/成功。信息父任务即使终态，也必须明确提供全部 child、总数吻合、ID 不重复且全部终态，才解除活动任务并允许再次预览。显式零任务与缺失列表不同。
5. 信息更新不改写原复制会话结果，不自动重复制；新信息先提示，用户预览并确认后才创建父任务。父任务完结后再次读 availability，之后仍可能出现新 revision 提示。
6. 当前父任务终态按 completed、completed_partial、failed、cancelled 读取；这不表示新增 SmartFollowSession cancelled 状态。未知父/子状态继续当待确认处理。后端请给正式状态表。

1. 先确认正式契约与普通全量复制的信息更新关联，回传字段/样本/版本和已知不支持项。

4. 验首张 committed、排空、断网/杀进程恢复、原盘/错盘、部分完成；App 与 OLED 对同一 ID 核对。
5. 验信息开关、预览取消零写入、显式部分确认、过期、父任务恢复、部分失败与再次变化；普通全量复制另外证明只更新信息、零新增照片复制。
