# RC4-HF-BLE-04 发布晋级手册

本手册用于在 BLE-03 真机验收完成后，把唯一选定的扫描策略晋级为正式
`deckers.thibault.aves.bird` Release。当前只有 vivo 时只能验证页面和普通回归，
不能执行正式晋级。

## 1. 前置材料

必须先取得一份通过
`tool/acceptance/rc4_hf_ble_03_evidence_validator.dart` 的证据 JSON。该证据应同时
包含 OPPO PKC110/API 36、Huawei、真实 K7、A/B 扫描矩阵、5 次首次配对、重连、
板端日志和三方审批，并明确：

```text
final_result=passed
hardware_status=verified
selected_scan_variant=A 或 B
```

不要手工只改这三个字段。BLE-04 会重新运行完整 BLE-03 校验器。

## 2. 把 A/B 结论应用到正式 bird 包

### 选择 A

- `android/app/src/main/AndroidManifest.xml` 的 `BLUETOOTH_SCAN` 保留
  `android:usesPermissionFlags="neverForLocation"`；
- `bird` flavor 不覆盖扫描诊断策略，继续继承 `defaultConfig` 的
  `never_for_location`；
- 不修改 `NEARBY_WIFI_DEVICES` 的 `neverForLocation`。

### 选择 B

不要直接破坏后续 A/B 调试包。推荐：

1. 新增 `android/app/src/bird/AndroidManifest.xml`，仅对
   `android.permission.BLUETOOTH_SCAN` 使用 `tools:remove="android:usesPermissionFlags"`；
2. 在 `android/app/build.gradle.kts` 的 `create("bird")` 中覆盖：

```text
buildConfigField("String", "BLE_SCAN_PERMISSION_POLICY", "\"full_scan\"")
```

3. 保留 `main` 和 `birdScanA` 的 A 策略，保留 `birdScanB` 的 B 策略；
4. 按实际权限用途同步隐私说明；
5. 构建后以合并 Manifest 为准复核，不能只看源 Manifest。

门禁同时检查合并 Manifest 和生产 BuildConfig，任何一边漏改都会阻断。

## 3. 形成可追溯候选包

1. 完成代码评审并形成提交；
2. 确认 `git status --porcelain` 为空；
3. 配置完整 Release keystore 环境或 `android/key.properties`；
4. 配置批准的 `AVES_RELEASE_CERT_SHA256`；
5. 构建 `bird` Release；
6. 运行 `tool/release/verify_android_release.ps1`；
7. 记录 APK SHA-256、Git SHA、版本和 UTC 构建时间；
8. 在真实设备执行签名包安装和上一正式版本回滚，保存脱敏记录。

## 4. 填写 BLE-04 证据

复制：

```text
docs/acceptance/rc4-hf-ble-04-release.template.json
```

`ble03_evidence_file` 使用相对于 BLE-04 JSON 的路径，或运行时通过
`--ble03-evidence=<绝对路径>` 覆盖。`candidate` 必须来自实际构建，不得从 Debug
A/B 包复制 SHA。发布审批和回滚文件同样使用相对路径，并提前脱敏。

独立校验：

```powershell
dart run tool/acceptance/rc4_hf_ble_04_release_gate.dart `
  --evidence=<BLE-04证据JSON> `
  --apk=build\app\outputs\flutter-apk\app-bird-release.apk `
  --manifest=build\app\intermediates\merged_manifests\birdRelease\processBirdReleaseManifest\AndroidManifest.xml `
  --approved-certificate=$env:AVES_RELEASE_CERT_SHA256
```

只有输出 `status=passed`、`releasable=true` 才能进入完整 B7 Release。

## 5. 完整 B7 Release

```powershell
powershell -ExecutionPolicy Bypass -File tool\release\run_b7_gate.ps1 `
  -Mode Release `
  -RealBoxEvidencePath <通用真实盒子证据> `
  -BleRc4EvidencePath <K7-01到K7-10证据> `
  -BleHotfixReleaseEvidencePath <BLE-04证据> `
  -B12BEvidencePath <B12-B证据>
```

缺少任一参数、真机材料、正式签名或干净 Git 时都应停止，不要用 vivo、模拟器、
Debug 包或人工口头结论替代。

## 6. 回滚原则

- 保留上一个已验签正式 APK、证书指纹、APK SHA 和安装说明；
- 回滚测试必须在物理 Android 上完成并记录结果；
- 若 B 策略出现权限或隐私合规问题，回滚到已验证的 A 正式包，而不是临时关闭
  BLE 加密、恢复通用 `createBond()` 或修改冻结 UUID；
- 回滚后重新核对 `/health.device_id`、已配对 Token 复用和任务不中断行为。
