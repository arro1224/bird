## 2. 字段来源与缺失处理

| 页面字段 | 使用来源 | 边界 |
| --- | --- | --- |
| 识别总数、成功、跳过、失败 | 原 RecognitionJob 的 `JobReport` | 验证任务身份；识别未结束时仅使用 detail 的总数并标明仍在识别，不请求最终报告 |
| 待确认 | 当前未提供 | 显示“未提供”；不以总数减去其他分类反推 |
| 符合条件、已复制照片/文件、失败照片 | `SmartFollowSession` 的明确原始字段 | 检查字段实际存在且为非负整数；DTO 默认 0 不能证明结果为 0 |
| 同名跳过、失败、不适用文件 | 全部终态子 `CopyReport` 的 `skipped_files`、`failed_files`、`not_applicable_files` | 沿用已有 RC3 口径；全分页、去重和报告身份检查完成后才允许聚合 |
| 覆盖文件 | 当前未提供 | 显示“未提供”；不从计划冲突决策或成功文件数推算 |
| 实际复制字节 | 子任务 detail 的 `stats.copied_bytes` | 要求存在性标记有效；不使用 child `total_bytes` 或 report `total_bytes` 的计划/未确认口径作实际值 |
| 识别信息保存 | 子任务冻结的 `review_export.enabled` 和报告的 CSV、XMP、嵌入、降级、导出失败字段 | 未开启、保存异常、字段未提供分别呈现；复制成功不能推出信息已全部保存 |
| 结束原因 | 会话 `error_message` / `error_code`；批次状态和报告缺失提示 | 批次更详细原因继续查看既有 RC3 详情 |

识别任务的“处理成功”和 SmartFollow 的 high 且有有效鸟种结果的“符合条件”分别列出，不混为同一数量。照片使用“张”，文件使用“个”，字节使用“B”；RAW＋JPEG 可以对应多个文件。

本批没有新增后端字段别名、接口路径、状态或动作；上述两项缺失统计等待对方确认契约后再适配。页面可以显示已取得的事实，不把尚缺字段包装为完整验收。

## 3. 聚合完整性

1. 先重读权威会话，仅终态继续加载结果。
2. 按 cursor 读完子任务全部分页，按 copyJobId 去重；重复内容冲突、缺分页标志/游标、循环游标、后页读取失败都不算完整。
3. 对照会话明确给出的 child_job_count；缺失或数量不符时，显示列表/报告待补齐。
4. 每组最多并发读取 4 个子任务详情和报告。仅终态批次读取报告，验证请求 ID、目标介质（响应已提供时）、摘要与详情状态，以及报告与详情明确给出的文件结果是否一致。
5. 聚合结束再次读取会话，核对版本及本页消费的标量字段，避免组合两个不同结果版本。普通 JSON 重读生成的新列表对象不会被误认为结果变化。
6. 会话与批次复制文件数矛盾、已复制照片数超过符合条件数时提示核对；不展示可信完整汇总。空批次只有在明确返回零批次、零复制照片/文件时才能形成零工作量结果。

部分页面字段可以独立展示；完整复制汇总需完整历史、全部子任务终态、有效报告及所需统计均存在。未齐时显示“报告待补齐/未提供”，不会把 pending、assigned、计划文件大小或只读到的第一页当成成功总数。后端已知的部分完成/失败和信息保存降级不会被渲染为全部成功。

原有 `SmartFollowChildJobPage.hasMore` 继续保留“有可用 cursor 才可继续翻页”的兼容行为，新增 `paginationValid` 供 C1 判断完整性。这样不会把不能翻页错误解释为完整结果，也不改变既有批次历史组件的行为。
