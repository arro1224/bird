## 3. 首页盒子状态与老师意见的兼容规则

本次不恢复“所有参数正常”的额外提示条，也不常驻显示正常温度。按以下方式兼顾照片首页设计稿和“只提示异常”的简化要求：

1. 首页保留一行紧凑、可点击的盒子状态入口：连接状态、电量、存储状态。
2. 三项是操作入口和状态摘要，不再增加“设备一切正常”等提示文案。
3. 正常温度不展示；温度过高、存储不可用、设备断开等情况继续使用顶部异常条。
4. 点击任一状态进入统一的设备状态底部抽屉，详细参数只在用户主动查看时出现。
5. 若硬件暂未提供电量或存储数据，显示“正在读取”或仅显示已取得的项目，不使用伪造数值。

## 4. 分批实施顺序

### 批次 1：搜索崩溃与错误页收口（P0）

目标：先恢复照片搜索的稳定性，避免任何正常操作进入全屏错误页。

实施内容：

1. 固定复现路径：拍摄记录 → 本次拍摄 → 右上角搜索 → 输入鸟种 → 提交。
2. 保存完整 `logcat`、Flutter 堆栈、触发时的路由栈和 `GalleryCubit` 状态。
3. 检查搜索对话框关闭动画期间的控制器释放时机、`context.mounted`、嵌套 Navigator 和刷新调用。
4. 将搜索输入改为由独立有状态组件管理，确保页面销毁、弹窗关闭和异步刷新互不抢占。
5. 错误边界在正式界面中不展示框架文件名和断言；技术详情只写入诊断记录。
6. 增加“提交搜索、清空搜索、连续搜索、搜索中返回、无结果”组件测试。

完成条件：连续搜索 20 次无崩溃；有结果、无结果和接口失败都有正常页面；返回键不出现黑屏或错误页。

### 批次 2：连拍与对比操作状态正确性（P0）

目标：先保证“点了以后真的改了，并且用户看得出来”。

实施内容：

1. 连拍页的弃用、待确认、保留、精选四个按钮，统一由当前选中照片的真实 `keepState` 决定高亮状态，取消固定高亮。
2. 保存开始时只锁定当前组并显示轻量加载；保存成功后回写 `GroupReviewState.groups` 中对应照片，不依赖退出重进才刷新。
3. 保存失败恢复原状态并显示可执行提示；离线排队时显示“重新连接后自动更新”。
4. 切换缩略图、上一组、下一组时重新读取该照片状态，避免沿用上一张的高亮。
5. 对比页区分“当前选中的照片”和“已经保存的照片状态”：照片边框表示当前选择，操作按钮表示真实保存结果。
6. 左图、右图各自显示是否已保留；精选操作作用于当前选中照片。两张照片都允许保留，不把视觉上的切换误实现为互斥删除。
7. 增加成功、失败、冲突、离线排队、快速连点和切换照片测试。

完成条件：四种状态逐一点击均能正确切换；退出重进状态仍一致；真机快速点击不会重复提交；操作失败不会出现“看似成功”的高亮。

### 批次 3：首页状态区、加号与“识别度”（P1）

目标：恢复照片首页关键视觉结构，并完成用户要求的术语更新。

实施内容：

1. 按第 3 节规则恢复首页盒子状态摘要，点击后打开设备状态抽屉。
2. 加号视觉圆形直径调整为约 40dp、图标约 22dp、白色；外围保留至少 48dp 可点击范围。
3. 空相册状态和有照片状态共用同一个加号组件，避免两处尺寸再次不一致。
4. 将所有用户可见的“识别把握”统一替换为“识别度”，范围包括：照片详情、识别修改、筛选、排序、查询条件摘要和识别结果面板。
5. 内部 `confidence` 字段、接口参数和模型名称保持不变，避免破坏硬件契约。

完成条件：首页状态区、加号与设计稿视觉接近；正常温度不显示；异常仍置顶；全模块搜索不到用户可见的“识别把握”。

### 批次 4：筛选与排序底部弹层（P1）

目标：统一照片模块弹层规格，解决尺寸不合适和真机溢出。

实施内容：

1. 筛选抽屉采用可拖动方案：初始高度约屏幕 52%，最小约 42%，最大约 78%；360dp 真机默认呈现约半屏。
2. 标题、重置、分组条件和底部“应用筛选”按设计稿重新排版；应用按钮固定在底部，筛选条件区域独立滚动。
3. 键盘弹出时自动避让，关闭键盘后恢复原高度；小屏和 1.3 倍字体下仍可滚动至所有条件。
4. 排序弹层使用与筛选相同的圆角、遮罩、拖动条、左右内边距和选中样式。
5. 排序选项统一为用户文案：“拍摄时间最新、照片质量从高到低、系统推荐优先、识别度从高到低”。
6. 排序弹层通过根导航或统一弹层宿主管理，不与底部导航重复占高；内容超出时可滚动，禁止出现黄黑溢出条。
7. 为 320×720、360×720、390×844 和字体 1.3 建立截图测试。

完成条件：默认约半屏；筛选与排序均无溢出；选中项、重置、应用和返回行为正确；弹层关闭后列表条件保持一致。

### 批次 5：单张详情更多菜单与修改记录（P2）

目标：使深层页面延续相册的米白、深绿、浅描边视觉体系。

实施内容：

1. 单张详情更多菜单改为定宽浮层，建议宽度 248–280dp、圆角 16dp、1dp 浅描边、轻阴影、统一 52dp 行高。
2. 菜单与屏幕右侧和状态栏保持安全距离；项目过多时内部滚动，不遮挡底部关键操作。
3. 上一张、下一张、设为精选、标记待确认、修改记录使用一致图标尺寸和文字层级；不可用项隐藏或明确禁用。
4. 修改记录页取消整页深绿色背景和深色主题，改为米白背景、标准二级页标题和浅色时间线卡片。
5. 删除重复“修改记录”大标题；时间线节点使用品牌绿，当前记录可使用低饱和强调色。
6. 将 `box/app` 等来源映射为“盒子识别、手机修改”等普通用户文案；显示完整日期时间、修改摘要和版本顺序。
7. 增加空记录、单条、多条、长摘要、未知来源和加载失败状态。

完成条件：菜单无截断、无贴边；修改记录文字对比清晰；页面与照片详情、底部导航和返回行为一致。

### 批次 6：联合真机回归与交付

目标：确认前五批改动组合后没有产生新的导航、布局和数据状态问题。

实施内容：

1. 按“相册首页 → 拍摄记录 → 本次拍摄 → 搜索/筛选/排序 → 连拍挑选 → 照片对比 → 单张详情 → 修改记录”完整走查。
2. 覆盖在线、断开、重新连接、识别处理中和操作失败场景。
3. 检查 Android 返回键、连续打开弹层、弹层上再开页面、切换底部导航和恢复前台。
4. 运行静态检查、照片模块完整测试和视觉基准测试。
5. vivo X20 每个关键页面保存“默认、操作后、失败”截图，并与设计稿并排复核。

完成条件：无崩溃、无布局溢出、无固定假高亮、无保存状态丢失；P0/P1 问题全部关闭后才进入最终交付。

## 5. 批次依赖与禁止合并项

1. 批次 1 和批次 2 必须先于视觉批次，避免页面更美观但核心操作仍不可用。
2. 搜索崩溃与筛选视觉不要同批修改；两者都涉及相册刷新和弹层生命周期，分开更容易定位回归。
3. 连拍/对比状态逻辑与页面外观可以同批，但必须先补状态测试再调整按钮样式。
4. 修改记录页不应继续使用独立深色主题；不得通过单纯调浅文字颜色临时掩盖结构问题。
5. 不恢复 NAS 复制入口；本实施书仅覆盖照片浏览、筛选、挑选、对比和详情流程。
