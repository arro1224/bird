# 默认照片排序与相册排序绑定设计

## 背景

设备模块的“默认照片排序”当前提供拍摄时间、文件名和文件大小共六种选项；照片模块现有排序入口提供拍摄时间最新、照片质量、系统推荐和识别置信度四种选项。两处排序定义不一致，且已保存的相册视图可能在重新进入相册时覆盖设置页的新默认值。

本次调整不改变现有设计稿的页面布局、色彩、组件结构和交互形式，只统一排序选项与数据流。

## 目标行为

1. 设备模块“默认照片排序”使用照片模块现有的四种排序：
   - 拍摄时间最新
   - 照片质量从高到低
   - 系统推荐优先
   - 识别置信度从高到低
2. 在设置页选择默认排序后：
   - 写入现有 `SettingsStore`；
   - 发布 `AppDataResource.photoPreferences` 变更；
   - 当前已打开的相册立即使用新排序重新加载。
3. 下次进入相册时，全局默认排序覆盖旧相册视图缓存中的排序字段。
4. 相册视图缓存中的搜索、筛选、场景和审核条件继续恢复，不因默认排序变化而丢失。
5. 相册内部排序弹窗属于当前相册的临时视图设置：
   - 更新当前 `PhotoQuery`；
   - 写入当前项目的相册视图缓存；
   - 不反向覆盖全局默认排序。

## 数据模型

使用照片查询层已有的排序值作为唯一排序协议：

| 设置项 | `PhotoQuery.sort` |
| --- | --- |
| 拍摄时间最新 | `captured_at_desc` |
| 照片质量从高到低 | `score_desc` |
| 系统推荐优先 | `recommended_desc` |
| 识别置信度从高到低 | `confidence_desc` |

`BirdPhotoSortOrder` 保留为设置 UI 使用的强类型枚举，但枚举值改为与以上四种业务排序一一对应。设置持久化仍存储枚举名称，由统一映射转换为 `PhotoQuery.sort`。

## 数据流

### 设置页修改

`PhotoSettingsPage` -> `BirdSettingsController.setSortOrder` -> `SettingsStore.write` -> `AppDataChangeBus.publish(photoPreferences)` -> 活跃的 `GalleryCubit` -> 读取最新设置 -> 使用新排序刷新相册。

事件必须在设置持久化完成后发布，确保相册收到通知时可以从 `SettingsStore` 读到新值。

### 相册首次进入

1. 读取全局照片偏好。
2. 读取当前设备和项目对应的相册视图缓存。
3. 恢复缓存中的筛选条件。
4. 最后用全局默认排序覆盖缓存中的 `sort`。
5. 发起照片查询并保存合并后的视图。

### 相册内临时排序

相册排序弹窗直接刷新当前 `GalleryCubit` 查询。该查询会继续写入相册视图缓存，但不写入 `SettingsStore`，因此只作用于当前项目视图，直到重新进入相册时再次应用全局默认排序。

## 兼容性

旧设置值按以下方式迁移：

- `newest` -> `captured_at_desc`
- 其他已废弃值（`oldest`、文件名、文件大小）-> `captured_at_desc`

读取未知值时同样回退到“拍摄时间最新”，避免升级后出现无选中项或查询参数非法。

## 测试范围

1. 设置页只显示四个与照片模块一致的排序选项。
2. 设置页选择“系统推荐优先”后，持久化值正确并发布照片偏好事件。
3. 活跃相册收到事件后立即刷新为对应 `PhotoQuery.sort`。
4. 恢复相册视图时，缓存筛选条件保留，但缓存排序被全局默认覆盖。
5. 相册内临时排序不修改 `SettingsStore`。
6. 默认入口、设备模块视觉结构和 `birdV1` Android 构建继续通过。

## 非目标

- 不修改照片模块现有排序弹窗视觉。
- 不增加新的后端排序协议。
- 不让相册临时排序反向修改全局默认。
- 不调整设备模块其他照片设置。
