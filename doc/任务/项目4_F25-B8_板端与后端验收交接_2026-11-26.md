# 项目4 F25 板端与后端验收交接

日期：2026-11-26。用户确认本次实施 B7，B8 的真实盒子验收由板端、后端及现场接收方执行；本端只准备可执行资料。本文件中的所有真实 K7 用例初始均为“待接收方验证”，不代表已经通过。候选 APK、实际哈希和本地结果见同包交接说明、构建清单及 B7 实施记录。

## 交付边界与责任

- App：B1 至 B6 本地修复已经实施；N06／N07／N13 交接修复已保留。提供正常 `bird` 入口的 Debug 联调候选，工作区 dirty、调试签名、`releasable=false`。它供联调安装，不是经过正式发布审批的 Release。
- 本地条件：vivo X20、Android 8.1 / API 27，电脑 BLE 测试广播及独立 HTTP 模拟服务。模拟数据、电脑广播、USB 工具和 vivo 结果不能替代真实 K7、OPPO／华为或真实文件复制证据。
- 板端：提供实际 K7、部署身份、源卡／目标盘、独立任务与文件时间线，执行重启、盘变化、空间和容量场景，配合保留证据。
- 后端：核对本次部署的 API／数据库版本、公开项目版本、CAS、幂等事务、完整流程封套、错误码及字段，提供脱敏响应和服务日志。
- 现场／产品：安排 OPPO 热点宿主、华为 Wi-Fi 客户端及可交换角色；确认取消 AI 后已入队复制的收尾策略与预览画质规格。OLED 由显示维护方单独接续。

请只在接收方安排的测试批次和测试存储介质执行以下写入场景，保留原片、既有副本和审阅历史。不要为了让用例通过而删 CAS、重建任务、换幂等键或填造部署／硬件证据。

## 开始前回传的基线

1. 核验 APK 文件名、字节数、SHA256、包名、版本、build ID、source fingerprint、签名证书；与 `build-manifest.json` 对应。升级使用 `adb install -r`；不通过卸载／清数据制造恢复成功。签名不兼容时先记录原因。
2. 记录 K7 型号、固件／后端部署提交或文件哈希、部署时间、API／schema 版本、OpenAPI 哈希、手机型号／系统及网络拓扑。后端“本地已修复”与“已部署到本次 K7”分别确认。
3. GET `/health`、`/api/v1/device/status`、`/api/v1/recognition-capabilities` 及当前项目，保留脱敏原始 JSON。核对 HTTP 身份、Bearer REST、WebSocket 各自结果。
4. 对齐手机和盒子的 UTC 时间；为每个用例记录开始／结束窗口及关联的 project/job/session ID。MAC、口令、Token、配对码、完整 DPP URI 不进入回传包。

vivo API 27 无法覆盖当前 API 29+ 自动请求加入指定 AP 的原生路径。相应 N06／N10 场景需要受支持的 OPPO／华为设备，不能用手动连网或 USB 转发代替。

## 必须答复的接口／产品事项

1. **N14-R1／R2 已有源码答复，仍需实板证据。** 当前项目、项目列表和文件分页的项目版本来源已确认；后端报告已修同键异参／全失败版本规则。请回收本次部署身份与 H07～H11 响应，不重复把源码问询列为未答复。
2. **N03／N08／本轮批量修复是否已部署。** 提供运行版本及 `blocked_kind/details`、图片准备 `available_actions` 的实际响应。旧交接的本地测试成绩不作为本次部署证明。
3. **取消 AI 后已入队复制如何收尾。** 请产品和板端明确最终语义；当前 App 不新增强杀写入／回滚复制承诺。H16 只验登记的分析取消与后续不启动。
4. **N09 规格和容量、OLED。** 分别确认预览画质／尺寸、保留余量、缓存重建策略和显示维护责任。它们继续单列 S1／S2，不由 App 界面修复关闭。

## 回传方式

填写同包 `回传结果模板.json`。每个用例绑定候选 APK、手机、板端部署与时间窗；证据路径必须实际存在。JSON 原始响应保留字段类型和整数精度；请求和事件可去标识，但同一用例内 ID 要能关联。保存原请求键的脱敏别名以证明重放没有换键，不回传 Token／口令。
