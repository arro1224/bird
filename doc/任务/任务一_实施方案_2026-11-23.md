## 三 实施设计

### 全局设备连接与资源归属

建议新增应用级 `DirectApConnectionCoordinator`（拟新增名称），在 `app_dependencies.dart` 中创建一次。页面 Cubit 订阅连接状态并提交操作意图；协调器持有系统 Wi-Fi 请求与绑定，repository 负责协议和授权，`DeviceSessionCubit` 仍负责全局业务会话。

同一 `device_id + operation_id + session generation` 仅保留一个活动连接 Future。重开恢复时没有活动 operation 的，先读取盒子状态再建立恢复意图，不能用旧 operation 当作新操作。协调器不再独立定义第二套全局业务在线状态。

| 事件 | Wi-Fi请求与绑定 | BLE/页面处理 |
| --- | --- | --- |
| AP ready重复、连点、同代次恢复 | 复用请求，不再启动AP、不再弹窗 | 合并Future，展示忙碌状态 |
| 相册/任务/设备切页、连接页dispose | 保持，页面只取消自己的订阅 | 归还页面观察权，避免夺走或释放全局控制会话 |
| BLE断开、恢复BLE失败 | 业务Wi-Fi仍有效则保持 | 单独标记控制离线并可重试 |
| 用户取消连接、切换设备、确认停止 | 使旧代次失效，按显式终止流程释放 | 阻断旧回调导航与状态覆盖 |
| native lost、业务网络不可恢复 | 关闭旧连接；仅当前意图允许有限恢复 | 显示恢复阶段，取消后不再自动请求 |
| App被系统回收 | 原生请求按系统生命周期结束 | 重开从可信设备与加密配置重建，不复用旧handle |

先盘点所有 release 调用，并逐一分类为控制释放、切网释放或全局销毁，尤其保留任务二 STA 成功/恢复时合理的解绑行为。页面退出取消尚未完成的连接意图，与进入主页面后正常切页要分开处理。

### A17 自动接入与恢复

主线：恢复所选盒子授权 → 读取真实模式/操作 → 复用已有效直连或启动AP → 验证 AP ready归属 → 系统请求具体热点 → 网络可用并绑定 → 身份/授权/受保护HTTP/WS验证 → 业务在线。

1. AP ready须匹配当前设备、request/operation和代次；已经有效的目标网络先验证复用。安全类型向下传递，明确支持矩阵；WPA2走现有实现，其他类型按协议和系统能力实现或明确报告不支持，不当作WPA2发送。当前 ready模型没有 BSSID，若板端未来提供可靠字段再考虑精确匹配，不从名称猜测。
2. join由正常、恢复和重开共用的协调器调用；手工救援仅在明确失败后由用户主动选择。用户取消停止自动重试，不能把返回前台当再次请求许可。
3. 阶段分别记录 AP就绪、系统请求、网络可用、绑定、身份、授权、受保护HTTP和WS；图库大图与任务访问另做业务验证。
4. 先沿用已有进程绑定方案，并验证 HTTP、媒体和WS完整路由。切换后重建旧socket/连接池及WS，不只让health通过；明确退出后解绑。若未来改为按连接绑定，应另核全部客户端覆盖。
5. 长期恢复资料按可信device_id加密保存，与短期配对兑换资料分开；至少包含配置版本、安全类型、端点与凭据有效性语义。不得把密码写入Hive pending、普通日志或诊断截图。冷启动仅恢复用户选定设备和有效意图，不遍历抢连其他盒子。
6. 凭据变更通过已授权BLE更新，身份不符立即停止；后台/锁屏恢复遵循系统实际条件。OPPO自开热点时记录角色切换限制，必要时提示关闭本机热点后继续同一次操作。

Android官方说明支持具体AP批准复用，且 `onUnavailable` 同时可能对应拒绝或连接失败。因此验收须记录实际弹窗及回调，不能保证所有手机首次无弹窗，也不能仅凭该回调判用户取消。参考 [Android本地Wi-Fi请求官方说明](https://developer.android.com/develop/connectivity/wifi/wifi-bootstrap)（2026-11-23核对）。

### A18 原页恢复控制与退出直连

网络设置同时显示业务网络与BLE控制状态。已验证直连业务在线而BLE离线时，继续显示“盒子直连中”，提供“恢复蓝牙控制”；停止按钮说明需要先恢复控制。当前业务状态过期则显示待核验，不能永久相信历史缓存。

专用恢复接口建议返回可等待Future，入参固定device_id与代次，第一帧即进入忙碌状态。优先复用仍有效的当前GATT/绑定，必要时定向重连并恢复授权；不先调用 `verifySavedSession()`，不推通用查找页。只有授权确实无效时说明需要重新授权，普通断BLE不要求重新配对。

恢复后调用 `resumeAfterBleReconnect` 等既有状态重读能力，按当前operation读取终态；留在网络设置页。页面返回/取消立即使本次恢复失效；迟到成功不得pop其他页、再push查找页或影响新设备。

停止顺序为：确认控制可用 → 发送一次 stop → 读取匹配operation的真实终态 → 在控制协议允许时释放手机请求/绑定 → 发现并验证盒子恢复端点 → 重建HTTP/媒体/WS → 更新结果。不能因BLE断开、AP消失或release返回就宣布停止/恢复成功。

分别呈现“盒子退出结果”“盒子旧STA恢复结果”“手机当前可达网络和业务恢复结果”。原Wi-Fi/原手机热点不可用时，保留原因与重试/换网入口。手机回到系统管理网络不保证一定回原Wi-Fi。

### A15 有效会话与扫描候选并行展示

查找页新增独立的“当前已连接设备”区域，来自已验证device_id与当前有效会话，并标明业务/BLE状态；广播区展示本轮新候选，历史记录另标识。广告名、SSID和scanId均不能升级为可信device_id。

重扫仅重建本轮扫描订阅与候选，保留有效连接区。新页面不要无条件领取并覆盖活跃GATT owner；引入只读观察/可复用所有权，显式切换设备才转移控制。页面退出和前后台订阅均与generation关联，旧扫描回调不得写入新列表。

仍出现空列表时同时采集scan raw/accepted/reason、GATT owner、可信设备状态、UI generation和板端广告/服务时间线。不预设广播故障，不将“注册广告实例存在”当作手机必定收到的证据。
