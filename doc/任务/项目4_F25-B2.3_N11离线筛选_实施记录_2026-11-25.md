## 结论与范围

B2.3 本地实现完成：图库更换分类、筛选及搜索时，先对当前设备／项目缓存叠加待同步意图并筛选，不把旧条件的列表显示为新条件结果；已知会话离线时直接使用投影，不等待 HTTP 超时。无法投影时清除旧条件结果并显示对应进度，取消及迟到回复不恢复旧列表。

分类计数与结果共用同一缓存集合及待同步投影，并明确标注“手机缓存内统计”或“手机缓存内统计（含待同步修改）”。空结果表达为“手机缓存中没有符合当前条件的照片”，不声称整批没有匹配项。精选分类在离线时仍可选择。

B2.3 不依赖现板项目版本读取字段。N14-R1／R2 仍见 [后端待确认清单](项目4_F25-B2_后端接口待确认清单_2026-11-25.md)；本次不关闭 B2.1 的外部契约条件，不把整个 B2、候选构建或真机验收标为完成。下一 App 开发批次为 B3；后端确认 N14 后可穿插其 P0 范围验证。

## 原因与改动

| 原缺口 | 本次处理 |
| --- | --- |
| 新 query 已更新，但旧 items 继续留在屏幕 | 增加同步缓存查询能力；刷新和搜索防抖开始时立即投影新条件，若没有可用投影则清除旧条件结果 |
| 离线读取先尝试 HTTP，失败后才查缓存 | 生产环境优先使用已验证设备会话状态；断线且有缓存时直接返回本地结果。无会话接入的仓库调用使用系统网络提示作为后备 |
| 系统网络标签可能误判热点宿主机 | 已验证会话在线时仍读取盒子 HTTP，不因 `hasNetwork=false` 阻止有效业务链路，保留 B1 边界 |
| 精确查询的空缓存盖住其他已知照片和刚保存意图 | 合并同设备／项目的照片页与候选快照，叠加较新的照片详情及待同步修改后再筛选；空缓存与完全没有缓存区分处理 |
| 待同步修改不参与分类／搜索／标签条件 | 单张字段补丁，以及批量保留、弃选、未标记、精选、增删标签均先投影再筛选；批量项目 CAS 不写成照片版本 |
| 已确认回执、冲突记录可能被当成新的待同步修改 | 仅投影尚待处理的非冲突意图；批量使用 `remainingFileIds` 排除已确认成功项。冲突意图仍留在原队列供现有处理入口核对 |
| 重连后旧候选快照继续返回空结果 | 复用完整候选前，对照当前已知照片事实及成员变化；已改变的候选重新读取，防止离线保存已同步但筛选仍为空 |
| 局部缓存数字容易看成整批统计 | 增加独立缓存统计来源；使用同一投影计算已保留、已弃选、识别度高、待确认及已跳过数量，迟到的整批统计不覆盖正在展示的缓存计数 |
| 本地分页游标可能混入服务端请求 | 增加独立 `cache-v1-` 游标；缓存页在手机内切片、去重合并，保留局部范围，不把缓存游标发送给盒子 |

投影为只读计算，不改变持久化请求、稳定键、作用域、回执或照片权威版本；按原队列时序处理意图。不会凭空创建未缓存照片、猜测整个批次完整性，或把失败／冲突当作服务端确认。B2.2 的幂等重放和真实 CAS 冲突保护保持有效。
