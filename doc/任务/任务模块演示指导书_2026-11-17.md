## 〇、演示环境准备（演示前 10 分钟）

### 1. 启动 Mock 盒子（窗口 1）

```powershell
cd E:\project\BirdApp
dart run tool/mock_box_server/server.dart --quick --auth --progressive-media `
  --host=0.0.0.0 --port=8787 --auto-smart-follow `
  --device-id=bbx-b7b7b7b7b7b7b7b7b7b7b7b7b7b7b7b7
```

- `--quick`：60 张照片快速集，任务进度全程约 **12 秒走完**（推进器 1s 一 tick）。
- 设备 ID 必须是 **`bbx-` + 32 位小写十六进制（共 36 字符）**，birdSim 约定值为 `bbx-b7b7b7b7b7b7b7b7b7b7b7b7b7b7b7b7`（9 月文档的 `bbx-82f41c9e…` 已作废）。
- 它必须与 App 侧 `simulatedBirdBoxDeviceId`（`lib/bird_companion/features/connection/presentation/b7_simulated_provisioning_repository.dart`）**逐字符一致**，差一位就在直连热点交接时报「设备身份不一致，已停止连接」——这个错误 2026-11-17、11-18 各踩过一次。
- 防呆已就位：mock 启动横幅会打印 `Device ID: … (36 chars)`；`--device-id` 不满足上式（例如多打一对 `b7`）会**直接拒绝启动**并提示实际长度。
- 启动日志应显示 `Workflow auto-advance: enabled`。
- **`--auto-smart-follow` 必须带**：带 `smart_follow_session_id` 的分析任务会被推进器刻意跳过（防止会话快照与任务进度撕裂），进度只能由测试端点 `POST /mock/control/smart-follow` 驱动。现场没人 curl 它 → 点「边识别边复制」后「AI 分析」会永远停在 `0 / 60 · 0%`（2026-11-18 实际踩到）。该开关把驱动内置化：每 1s 自动 commit 一批，60 张约 8s 识别完，再自动 draining → complete_children 收尾。启动日志确认 `SmartFollow auto-drive: enabled`。

### 2. 启动 App（窗口 2，birdSim flavor）

```powershell
cd E:\project\BirdApp
adb reverse tcp:8787 tcp:8787
flutter run -d <设备序列号> --debug --flavor birdSim `
  -t lib/main_bird_simulated.dart
```

- `adb reverse` 把手机上的 `127.0.0.1:8787` 映射回本机 Mock。
- 模拟器用 `http://10.0.2.2:8787`；真机用 `http://127.0.0.1:8787`。
- `BIRD_TEST_BASE_URL`（默认 `http://127.0.0.1:8787`）和 `BIRD_SIMULATED_DEVICE_ID`（默认即上述 36 字符 ID）**默认值已经对得上，一般不用传**；只有换端口才加 `--dart-define=BIRD_TEST_BASE_URL=…`。注意 `BIRD_SIMULATED_DEVICE_ID` 也会过 `^bbx-[0-9a-f]{32}$` 校验，写错（如 42 字符）App 会**启动即抛异常**，不是配对时才报错。

### 3. 完成配对进入首页

- Mock 重启后授权即清空，**必须完整重走配对**（重连无效）。
- 配对码窗口约 60 秒 TTL，拿到配对页后尽快提交。
- 进入三标签首页后，点击底部导航**中间「任务」标签**。

### 4. 演示前检查清单

| 检查项 | 方法 | 不通过时的处理 |
| --- | --- | --- |
| Mock 在跑 | `netstat -ano \| grep 8787` | 端口被占：找 PID `taskkill //F //PID <pid>` 后重启 |
| App 连上盒子 | 任务页顶部无「连接已断开」横幅 | 重走配对 |
| 任务页可操作 | 「下一步」格子按钮不置灰 | 等待「正在读取盒子权威状态」消失 |

### 已知坑（务必记住）

- **K70 真机 adb 点击不可靠**：开了开发者选项里的「USB 调试（安全设置）」后 `adb shell input tap` 能生效，但**约一半的点击会被丢弃**（`input tap` 曾完全失效，`motionevent` 偶发有效）。不要用 adb 脚本连续驱动演示，**关键步骤人工手点**；只读观察用 `adb exec-out screencap` / `uiautomator dump` 没问题。
- Mock 重启 = 重新配对；演示中途 Mock 不能杀。
- **配对授权窗口很短**（模拟层 `pairingCodeTtl` 2 分钟，界面提示「剩余等待时间」）。一旦直连交接报「盒子可达，但授权已失效」或「设备身份不一致」，回「连接方式」或重新配对即可，**不需要重启 Mock**——因为 App 在兑换前会先持久化消费掉授权记录，失败后无法自愈。
- **Mock 的配对会话是一次性的**：同一 Mock 进程里成功配对过一次后，同一会话不能再兑换；换新 App 数据重配对必须重启 Mock。
- `android/gradle.properties` 的 JDK 路径改动是本机配置，不要动它。

### 2026-11-18 修复与待查

- ✅ **导入完成自动级联 AI 分析**已修：原实现用只增不减的 `_analysisRequestedProjects` 去重，Mock 重启后 `project-0001` 这类 id 被回收复用时，陈旧记录会把新批次的级联永久挡死（表现为「导入 100% 完成但 AI 分析不启动」）。现改为「以盒子返回的权威任务为准 + 仅在请求在途时去重」，并对 404 幽灵任务做剔除。
- ✅ 新增 `--auto-smart-follow`（见上）与 `GET /api/v1/smart-follow-sessions` 列表路由（App 回前台恢复跟随卡片用）。
- ⚠️ **待查**：真机上「复制照片」偶发显示「当前批次没有可处理照片」——Mock 单测已证明导入完成后会回填 `total_files=60`，问题疑似在 App 侧的批次摘要读取，正在定位。

## 二、导入与索引（核心主线，约 5 分钟）

这是任务模块的主链路：**读卡 → 建批次 → 导入索引 → 自动级联 AI 分析**。

### 演示点 2-1：进入 SD 卡流程

点「下一步」里的**「导入/索引」**卡片 →

**预期画面**：「读取 SD 卡」页，显示已检测到的存储卡：

- SD 卡插画（自绘 CustomPaint）
- 卡名、照片数量、预计读取空间、RAW/JPEG 数量、扫描时间
- 底部提示「建议先生成缩略图，再开始 AI 分析」
- 按钮：「开始建立批次」（实心）/「稍后处理」（描边）

### 演示点 2-2：建立批次

点「开始建立批次」→ 进入「建立批次」页（步骤 1/4）：

1. **批次名称**输入框已预填 `2026.11.17 拍摄批次`（按扫描日期生成，可改）。
2. 信息卡：照片来源 / 照片数量 / 文件类型 / 预计空间。
3. 安全提示：**「SD 卡只读，原始照片不会被修改或删除」**——这是要强调的设计承诺。

点 **「开始导入并建立索引」** →

- 按钮变「正在创建任务…」
- 自动跳转到**任务详情页**，导入任务进入 running 状态。

### 演示点 2-3：任务详情页（重点讲）

**预期画面**（按代码 `task_detail_page.dart`）：

| 区块 | 内容 |
| --- | --- |
| 断连/重连横幅 | 仅断连时出现，平时不占位 |
| 摘要卡 | 任务类型名 + 状态章 + 「已处理 X / 总 Y 张」大字 + 进度条 + 预计剩余 |
| 任务进度时间线 | 导入任务 4 步：读取照片 → 建立索引 → 生成缩略图 → 准备分析；当前步骤显示状态文字，已完成步骤打勾 |
| 详情卡 | 来源批次 / 当前文件 / 处理速度 / 失败数量 |
| 增量面板 | 「导入与索引 → 生成缩略图与预览 → AI 分析；符合条件的结果会自动分批复制。」+ SmartFollow 跟随卡片 |
| 操作按钮 | 暂停任务 / 取消任务 / 导出日志（按盒子返回的 available_actions 动态渲染） |

**Mock 推进器效果**：进度约 **12 秒走完**，每秒推送一次 job_updated（版本递增），
肉眼可见进度条从 0% 涨到 100%。

### 演示点 2-4：暂停 / 恢复 / 取消（趁 12 秒进行中操作）

进度还在跑时，**快速按顺序演示**：

1. 点**「暂停任务」** → 状态章变「已暂停」，按钮变「继续任务」；Mock 推进器暂停期间不计时，恢复后从原进度继续（讲这句）。
2. 点**「继续任务」** → 状态回「进行中」，进度继续涨。
3. 若时间不够演示取消，改讲：取消会弹确认框「盒子会停止当前任务，已经完成的文件不会被删除」，确认后状态变「已取消」。

> 注意：Mock 1s 一 tick 推进，暂停/取消按 409 冲突处理过版本抖动，但点击要果断；
> 失败了会弹 SnackBar 提示，点一次重试即可。

### 演示点 2-5：导入完成 → 自动级联 AI 分析

导入 12 秒完成后：

- 时间线 4 步全部打勾，状态章「已完成」。
- **App 自动为该项目创建 AI 分析任务**（`RepositoryTaskExperienceController._afterJobUpdate` 级联），
  详情页出现新的分析任务卡片，或返回首页可见「当前任务」已切到 AI 分析。

> 讲解词：用户不需要手动点"开始分析"——导入完成后 App 检测到导入任务完成事件，
> 自动提交分析任务。这是任务链路的自动编排能力。

## 四、复制照片任务（约 5 分钟）

### 演示点 4-1：从任务首页发起复制

回任务首页，确认「当前任务」已无进行中任务（或分析已完成）。

点「下一步」里的**「复制照片」**卡片 → 跳转 **复制确认页**（`/copy-confirmation` 路由，
属复制模块 RC3 流程，任务模块负责入口与跳转）。

> 注意：复制确认页是独立模块（features/copy），此处任务模块只负责**入口分发与完成后刷新**。
> 演示时重点讲任务首页对复制任务状态的承接（见 4-2）。

### 演示点 4-2：复制任务在任务模块的呈现

复制任务创建后回到任务首页/详情页：

- 任务列表出现「复制照片」任务行，来源批次显示项目名。
- **复制与全量备份互斥**：讲解「同一时间只能有一个目标写任务」（协议 §16）——
  此时看「全量备份」按钮置灰，原因「已有复制/备份任务正在使用目标设备」。

### 演示点 4-3：复制结果报告页

复制任务完成后（RC3 copy 独立推进，约几分钟走完 60 张）：

- 任务详情页点右上角 ⋯ → **「查看复制结果」**，或详情页底部结果按钮。
- **复制结果页**（`ProductionTaskResultPage`）按报告结果分四种外观：

| 结果 | 标题/图标 |
| --- | --- |
| success | 「照片复制完成」绿色对勾 |
| partialSuccess | 「照片部分复制完成」黄色警告 |
| failed | 「照片复制失败」红色错误 |
| cancelled | 「复制任务已取消」灰色 |

- 指标卡：复制照片数 / 数据大小 / XMP 数量 / 耗时。
- 有跳过项时显示黄色提示「有 N 个文件待人工确认」。
- 点 **「查看复制报告」** → 底部弹层「复制报告」：

  - 失败文件明细（文件名 + 文件 ID + 失败原因），支持**「加载更多失败项」**分页。
  - 失败项按钮 **「重试失败项」**（详情页操作区）。

> 演示技巧：若复制任务较长，可先讲 4-2 互斥，等报告出来再回来看 4-3。
> Mock 的 RC3 复制推进约 1.8 秒/项，60 张约 2 分钟。

### 演示点 4-4：复制任务独立列表

任务首页任务列表标题行右侧点**「复制任务」**按钮 → 进入独立的复制任务列表页

## 五、全量备份（约 2 分钟，讲清即可）

点「下一步」里的**「全量备份」**卡片。

**两种情形**：

- Mock `copy-capabilities` 默认含 `media_full_backup`（当前 MockCopyRepository 返回支持）→ 可发起，流程与复制类似但 scope 是整卡备份。
- 若能力声明不含（真实后端旧版本）→ 按钮置灰，原因**「当前盒子不支持全量备份」**。

> 讲解词：全量备份与普通复制是两个不同 scope（media_full_backup vs 资产复制），
> 但都是「目标写任务」，互相互斥；且都要求相机存储卡在位（未插卡时禁用，原因「未检测到相机存储卡」）。

**演示要点**：不插卡 / 能力不支持时按钮置灰 + 原因文案，体现能力门控。

## 六、同步任务（约 3 分钟）

同步的前提是**有本地待同步修改**（离线审阅决策、批量标签等排队在本机 pending 队列）。
没有待同步项时「同步」按钮置灰，原因**「没有待同步的本地修改」**——这也值得演示。

### 演示点 6-1：制造一条待同步修改

1. 切到**相册标签**，任选一张照片做一次审阅操作（改保留状态 / 加标签 / 评分）。
2. （可选）断开 Mock（杀掉窗口 1 进程）→ 该修改进入离线 pending 队列。
3. 重启 Mock + App 重连 → pending 队列里留下这条操作。

### 演示点 6-2：手动触发同步

回任务页，点「下一步」里的**「同步」**卡片 →

- App 调 `BirdSyncService.synchronize()`，逐条重放 pending 操作
  （幂等键 = 操作 ID，重复同步不会在盒子上产生重复审阅——讲这句）。
- 弹出**同步结果面板**（`TaskSyncResultSheet`）：
  - 已同步 / 失败 / 版本冲突 / 仍需处理 四项计数。
  - 全部成功：标题「同步完成」+ 绿色云图标。
  - 有失败/冲突：标题「同步需要处理」+ 黄色提示条（冲突项指引去照片详情选择保留盒子内容）。
  - 有冲突时按钮变**「处理冲突」**，点击直达冲突照片。

### 演示点 6-3：同步任务摘要

同步也会作为任务出现在任务列表（类型「同步」）。完成后进详情，
点右上角 ⋯ → **「查看同步摘要」** → 底部弹层显示已处理 / 总数 / 失败 / 完成时间，
并附诚实提示：「盒子当前没有提供可按任务恢复的逐项同步结果；这里仅显示权威汇总」。

> 讲解词：同步任务标题特意写成「同步（含缩略图与预览，不是 U 盘复制）」，
> 避免用户误解。

## 七、任务列表与分组（约 2 分钟）

### 演示点 7-1：三组筛选

任务列表上方筛选条：**进行中 / 需处理 / 已完成**。

- 「进行中」= queued + running。
- 「需处理」= paused + failed（失败项右侧红字「失败 N 项」；任务级失败没有逐文件失败时只显示「失败」，不显示误导性的「失败 0 项」——细节可提）。
- 「已完成」= completed + cancelled，副标题显示「完成于 M月D日 HH:MM」。

### 演示点 7-2：分页加载

历史任务超过第一页（约 20 条）时，列表底部出现**「加载更多任务」**按钮 →
点击加载下一页；刷新时已加载的历史页不会被清掉（`_pagedJobs` 保留）。
演示集只有几条任务时此点可跳过，口述即可。

### 演示点 7-3：失败任务的控制按钮

Mock 推进器正常走完不会失败。若要演示失败态，可用 Mock 测试钩子
（对指定 job 调 failJob）或人为断连制造失败，展示：

- 「重试失败项」「跳过失败项」「取消任务」「导出日志」按钮组。
- 跳过失败项 → 任务直接进「已完成」，失败项计入报告。
- **导出日志**：点击后 SnackBar 显示「任务日志已下载到：<路径>」（走 `/api/v1/logs/export` + 签名 URL 下载）。

## 八、断线韧性（加分演示，约 3 分钟）

### 演示点 8-1：断连横幅

演示中杀掉 Mock 进程（或关掉 adb reverse）→

- App 顶部出现 **DisconnectedBanner**（app_shell 层，仅任务标签）。
- 任务页内部再叠一层 **「连接已断开，盒子任务可能仍在运行；重新连接后刷新任务进度」** 通知。
- 所有写操作按钮（暂停/取消等）自动失效（`canSubmitTaskWrites` 门控）。

### 演示点 8-2：重连后权威刷新

重启 Mock + 重新连接（birdSim 需完整重配对，或用重连入口）→

- **WebSocket 恢复后强制走一次 REST 全量快照**（事件可能丢，REST 是冻结 v1 唯一权威源——讲这句）。
- 「当前任务」空态文案会区分三种状态：断开「盒子任务可能仍在运行」/ 重连中「正在重新连接盒子」/ 在线读取中「正在读取盒子任务状态」。

> 演示技巧：8-1/8-2 重建配对耗时约 1 分钟，若时间紧可在开场前先造好一条
> 离线审阅（配合第六节），现场只演示断连横幅 + 恢复，不重走完整配对。

## 九、离线排队与 409 冲突（加分演示，约 3 分钟）

### 演示点 9-1：版本冲突

1. 手机 A 上打开某任务详情。
2. 用 curl 对同一任务再发一次 pause（消耗一个版本）：

```bash
curl -X POST http://127.0.0.1:8787/api/v1/jobs/<jobId>/actions \
  -H "Authorization: Bearer <token>" \
  -H "X-Idempotency-Key: demo-conflict-1" \
  -H "Content-Type: application/json" \
  -d '{"action":"pause","version":<当前版本>}'
```

3. 手机上再点「暂停任务」→ 409 → App 自动刷新任务详情拿最新版本，
   SnackBar 提示冲突。

> 讲解词：任务控制带乐观锁（version），冲突时自动恢复到权威状态，不会悄悄覆盖。

## 十、演示收尾话术（30 秒）

- 任务模块 = **一个入口、五类任务、一条自动级联链**（导入 → 分析 → 复制/相册）。
- 所有任务状态以**盒子为权威源**：REST 快照 + WebSocket 增量 + 4 秒轮询兜底（事件断开时）。
- 所有操作带**乐观锁 + 幂等键**，断线不丢单、重连不重放、冲突自动恢复。
- 能力门控全部**给出原因**，不搞静默禁用。

## 附：常见问题应对

| 现场状况 | 应对话术 | 处理 |
| --- | --- | --- |
| 进度不动 | 「推进器按真实墙钟推进，暂停期间不计时」 | 确认任务处于 running |
| 暂停/取消报错 409 | 「1 秒一 tick 的推进器与手动操作撞版本，属预期」 | 重试一次即可 |
| 详情页「阶段未知」 | 「证据制时间线：协议未声明子阶段时不编造状态」 | 口述设计决策 |
| 复制结果「XMP 盒子未提供权威数量」 | 「协议未提供 XMP 计数端点，App 不编数字」 | 口述 |
| 同步按钮置灰 | 「没有待同步的本地修改——这是能力门控的正确表现」 | 按 6-1 造一条 |
| Mock 连不上 | 「先确认 adb reverse 和端口」 | `netstat -ano \| grep 8787` |
| App 进程卡死 | 白屏挂死多为 dart-define 格式错 | 重启 flutter run，检查 define 串 |
