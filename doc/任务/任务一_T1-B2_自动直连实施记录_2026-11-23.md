# 任务一 T1 B2 自动直连实施记录

日期：2026-11-23。起点为B1提交 `e79f8552e`，分支 `codex/task1-network-20261123`。本批接通Android正常直连的系统入网主线；真实手机弹窗、网络角色切换、媒体实际路由及盒子退出恢复仍待后续真机验收。

## 实现结果

授权且关联当前设备/operation的AP ready保存在生产repository的内存配置中，并保留短期加密授权的既有消费规则。全局装配的handoff先调用 `prepareDirectApNetwork`，协调器请求具体SSID并绑定本地网络，随后才验证公开设备身份、兑换/恢复授权、读取受保护HTTP并建立WS，业务验证完成后将租用标为online。

正常与恢复AP共用B1协调器；按device/operation/intent和配置合并请求。重复事件、连点、前后台信号及HTTP暂时不可达不重复发系统join。用户取消或旧代次失效后，迟到onAvailable不能绑定、发送凭据或导航。验证失败/超时清理当前租用；凭据本地保存失败保留可显式重试的已验证过程，不再次兑换授权。

已在目标网络上的设备以真实公开身份响应核验后复用，不以SSID、历史批准或缓存代替当前可达性，也不再次启动AP。手工备用仅在明确失败后由用户选择，仍先验证设备身份再恢复授权；诊断终态标记 `connection_path=manual_rescue`，不计自动接入通过。

全局切换设备也会按旧device归属释放请求；单独BLE断开或成功页面销毁不释放业务网络。真实网络切换时重建应用自己持有的HTTP/媒体连接池并断开旧WS，随后走原有业务验证重建；注入的调用方自有adapter保持原归属。STA交接保留任务二释放旧AP与恢复业务的流程。

## 安全类型和错误分类

| 声明类型 | Android请求 |
| --- | --- |
| wpa2_personal | setWpa2Passphrase |
| wpa3_personal | 检查手机SAE能力后setWpa3Passphrase |
| wpa2_wpa3_transition | 明确使用该过渡模式允许的WPA2 |
| open或未知类型 | 本轮直连不支持，明确报错；不静默按WPA2处理 |

Dart向原生传递security；native仍使用具体SSID和无互联网的本地请求。`onUnavailable`统一保留“连接未建立”，不将无法区分的拒绝、AP不可见或超时全部误报为用户取消。明确用户取消、权限不足、安全类型不支持和绑定失败分别处理；release通道携带真实原因，STA切网不再被native统一标成用户取消。

Android API依据：[本地Wi-Fi请求](https://developer.android.com/develop/connectivity/wifi/wifi-bootstrap)、[WifiNetworkSpecifier.Builder](https://developer.android.com/reference/android/net/wifi/WifiNetworkSpecifier.Builder)。首次可能仍需系统批准，同一具体AP的批准复用以手机实际条件为准，本批不承诺首次静默或所有机型无弹窗。

## 界面和诊断

正常直连页显示“正在请求连接盒子热点”和系统确认说明，不展示密码、不把WLAN设置作为首选操作。仅明确失败后提供故障备用WLAN入口；STA仍保留同网说明与设置入口。身份/配对授权错误提供与实际按钮一致的返回引导，本地凭据保存失败保留显式重试入口。

诊断复用现有journal，记录join开始/available/lost/绑定/复用、device/operation/attempt/generation、客户端重建及释放原因；不记录密码或token。普通pending仍只保存公开端点数据，未新增明文密码持久化。
