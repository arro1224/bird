# 拍鸟盒子：复制、摄影资料全量备份与多存储设备三端协议

**版本：** v1.0-rc1（开发冻结版）  
**日期：** 2026-08-24  
**适用端：** 拍鸟伴侣 App、盒子业务后端、盒子存储服务  
**协议标识：** `birdbox-copy-v1`  
**文档性质：** 三端实现唯一基线；需求来源文档用于解释意图，不直接充当接口规范

---

## 0. 文档状态与术语

本文使用以下规范词：

- **必须（MUST）**：缺失即不符合本协议。
- **禁止（MUST NOT）**：任何端不得采用。
- **应当（SHOULD）**：除非存在可记录、可复核的特殊原因，否则必须采用。
- **可以（MAY）**：兼容性扩展，不得破坏既有字段和语义。

本版冻结的是三端协议、职责边界、状态机、安全规则和第一版文件范围。摄影格式清单允许通过后续兼容版本追加，但禁止在同一协议版本中静默删减或改变已有格式含义。

## 1. 冻结结论

以下结论在 v1.0-rc1 中冻结：

1. 导入/分析源设备和复制目标设备必须由用户选择，盒子不得按 `/dev/sdX`、插入顺序或固定 USB 口静默决定。
2. App 可以为同一批次预选上次成功使用的目标设备，但必须允许用户修改；不得设置跨批次、永久绑定的物理默认盘。
3. 一项复制任务只能有一个源设备和一个目标设备，且二者不得相同。
4. 源设备必须只读挂载；只有获得有效写租约的目标设备可以临时读写挂载。
5. “复制”和“分析”相互独立。照片是否已分析不得决定其能否复制；系统资源调度可影响速度，不得改变业务范围。
6. “摄影资料全量备份”是独立入口，范围是摄影相关文件，不是整盘镜像。Word、PDF、安装包等无关文件不得包含。
7. 同名冲突没有隐式默认值。每次新建任务时用户必须明确选择：跳过、覆盖目标副本或两份都保留。
8. RAW+JPEG 视为一个逻辑照片。第一版默认复制 RAW；用户可在任务确认页选择 RAW、JPEG 或两者。
9. 复制必须保留原始文件名，不得修改源文件。目标目录由盒子按本协议生成。
10. 开启“随副本保存审阅信息”时，任务必须同时输出 XMP 与 CSV，并在安全兼容的副本格式上优先嵌入标准字段；RAW 只写 sidecar，永不改源文件。
11. 关闭上述开关时，系统仍保留盒子内部最小复制记录，但不得向目标盘输出 XMP、审阅 CSV 或嵌入审阅字段，也不得自动建立待同步审阅信息。
12. 用户最终确认的鸟种、评分、保留状态优先于 AI 原始结果；AI 原始结果仍须在内部数据库中保留，不得被覆盖。
13. 任务必须支持断线继续、失败项重试、文件边界暂停/继续、取消和安全移除。App 断线不得使板端任务停止。
14. 设备身份必须使用稳定 `media_id`；`/dev/sda1`、挂载路径和 USB 口编号只能作为板端内部瞬时信息。

## 2. 三端职责边界

### 2.1 App

App 负责：

- 展示设备类型、名称、容量、空间、状态和可选角色；
- 让用户选择源设备、目标设备、复制范围、RAW/JPEG 策略、同名策略和审阅信息开关；
- 创建不可变的选择快照；
- 展示预检结果、进度、错误、报告和历史；
- 发起暂停、继续、取消、失败项重试和安全移除；
- 记住“同一批次上次成功目标设备”，并仅作为可修改的预选项。

App 禁止：

- 直接接触 Linux 绝对路径；
- 直接把文件从源盘复制到目标盘；
- 使用 `/dev/sdX` 作为设备 ID；
- 在缺少用户同名策略时自行填默认值；
- 因断线而取消盒子任务；
- 把“识别为读卡器”当作自动源盘授权。

### 2.2 业务后端

业务后端负责：

- 对 App 提供本协议的 HTTP API；
- 批次、逻辑照片、选择快照、审阅快照、复制任务和报告的持久化；
- 校验用户请求并生成不可变执行清单；
- 调用盒子存储服务的内部接口，不直接把 Linux 路径暴露给 App；
- 维护任务状态机、幂等、断线恢复、失败项重试和事件流；
- 生成 CSV 内容与标准化 XMP 数据模型；
- 保存内部最小复制记录，即使用户关闭目标盘审阅导出；
- 将任务所需文件 ID 转换为存储服务可以验证的内部源引用。

业务后端禁止：

- 自行重新实现挂载、卸载、设备身份和原子文件替换；
- 直接改相机卡或其他源介质；
- 用 App 当前页面字段反向定义协议；
- 将 AI 结果覆盖成人工结果；
- 在同名策略缺失时创建任务。

### 2.3 盒子存储服务

盒子存储服务负责：

- 发现可移动介质并排除系统盘；
- 生成稳定 `media_id` 和设备展示提示；
- 源盘只读挂载、目标盘写租约、安全同步和卸载；
- 摄影资料白名单扫描；
- 路径越界、符号链接、挂载变化和设备替换校验；
- 原子复制、临时文件、哈希、空间预检和取消检查；
- XMP/CSV 文件落盘及安全格式的副本元数据写入；
- 提供内部 Unix Socket 控制接口；
- 写租约过期或执行进程异常后恢复目标盘只读。

盒子存储服务禁止：

- 决定用户要复制哪些照片；
- 决定用户的同名策略；
- 解释“保留/评分/鸟种”的业务含义；
- 修改源盘文件、源盘时间戳或源盘元数据；
- 把硬件型号提示作为源/目标角色授权。

## 3. 核心对象和稳定标识

| 对象 | ID 格式 | 创建端 | 是否稳定 |
|---|---|---|---|
| 存储介质 | `media_<24hex>` | 存储服务 | 同一文件系统介质重新插拔稳定 |
| 批次 | `batch_<uuid>` | 业务后端 | 永久 |
| 逻辑照片 | `asset_<uuid>` | 业务后端 | 批次内永久 |
| 选择快照 | `sel_<uuid>` | 业务后端 | 创建后不可变 |
| 审阅快照 | `review_<uuid>` | 业务后端 | 创建后不可变 |
| 复制任务 | `copy_<uuid>` | 业务后端 | 永久 |
| 单文件执行项 | `copyitem_<uuid>` | 业务后端 | 永久 |
| 目标盘写租约 | 随机 256-bit token | 存储服务 | 仅内部、短时有效 |
| 请求幂等键 | UUID/ULID | App | 同一意图重试时不变 |

### 3.1 `media_id`

有文件系统 UUID 时：

```text
media_id = sha256("birdbox-media-v2\0uuid\0" + lower(fs_uuid) + "\0" + lower(fs_type))[0:24]
```

无 UUID 时允许使用文件系统、容量、卷标和只读清单摘要生成降级指纹。无 UUID 设备在清单变化后可能产生新 ID，后端必须返回 `identity_confidence=degraded`，App 不得将其作为长期默认目标。

`media_id` 禁止包含设备节点、挂载点、USB 口或读卡器序列号；换读卡器后，同一张有 UUID 的卡仍应保持同一 ID。

## 4. 设备发现、展示与选择

### 4.1 设备返回模型

业务后端对 App 返回：

```json
{
  "media_id": "media_7f9a76e6c97690b61aedf6fd",
  "display_name": "U 盘 Ee",
  "kind": "usb_flash",
  "kind_confidence": "medium",
  "detail": "SanDisk Ultra USB 3.0 · 28.7 GB · EXFAT",
  "capacity_bytes": 30765203456,
  "free_bytes": 30500000000,
  "filesystem": "exfat",
  "label": "Ee",
  "role_state": "available",
  "can_be_source": true,
  "can_be_target": true,
  "target_block_reasons": [],
  "identity_confidence": "stable_uuid",
  "last_seen_at": "2026-08-24T14:30:00+08:00"
}
```

`kind` 枚举：

- `memory_card`
- `card_reader`
- `usb_flash`
- `usb_storage`
- `external_hdd`
- `external_ssd`
- `removable_storage`
- `unknown`

`kind_confidence` 枚举：`high`、`medium`、`low`、`unknown`。

### 4.2 展示规则

1. 用户别名优先于卷标，卷标优先于通用类型名。
2. 多逻辑槽位且存在空槽位可作为读卡器高可信证据。
3. 厂商/型号中的 `reader`、`USB`、`flash` 等只能作为提示，不得授权角色。
4. `DCIM`、相机文件扩展名等内容信号只可提高提示可信度。缺少 `DCIM` 不得排除相机卡。
5. 无可靠证据时必须显示“USB 存储设备（类型未确认）”，并展示容量、卷标和型号。
6. App 应提供“给设备命名”能力；别名由后端按 `media_id` 保存。
7. 如需显示“USB 口 1/2/3”，必须先对具体硬件型号做物理端口到拓扑路径的出厂映射；未校准前禁止猜测端口编号。

### 4.3 可选角色

以下设备不得成为目标：

- 系统盘或系统盘分区；
- 当前任务源设备；
- 硬件只读设备；
- 不支持或只读的文件系统；
- 空间不足；
- 正被其他任务持有写租约；
- 正在安全移除保持期；
- 身份已变化或设备已拔出。

App 必须显示不可选原因，不得仅灰掉选项。

### 4.4 同批次目标盘预选

后端可保存：

```json
{
  "batch_id": "batch_...",
  "last_successful_target_media_id": "media_...",
  "updated_at": "..."
}
```

仅当该设备当前在线且仍可作为目标时，App 才可预选。预选不是确认；提交前确认页必须再次展示目标名称、容量和预计写入量。若预选设备不在线，不得自动换成另一块盘。

## 5. 复制范围

`scope` 必须为以下之一：

| `scope` | 用户语义 | 文件来源 |
|---|---|---|
| `selected_assets` | 复制我选中的照片 | 不可变选择快照 |
| `kept_assets` | 复制本批次标记为保留的照片 | 创建任务时的审阅快照 |
| `batch_all_assets` | 复制本批次全部照片 | 批次不可变资产清单 |
| `media_full_backup` | 备份该源设备全部摄影资料 | 创建任务时重新扫描源设备 |

旧的 `keep/all/dual` 不属于本协议。`dual` 必须删除；RAW+JPEG 由独立 `pair_policy` 表达。

### 5.1 摄影资料全量备份

全量备份只包含以下类别：

**成片/通用图像：**

```text
AVIF BMP HEIC HEIF HIF JPE JPEG JPG PNG TIF TIFF WEBP
```

**RAW：**

```text
3FR ARW CR2 CR3 DCR DNG ERF FFF IIQ KDC MEF MOS MRW NEF NRW
ORF ORI PEF RAF RAW RW2 RWL SRW X3F
```

**视频/专业视频：**

```text
3GP AVI BRAW CRM M2TS MOV MP4 MPEG MPG MTS MXF R3D
```

**摄影伴随文件：**

```text
AAE BWF COS LRV SRT THM VTT WAV XML XMP
```

扩展名比较不区分大小写。第一版禁止按 MIME 猜测并复制无扩展名文件。

明确排除：

- DOC/DOCX、XLS/XLSX、PPT/PPTX、PDF、TXT；
- ZIP/RAR/7Z、APK/EXE/DMG、程序和系统文件；
- 回收站、系统索引、隐藏临时目录；
- 符号链接及其目标；
- 不在白名单内的其他文件。

扫描报告必须给出 `included_count`、`included_bytes` 和按扩展名统计的跳过数量，但不得把跳过的文档文件名上传给 App，除非用户进入诊断页。

格式清单带版本 `photography_policy_version=1`。追加格式须提升版本并保持向后兼容；删除格式或改变类别必须提升协议主版本。

## 6. 逻辑照片、RAW+JPEG 与伴随文件

### 6.1 逻辑配对

同一目录内，去掉扩展名后文件名大小写相同的 RAW 和 JPEG/HEIF，视为一个逻辑照片。相机生成的 XMP、THM、XML 等可关联到同名主文件。

不得只凭拍摄时间相近自动合并不同文件名；模糊配对只能作为后续版本功能。

### 6.2 `pair_policy`

枚举：

- `raw_only`：默认；有 RAW 时复制 RAW，无 RAW 时复制可用成片。
- `jpeg_only`：优先 JPEG/HEIF，无成片时该逻辑照片进入 `not_applicable`，不得静默改复制 RAW。
- `both`：复制 RAW 和 JPEG/HEIF。

对于 `media_full_backup`，`pair_policy` 不生效：白名单内所有原始摄影文件都必须包含。这是“备份”与“按照片复制”的关键区别。

### 6.3 伴随文件

- `selected_assets`、`kept_assets`、`batch_all_assets`：复制与选中主文件明确同名关联的原有摄影伴随文件。
- `media_full_backup`：复制白名单内全部伴随文件。
- BirdBox 新生成的 XMP/CSV 由第 9 节控制，不属于源文件伴随复制。

## 7. 目标目录与原始文件名

### 7.1 固定目录规则

盒子必须写入：

```text
<目标盘>/BirdBox/YYYY/MM/DD/<原始文件名>
```

日期选择顺序：

1. EXIF/QuickTime/XMP 中可信的原始拍摄时间；
2. 源文件修改时间；
3. 任务创建日期。

每个执行项必须记录 `date_source=capture_time|source_mtime|job_created_date`。伴随文件跟随其主文件日期；无法关联的伴随文件使用自身修改时间。

禁止在用户文件名中加入 AI 鸟种、评分、任务 ID 或“保留”等词。禁止修改原扩展名大小写。

### 7.2 管理文件

用户开启审阅导出时，每个任务另写：

```text
<目标盘>/BirdBox/Reports/<copy_job_id>/BirdBox_Review.csv
```

XMP sidecar 与对应文件同目录、同主文件名，例如：

```text
DSC0001.ARW
DSC0001.xmp
```

目标盘不得保存业务数据库、访问令牌、Linux 路径或完整内部事件日志。

## 8. 同名冲突

创建任务时 `conflict_strategy` 为必填，枚举：

- `skip`：保留既有目标文件，该执行项记为 `skipped_conflict`。
- `overwrite`：将新内容写入临时文件并校验，最后原子替换目标副本；绝不原地截断写入。
- `keep_both`：生成 `文件名 (1).扩展名`、`文件名 (2).扩展名`，选择首个不存在名称。

后端在字段缺失时必须返回 `COPY_CONFLICT_STRATEGY_REQUIRED`，不得填默认值。

同一任务创建后策略不可修改。用户若要换策略，必须取消未完成任务并创建新任务；已完成文件不会自动回滚。

## 9. 审阅信息、XMP、CSV 与副本嵌入

### 9.1 请求模型

```json
{
  "review_export": {
    "enabled": true,
    "write_xmp": true,
    "write_csv": true,
    "embed_into_supported_copy": true
  }
}
```

规则：

- `enabled=true` 时 `write_xmp` 与 `write_csv` 在 v1 必须同时为 `true`。
- `enabled=false` 时其余三个字段必须为 `false` 或省略。
- 新任务 UI 建议默认开启，但 App 必须让用户在确认页看见并可关闭。此项默认值属于 UI 偏好，不改变上述协议语义。

### 9.2 内部记录与目标盘导出

无论开关状态，业务后端都必须保存：任务 ID、源/目标 `media_id`、文件 ID、源相对路径、目标相对路径、字节数、哈希、状态、错误和时间。这是复制可靠性记录，不是目标盘审阅文件。

关闭时：

- 不创建 BirdBox XMP；
- 不创建审阅 CSV；
- 不向 JPEG/HEIF/TIFF 等副本嵌入评分、鸟种或保留信息；
- 后续人工修改不为该任务自动建立元数据同步待办。

### 9.3 审阅快照

任务创建时生成不可变 `review_snapshot_id`。至少包含：

- AI 原始 Top-1、Top-K、置信度、判定档位；
- 用户最终鸟种和是否人工确认；
- 评分；
- 保留/不保留/未审阅；
- 模糊、眼部、构图等所有 App 可见分析标签；
- 拍摄时间、相机信息、原始文件名；
- 数据来源和最后修改时间。

用户值存在时，导出字段以用户值为最终值，同时在 BirdBox 自定义命名空间中保留 AI 原始值。禁止覆盖内部 AI 原始记录。

### 9.4 XMP 兼容规则

优先使用标准字段：

- `xmp:Rating`：0–5；
- `dc:subject`：最终鸟种及用户标签；
- `photoshop:Urgency` 或兼容色标映射：仅在产品定义明确时使用；
- `xmp:Label`：用户可见标签文本。

BirdBox 扩展命名空间固定为：

```text
https://schemas.birdbox.app/review/1.0/
```

至少包含：`FinalSpecies`、`FinalSpeciesSource`、`KeepState`、`AiTop1Species`、`AiTop1Confidence`、`AiVerdict`、`ReviewSnapshotId`、`CopyJobId`。

RAW 永远只写 sidecar。对 JPEG、TIFF、HEIF 等格式，只有 ExifTool 能在临时副本上成功写入、重新读取并验证像素数据未变化时，才允许嵌入；否则保留普通副本并写 XMP，不得把元数据写入失败升级为原片损坏。

兼容验收目标：Adobe Lightroom Classic、Adobe Bridge、Capture One。三者无法统一识别的自定义信息仍保存在 BirdBox 命名空间和 CSV 中。

### 9.5 CSV

CSV 使用 RFC 4180、UTF-8 with BOM、CRLF。固定列至少包括：

```text
copy_job_id,review_snapshot_id,asset_id,source_filename,target_relative_path,
capture_time,date_source,raw_jpeg_role,final_species,final_species_source,
rating,keep_state,ai_top1_species,ai_top1_confidence,ai_verdict,
copy_state,bytes,source_sha256,destination_sha256,error_code
```

一项逻辑照片若复制 RAW+JPEG，应有两行，共用同一 `asset_id`。

## 10. 复制预检与不可变执行清单

任务创建分两步：`preview` 与 `create`。

### 10.1 预检

预检必须返回：

- 源/目标设备当前身份与角色；
- 逻辑照片数、实际文件数、总字节数；
- 按 RAW/JPEG/视频/伴随文件分类统计；
- 预计日期目录数；
- 同名文件数量；
- 目标可用空间与至少 5% 或配置下限的安全余量；
- 不支持、缺失、已拔出和权限错误；
- `preview_token` 与过期时间。

预检不取得长期写租约，不写目标盘。

### 10.2 创建任务

创建时后端必须重新验证：

- `preview_token` 未过期；
- 源/目标 `media_id` 未改变；
- 选择快照未改变；
- 同名策略存在；
- 空间仍足够。

随后生成不可变执行项，至少包含：

```json
{
  "copy_item_id": "copyitem_...",
  "asset_id": "asset_...",
  "source_media_id": "media_...",
  "source_relative_path": "DSC0001.ARW",
  "source_size": 52703232,
  "source_mtime_ns": 1782789298000000000,
  "target_relative_directory": "BirdBox/2026/08/24",
  "target_filename": "DSC0001.ARW",
  "state": "pending"
}
```

源绝对路径不得写入公开 API 或 App 数据库。

## 11. 文件复制算法

每个文件必须执行：

1. 在源盘只读挂载和稳定 `media_id` 下重新解析相对路径；
2. 拒绝绝对路径、`..`、符号链接、非普通文件和越界路径；
3. 校验当前大小和修改时间与执行清单一致；
4. 检查目标写租约、文件系统和剩余空间；
5. 在目标目录创建隐藏临时文件：`.原文件名.birdbox-part-<uuid>`；
6. 以固定大小流式读取并同时计算源 SHA-256；
7. `fsync` 临时文件，保留源文件修改时间；
8. 按配置重新读取目标临时文件并计算 SHA-256；v1 正式模式必须开启；
9. 哈希一致后执行原子 `replace`；
10. `fsync` 目标目录；
11. 更新内部执行项状态。

取消或异常时只允许删除本任务的 `.birdbox-part-<uuid>`，不得删除已有目标文件、源文件或其他任务临时文件。

源文件在复制期间发生大小、时间或身份变化时，执行项失败为 `COPY_SOURCE_CHANGED`，不得继续使用旧哈希。

## 12. 任务状态机

任务状态：

```text
draft
  -> preflighted
  -> queued
  -> acquiring_target
  -> running
  -> pause_requested -> paused -> running
  -> cancel_requested -> cancelled
  -> waiting_for_source | waiting_for_target -> queued/running
  -> completed | completed_with_errors | failed
```

单文件状态：

```text
pending -> copying -> verifying -> copied
                         |-> failed
pending -> skipped_conflict
pending -> not_applicable
copying/verifying -> pending（仅进程恢复时，清理本项临时文件后）
```

规则：

- `pause` 在文件边界生效；当前正在写的文件完成并校验后进入 `paused`。v1 不承诺字节级暂停。
- `cancel` 可在块边界检查并终止当前临时文件，随后状态为 `cancelled`。
- `retry-failed` 只为失败项创建新尝试，不重复制成功项和已跳过项。
- 同一任务最多一个执行 worker；整个盒子最多一个目标写租约。
- App 断线不改变任务状态。
- 重启恢复时，`copying/verifying` 项回到 `pending`，只清理与该项 ID 匹配的临时文件。

## 14. 业务后端 ↔ 存储服务内部接口

正式接口使用 Unix Domain Socket：

```text
/home/kickpi/birdbox_data/runtime/storage-control.sock
```

权限 `0660`，仅 `kickpi` 用户/指定服务组可访问。禁止监听公网或局域网 TCP 端口。

传输格式：每行一个 UTF-8 JSON 对象（JSON Lines），单消息最大 1 MiB。每个请求和响应必须含 `request_id`、`protocol_version=birdbox-storage-v1`。

方法：

| method | 作用 |
|---|---|
| `devices.list` | 返回稳定设备、展示和角色状态 |
| `source.verify` | 验证源介质在线、只读、身份一致 |
| `target.acquire` | 获取单目标盘写租约 |
| `target.renew` | 续租；复制 worker 每 30 秒调用 |
| `target.release` | 同步、卸载并恢复只读 |
| `media.safe_remove` | 同步、卸载并进入短时禁止重挂载状态 |
| `photography.scan` | 生成摄影资料白名单清单 |
| `file.copy` | 原子复制一个执行项 |
| `file.write_xmp` | 写副本 sidecar |
| `file.write_csv` | 原子写/替换任务 CSV |
| `file.embed_metadata` | 仅修改目标临时副本并复核 |

`target.acquire` 请求不得传设备节点：

```json
{
  "request_id": "req_...",
  "protocol_version": "birdbox-storage-v1",
  "method": "target.acquire",
  "params": {
    "source_media_id": "media_...",
    "target_media_id": "media_...",
    "owner": "copy_<uuid>",
    "ttl_seconds": 120
  }
}
```

存储服务返回不透明 `lease_token`。业务后端不得将 token 传给 App 或写入普通日志。租约到期后存储服务必须在共享锁保护下恢复目标只读；任务转为 `waiting_for_target` 或 `failed`。

`file.copy` 只接受 `source_media_id + source_relative_path + target_relative_directory + target_filename + conflict_strategy + expected_size + expected_mtime_ns`，禁止接受任意源绝对路径。

## 16. 并发、资源与性能

1. 全盒子同时最多一个目标写租约、一个复制 worker。
2. 分析和复制业务上可并存，但板端 I/O 调度必须限制并发，避免相机卡随机读竞争。
3. 第一版复制 worker 数固定为 1，流式块默认 1 MiB；不得盲目增加 worker。
4. NPU 分析不因复制而取消。存储压力高时，调度器可以在文件边界降低复制或分析优先级。
5. 任务报告记录：总墙钟时间、有效吞吐、复制/跳过/失败数量、源/目标设备类型、文件系统、哈希验证开关和错误。
6. 性能验收至少覆盖 JPEG、ARW、混合文件、100 GB 级长任务、拔盘和断电恢复；不得只用一个小文件得出性能结论。

## 17. 安全移除、拔盘和断电

### 17.1 正常安全移除

目标盘：停止派发新文件 → 等当前原子项结束或取消 → 刷新 CSV/XMP → `sync -f` → 卸载 → 写入 `safe_remove_hold` → 返回 App。

源盘：确认无分析/复制读取 → 卸载 → 写入 `safe_remove_hold` → 返回 App。

保持期内设备仍插着时不得自动重挂载；默认 60 秒，最长 300 秒。设备拔出后清除保持记录。

### 17.2 非正常拔盘

- 当前临时文件不得被当作完成文件；
- 已原子完成并校验的文件保持成功；
- 当前项进入 `failed` 或 `waiting_for_target`；
- 重插时必须按 `media_id` 验证是同一设备，不能因挂载到原路径就继续；
- 不得切换到另一目标盘静默继续。

### 17.3 断电恢复

- 后端数据库使用事务保存任务和执行项；
- 启动后将 `copying/verifying` 恢复为 `pending`；
- 存储服务清除过期租约并恢复外置盘只读；
- 仅删除能由 `copy_item_id`/临时 UUID 证明归属的临时文件；
- 已有目标同名文件重新按原任务策略处理。

## 18. 持久化最低要求

业务后端至少维护：

- `storage_devices`：稳定身份、别名、最近展示信息；
- `batch_target_preferences`：同批次上次成功目标；
- `copy_selections` / `copy_selection_items`：不可变选择快照；
- `review_snapshots` / `review_snapshot_items`：不可变审阅快照；
- `copy_jobs`：请求参数、状态、版本、统计；
- `copy_items`：源相对路径、目标相对路径、状态、字节、哈希、错误、尝试次数；
- `copy_attempts`：每次失败/重试审计；
- `copy_events`：单调 `event_seq`，供 App 增量同步。

数据库禁止存目标写租约明文 token。需要恢复的临时秘密只保存在权限为 `0600` 的运行态文件中。

## 20. 三端实施顺序

1. **存储服务**：完成 Unix Socket、设备列表、租约、扫描、单文件复制、安全移除；复用已验证的底层模块。

5. **三端联调**：设备插拔、同名三策略、RAW/JPEG、全量备份、元数据开关、断线、断电、安全移除。

## 21. 验收矩阵

| 场景 | 必须结果 |
|---|---|
| 一张相机卡 + 一个 U 盘 | App 能区分展示并让用户选择角色 |
| 三个 USB 存储同时插入 | 列出全部；不自动选择目标；系统盘不出现 |
| 同批次再次复制 | 上次成功目标可预选，仍可修改 |
| 目标盘离线 | 不静默切换其他盘 |
| 源=目标 | 创建前拒绝 |
| 全量备份含 ARW/JPG/MP4/THM/XML/XMP/DOCX/PDF | 前六类按白名单复制，DOCX/PDF 跳过并统计 |
| RAW+JPEG 默认任务 | 复制 RAW；用户可改 JPEG 或两者 |
| 同名策略缺失 | 后端 422 拒绝 |
| `skip` | 旧目标不变，项为 `skipped_conflict` |
| `overwrite` | 临时写入和校验后原子替换 |
| `keep_both` | 使用 ` (1)` 后缀，不改原名主体 |
| 审阅导出开启 | XMP 与 CSV 均生成；可兼容格式优先嵌入副本 |
| 审阅导出关闭 | 目标无 BirdBox XMP/CSV/嵌入字段，内部复制记录仍在 |
| 用户改鸟种后复制 | 导出最终用户值，同时保留内部 AI 原始值 |
| App 断线 | 任务继续，重连按 `event_seq` 恢复 |
| 暂停 | 当前文件完成后暂停，不产生半成品 |
| 取消 | 本任务临时文件清理，既有目标和源不变 |
| 复制中拔目标盘 | 已完成项保留，当前项失败/等待，不换盘 |
| 重插另一块同容量盘 | `media_id` 不同，禁止继续 |
| 安全移除 | 同步、卸载、保持期内不重挂载 |
| 断电重启 | 过期写租约恢复只读，未完成项可重试 |

### 21.1 发布阻断项

任一项存在则禁止发布：

- 任何路径可修改源盘；
- App 或 HTTP API 出现 Linux 绝对路径；
- 无同名策略仍可创建任务；
- 目标租约失效后仍长期读写挂载；
- 哈希不一致仍标记成功；
- 安全移除后被守护服务立即重挂载；
- App 断线导致任务取消；

## 23. rc1 后仍需产品确认的非阻断偏好

以下不影响三端开始开发，但应在升 v1.0 前由产品最终确认：

1. App 新任务中“随副本保存审阅信息”开关是否默认开启。本文建议开启；关闭语义已经冻结。
2. 默认目标目录是否需要在 `BirdBox/YYYY/MM/DD/` 中再增加用户可见的批次名称。当前协议不增加，以减少路径冲突和非法字符问题。
3. 安全移除保持期 UI 倒计时是否显示。协议默认 60 秒，显示方式由 App 决定。

除以上三项外，三端不得以“产品未确认”为由自行改变本协议的设备选择、文件范围、冲突策略、源盘保护、任务状态和接口字段。
