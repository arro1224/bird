## 结论与边界

B6 App 本地实现完成。支持 `import-analysis-v1` 时，一次开始使用固定的项目创建键和导入键，分别在首次 POST 前持久化完整请求。导入同时携带显式分析配置和用户已确认的持续复制选择，接回盒子登记的原 import job、analysis job 和可选 follow session；手机的导入完成事件、轮询和冷恢复均不再补建识别或复制。

回包丢失、重复点击、进程重开和未知结果沿原请求恢复；重放 POST 后仍查询当前流程。识别取消针对已登记任务，使用当前版本和持久化动作键，结果不明显示“取消待确认”，不将离线意图伪装为已取消。旧盒子和明确没有新流程的旧项目保留原能力分支，新协议出错不删除分析／复制字段后降级。

## 实现规则

| 范围 | 最终行为 |
| --- | --- |
| 能力 | 严格核对 `available`、契约版本、`owner=box`、请求字段和状态路径；能力缺失／明确 false 走旧分支。声称可用却格式错误或契约未知时停止，不猜测兼容 |
| 请求映射 | 新增 `AutoAnalysisRequest`，显式 `mode=new_only`、`existing_result_policy=skip`、`include_grouping=true`；不复用旧 `mode=standard`，不发送尚未存在的照片 ID |
| 复制选择 | 重新只读校验确认有效期、源设备、目标身份与空间、偏好版本及配置上下文，再把用户的 target、pair、conflict、review export 原样映射到新协议。没有选择时为 null，不默认挑盘或创建跟随 |
| 完整封套 | `ApiClient.postEnvelope` 为专用入口，保留 `data` 同级 `workflow/analysis_job`；复用原 HTTP、认证、诊断和错误路径。现有端点继续原来的 data 拆包 |
| 结果校验 | `ImportStartResult` 校验 contract、owner、项目、不同的两个任务 ID、任务类型与来源项目，以及可选 session 关联；缺失或身份变化视为协议错误。已选复制却没有会话时不当作普通识别成功 |
| Repository | 新增可选 `ImportWorkflowRepository` 边界，不改变旧 `createImport` 的单任务返回类型；生产实现接完整 POST、流程 GET 和带稳定键的 job action |
| 持久化 | 新命名空间 `import-analysis-intents:v1:<device_id>`，记录 format、阶段、原参数、两个独立键、项目及任务关联、完整快照和取消意图。写失败不发首次 POST；未知未来格式保留并拒绝覆盖 |
| 一次开始 | 同一逻辑开始的并发／迟到回调复用原项目与任务。重新明确进入配置才产生新的逻辑意图；未决请求存在时不得通过改名、换卡或换策略绕过 |
| 项目回包丢失 | 重开后用原项目创建键和原参数恢复；项目已创建时接回同一个 project，不再创建第二批 |
| 导入回包丢失 | 优先 GET 查询；仅明确 `404 import_analysis_not_found` 时用原导入键和原完整参数重放。POST 重放为首次快照，随后必须 GET 当前进度 |
| 盒子所有权 | 冷恢复主动核对当前项目。已有 managed 意图即使 GET 暂时 404 也不交回手机；未知归属先查，查询失败不认定为旧项目。明确旧项目未登记时才允许原级联 |
| 禁止重复建任务 | 新协议的完成事件、REST 轮询、手动识别和 SmartFollow staged／直接创建入口均受所有权保护。收到 `import_analysis_owned/conflict` 接回原流程，不再 POST analysis |
| 状态合并 | 每个 job 沿用 B5 的 ID、类型、项目和版本比较；串行落盘时再次合并最新记录。迟到首次 POST、旧 GET 或旧动作回执不能覆盖较新快照或后来持久化的取消意图 |
| 设备隔离 | 记录按盒子身份隔离；异步请求保存捕获的连接上下文，换盒子后拒绝继续导入或接纳迟到响应，不把旧流程写给新盒子 |
| 取消 | 先查询原流程，再以用户看到的版本提交，先落盘动作／版本／稳定键。未知 ACK 保持待确认；查询确认终态后才显示真实结果。遇新版本刷新并要求用户重新确认，不自动换 CAS 取消 |
| 页面 | queued + `waiting_import` 显示“等待导入完成”和盒子自动开始提示，不显示 AI 0／0、0% 或虚假进度条。待确认取消保留原任务状态，并提供核对原结果入口；首页增加未决开始恢复入口 |
| 兼容入口 | 任务详情兼容路由、次级任务中心与任务卡使用相同流程／取消语义；图片准备和 AI 的独立进度、可用动作、时间与完成导航保护保持 |
| 错误解释 | 明确来源卡变化、复制能力／metadata 不支持、流程未准备、活动流程不可删、源导入失败／取消、`backend_restarted`；不自动重建失败流程，不丢复制选择后重试 |
| 模拟服务 | `importAnalysisWorkflow` 默认关闭，旧夹具行为保留；显式开启时提供真实完整封套、幂等异参冲突、持久化工作流及独立接续，区分 dispatch 与 job 终态 |

`dispatch_state=waiting/dispatched/stopped/no_candidates` 不充当任务终态。无候选的已登记 analysis 明确 completed、总数 0；导入失败使原分析停止并返回源导入错误；服务重启使未完成原任务明确失败为 `backend_restarted`。取消识别只控制该任务，未改变已入队复制的产品收尾规则。
