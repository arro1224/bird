# 项目4 F25-B2 后端接口确认与修复结果

日期：2026-11-25

## N14-R1：项目版本只读来源

本地后端源码已确认存在可供 App 读取的项目级 version，不是数据库字段推断：

- GET /api/v1/projects/current 返回 data 项目对象，含非负整数 version。
- GET /api/v1/projects 返回的每个 data.items[] 项目对象含同一 version，可查询历史项目。
- GET /api/v1/projects/{project_id}/files 的分页结果也返回项目 version。
- 上述版本读取与 POST /api/v1/projects/{project_id}/files/actions 使用同一个 projects.version 计数器。单张审阅成功、批量审阅至少一项成功时推进；批量没有成功项时不应推进。

批量响应格式：

    {"data":{"succeeded_ids":["file-a"],"failed":[{"file_id":"file-b","reason":"照片不属于当前项目"}],"version":12}}

真实字段及类型应以部署中的 OpenAPI 和脱敏响应为准。上述源码确认不等于已对现有 K7 实机取样；板端部署版本、响应样例及版本推进行为仍需实机联调确认。

## N14-R2：幂等回放与部分结果

检查发现批量写入此前虽会保存和重放原响应，但没有比较同一幂等键的请求参数；同键改参数也会被当作重放。已在本地修复：批量请求保存规范化请求摘要，同键同请求重放原结果，同键不同请求返回 HTTP 409、错误码 IDEMPOTENCY_CONFLICT。批量部分成功保留成功／失败列表；仅当至少一项成功才推进项目版本，全失败不推进。

旧数据库中的既有幂等记录没有原请求摘要，无法从历史响应反推出首次请求参数；它们仍按旧行为重放，不声称能识别历史记录的同键异参。新记录具备请求摘要。正式 K7 的同键重放、异参拒绝及部分结果稳定性仍需按联调清单验证。
