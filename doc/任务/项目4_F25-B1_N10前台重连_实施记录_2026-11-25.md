### 前台接替与取消结束

- 网络可用性、客户端 Wi-Fi 标签变化后，取消旧尝试时直接登记后继 attempt 并启动验证。相同信号与正在运行的同一恢复合并，不因重复通知不断重新发送请求。
- 自动接替共用 `_RecoveryBudget` 的时钟和期限，不能每次增加 generation 就重新获得 20 秒。默认 STA 恢复总预算仍为 20 秒；直连系统准备保留既有至少 90 秒窗口，同一恢复内的替换继续使用原时钟。
- 失败、当前 token 取消、保存设备不存在或身份不符时，退出恢复状态，清空活动尝试及页面中的旧验证标识。保留设备和缓存内容，明确允许重试。
- 超时后相同的网络标签通知不会自行开启下一轮恢复；实际网络标签变化或明确的新恢复操作可重试。旧成功、旧失败及旧期限回调不能覆盖后继会话。
- 手动连接开始也会取消之前的自动恢复；手动流程取消或页面关闭后不接纳旧恢复的迟到成功。配网接管先结束旧恢复，再由现有配网端点验证进入连接状态。
- 取消同时清理尚未触发的原生直连丢失延迟重试，避免已取消后被旧定时器重新拉起。

### 本机热点与网络提示

- 将 `hasWifi`、默认网络可用性作为提示，既不据其直接确认连接，也不据其直接否定已保存盒子的本地链路。
- 网络提示读取失败或超时仍允许本地验证；提示查询各有 2 秒上限，实际验证继续受恢复总预算约束。
- 网络变化时先显示正在验证，真实验证失败后显示断开，不能长期保留未经核实的已连接状态。
- 不新增跨厂热点检测或原生权限。诊断角色为 `wifi_client`、`box_direct_ap`、`local_link_unconfirmed` 或 `local_link_verified_without_wifi_client`，不能从蜂窝标签推定手机一定开启热点。
- 生产验证仍走 `ConnectionRepositoryImpl`／`ConnectionApi`，检查保存的 `device_id`、恢复授权、受保护 HTTP 和认证 WS；没有以普通 health 探测代替授权成功。

## 二 取消入口与后继动作

| 来源／入口 | 后继动作与状态 |
| --- | --- |
| `network_changed`、`transport_changed` | 有变化时用新代次接替；同一活跃恢复共享原预算；重复信号合并 |
| 显式 `verifySavedSession(restart: true)` | 明确替换旧尝试，使用新的恢复预算；普通重复调用仍合并 |
| `manual_connection_started` | 停止旧自动恢复，由手动连接流程负责后续成功、取消或失败 |
| `network_intent_started`、`handoff_claimed`、`legacy_handoff` | 停止旧恢复，由配网流程接管；没有端点验证时不保留旧恢复转圈 |
| `network_intent_ended` | 没有新的所有者且未连接时明确结束 |
| `authentication_failure` | 结束当前验证，显示授权失效；不将可达性当成授权通过 |
| `user_cancel`、`connection_page_closed`、`pairing_dismissed` | 取消并结束对应连接，不由旧延迟重试复活 |
| `connection_failed`、`pairing_failed`、`pairing_required` | 结束当前连接并保留各自错误／配对路径 |
| 当前 token 被取消、恢复到期、保存设备缺失 | 结束恢复、清除旧标识；之后允许明确重试 |
| `verified_status_received`、`session_closed` | 分别交给新验证成功状态、结束全部会话资源 |

诊断增加 `cancel_source`、`successor_action`、`successor_attempt_id`、`previous_generation`、`next_generation`、`recovery_elapsed_ms`、`network_role`。字段通过连接和手机两层白名单后可进入导出；测试同时检查密码等任意字段不会被保留。
