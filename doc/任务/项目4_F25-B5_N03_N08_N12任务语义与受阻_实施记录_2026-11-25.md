## 实现规则

| 范围 | 最终行为 |
| --- | --- |
| 受阻来源 | 优先 `summary.blocked_kind`，兼容 `blocked_reason=COPY_INSUFFICIENT_SPACE` 等已知旧原因；未知新原因可回退已知旧原因，全部未知时只说明存储受阻，不推断拔盘 |
| 空间快照 | 显示有值的 `free_bytes`、`required_bytes`、`reserved_bytes`、`missing_bytes`，单位为字节；大整数不换算截断。缺失或无效值保持未知，不计算虚假缺口 |
| 快照时间 | 使用会话 `updated_at`，明确是受阻时的快照，不作为实时可用空间。时间缺失明确“盒子未提供”，不拿手机当前时间补造 |
| 原会话恢复 | 页面仅渲染 `allowed_actions`；允许时提示“重试原任务”。沿用仓库当前 `expected_state_version` 和会话／动作／版本派生的幂等键；已复制计数来自后端，不归零、不补建子任务 |
| 图片准备 | DTO、主任务详情、任务卡与摘要统一名称；即便旧盒子返回遗留控制动作，也在视图适配、页面及三个控制器入口阻止图片准备控制。日志导出与任务控制分开 |
| 手机审阅回写 | 保留原同步服务、冲突处理和结果页，不将浏览图片准备混作审阅回写；未把 `TaskType.sync` 的手机入口统一改名 |
| AI 动作 | 只用 AI 任务自己的 `available_actions`；没有新增运行期暂停／继续，也未更改取消 AI 后复制队列的产品策略 |
| ETA 与阶段 | 缺 ETA 显示暂不可用，显式 0 与缺值分开。运行到 100% 仍等待盒子终态，准备图片、AI、导入、复制与回写各自使用自己的计数 |
| 离线 | 保留旧任务和准确更新时间；页面按全局连接状态显示“上次进度快照”，不推进本地百分比。旧任务列表读取失败时保留快照，并阻止使用失效控制 |
| 回网 | 主控制器先完成 REST 核对，再接续事件；核对中有事件则安排补读。恢复及详情读取拒绝旧设备响应，不把请求前的旧内存当成新权威 |
| 单任务版本合并 | 按任务 ID、类型、项目和版本比较。旧版本、缺版本降级、同版本终态回退或进度回退拒绝；更高版本允许合法重试。控制 ACK 与 REST 同样遵守规则 |
| 多个 REST 来源 | 设备 `current_job` 与任务分页先比较版本，再和当前事件快照合并；设备旧快照不能覆盖分页中的新终态 |
| 完成通知 | 新增携带实际完成任务的通知，保留旧项目通知接口兼容调用方。陈旧完成事件未被接受时不产生导航副作用 |
| 自动导航 | 只在任务页可见、当前项目匹配且没有别的页面／操作意图时触发。异步查询返回后再核对设备上下文及该任务仍已完成；换页、换盒子、其他项目或更高版本重试都不跳页 |
| 用户查看结果 | 运行中打开详情后，后续真实完成可出现显式结果入口，不依赖自动导航；图片准备摘要与审阅同步摘要分别表达 |
| 模拟协议 | 缺目标盘／缺源卡的模拟故障补明确 `blocked_kind`，保留队列和恢复规则；不因模拟的旧字段缺失而让生产 App 继续猜测拔盘 |
