# 模拟盒子：本地人工调试终端命令（birdbox-copy-v1）

**日期：** 2026-09-10
**适用环境：** Windows + Git Bash，项目 `E:\project\BirdApp`，Android 模拟器 `emulator-5554`
**用途：** 不依赖真实盒子硬件，在本地跑通「配网 → 首页 → 相册/审阅/任务 → 复制流程」全链路人工调试

## 1. 终端 1：启动模拟盒子（一直保持运行）

```bash
dart run tool/mock_box_server/server.dart --quick --auth --progressive-media --host=0.0.0.0 --port=8787 --device-id=bbx-82f41c9e7a3d4b68a1501e21e536c649
```

参数说明：

| 参数 | 作用 |
|---|---|
| `--quick` | 60 张照片快速集（默认 1200 张） |
| `--auth` | 全通道 Bearer 鉴权（与生产行为一致，推荐） |
| `--progressive-media` | P1 渐进图片（thumbnail/preview、ETag/304、asset_ready） |
| `--port=8787` | 服务端口 |
| `--device-id=bbx-...` | 必须 `bbx-` + 32 位小写十六进制（rc4 身份约束），与 App 侧 `BIRD_SIMULATED_DEVICE_ID` 一致 |

验证已启动：

```bash
curl http://127.0.0.1:8787/health
# 期望：返回 device_id 与 "1.0-rc4" 的 JSON
```

## 2. 终端 2：运行模拟入口（App 侧）

```bash
  flutter run -d emulator-5554 --debug --flavor birdV1 -t lib/main_bird_simulated.dart --dart-define=BIRD_TEST_BASE_URL=http://10.0.2.2:8787 --dart-define=BIRD_SIMULATED_DEVICE_ID=bbx-82f41c9e7a3d4b68a1501e21e536c649
```

要点：
- **模拟器用 `10.0.2.2`**（模拟器访问宿主机）；**真机才需要 `adb reverse` + `127.0.0.1`**（见 §3）
- 配网页标题带「模拟」；走 Fake BLE 发现 → 配对 → 换 Token → 进正式三标签首页
- 首页后的相册、审阅、任务、复制、存储都用正式 Repository，仅盒子地址指向本地 Mock
- 热重载 `R` 可用

## 3. （换真机时）vivo 真机变体

真机需先建 TCP 反向映射（模拟器跳过本步）：

```bash
/d/code/Android/Sdk/platform-tools/adb.exe -s <设备序列号> reverse tcp:8787 tcp:8787
/d/code/Android/Sdk/platform-tools/adb.exe -s <设备序列号> reverse --list
```

然后运行入口，`BIRD_TEST_BASE_URL` 改用 `http://127.0.0.1:8787`：

```bash
/d/code/flutterSetting/bin/flutter run -d <设备序列号> --debug --flavor birdV1 \
  -t lib/main_bird_simulated.dart \
  --dart-define=BIRD_TEST_BASE_URL=http://127.0.0.1:8787 \
  --dart-define=BIRD_SIMULATED_DEVICE_ID=bbx-82f41c9e7a3d4b68a1501e21e536c649
```

## 4. 配对码

**任意 6 位数字**（如 `123456`、`2468`）。模拟 BLE 层只校验位数、不校验数值；
真正决定能否配对的是模拟层硬编码的会话 ID（`ps_mock_pairing_session`），与界面输入的码无关。

---

## 5. 调试中必知的坑

1. **RC4 配对会话一次性**：每次**完整重跑 App（冷启动）前，必须先 Ctrl+C 重启终端 1 的 mock 盒子**，否则配网失败（会话已消费）。热重载 `R` 不受影响。
2. **「获取预检并继续」点不了** = 同名文件处理策略未选（**必选、无默认值**，协议 §8）或目标设备未选。目标设备首次进入不会自动选，需手动点一张（U 盘 Ee / 移动固态硬盘）。
3. **「保存为默认策略」不跳转**：只把当前范围和审阅导出选项写入本地设置并弹提示条，需再点「获取预检并继续」前进。
4. **提交后任务列表看不到复制任务 = 预期**：当前 `useMockCopyRepository = true`，任务只存在于 App 内存，不进盒子 `/api/v1/jobs`；任务进度/报告联动（阶段 D）等后端交付后接入。
5. 模拟会话不写 Android Keystore，不覆盖真实盒子凭据。

## 6. 可选：手动让盒子创建一个复制任务（体验任务列表联动）

```bash
curl -X POST http://127.0.0.1:8787/api/v1/copy-jobs \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: manual-copy-001" \
  -d '{"batch_id":"b12a_20260910_123456","scope":"kept_assets","conflict_strategy":"keep_both","preview_token":"manual-preview-token-001"}'
```

- 用 `--auth` 启动的 mock 需要带 Bearer，会 401；不想鉴权就在终端 1 重启时去掉 `--auth`（App 需重新配对一次）
- 创建后回 App 任务列表刷新可见该任务（job 类型 copy）
