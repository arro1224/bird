## 1. B4-A：计划模型与展示

`CopyJobItem.planState` 与执行 `state` 分开。仅识别 `copy / skip_conflict / not_applicable / blocked`，缺失或未知值进入 unknown，不能根据 pending、全局 keep_both 或 conflict_decision 补成 copy。

明细主徽标分别显示“将复制 / 将跳过 / 不适用 / 已阻止”；覆盖、两份保留为辅助说明。路径尾部优先展示、点击展开完整路径的能力保留。

计数采用以下口径：

| 内容 | 来源与单位 | 本轮处理 |
|---|---|---|
| 逻辑照片数 | 既有 `logical_assets`，兼容 `logical_photo_count` | 独立展示，不与明细条数强行相等；RAW+JPEG 可以一张多项 |
| 计划复制文件数 | 既有 `planned_files`，兼容 `actual_file_count` | 领域及页面使用 `plannedFileCount`；保留旧构造参数/getter 供既有调用兼容 |
| 计划复制字节 | 既有 `planned_bytes`，兼容 `total_bytes` | 必须等于完整计划中 copy 项的 source_size 之和 |
| 明细总条数 | 读完所有分页后 items.length | 不从计划复制数推导，也不虚构 total_count wire 字段 |
| 复制/跳过/不适用/阻止 | 按完整明细的 plan_state 分别计数 | 统一承载于 `CopyPlanIntegrity`，摘要和弹层复用同一快照 |
| 明细查询 ID | 显式 `preview_id` 优先，包含 building → ready 场景 | ready 未再次返回 ID 时保留 building 的 ID；旧响应无 ID 才沿用 token，关系待实机复核 |

确认页示例为“5 张逻辑照片 · 2 个将复制文件”；计划摘要为“5 条明细（2 个将复制 · 3 个将跳过……）”。分类统计沿用后端，不擅自规定分类数量之和等于逻辑数或文件数。

这里记录的是 App 使用口径和既有适配字段，尚未冻结真实板端契约。尤其要复核旧 actual_file_count 的实际含义、每条计划的文件单位、伴随文件及计划字节是否覆盖相同范围。

## 2. B4-B：完整性校验和创建门禁

新增纯领域 `CopyPlanVerifier`，由 `CopyConfigCubit` 调用；校验不依赖用户打开弹层。状态区分 pending、verified、inconsistent、unavailable、expired。

流程如下：

1. 保留 B3 的设备、源绑定、配置及会话检查，取得预检汇总。
2. 页面提示“正在核对预检”，自动读完该预检的全部明细分页。
3. 核对稳定 item ID、已知 plan_state、源路径/非负整数文件大小、可复制项的目标目录及文件名，以及分页结构。
4. 验证 copy 项数量和字节数与汇总一致，生成与 token 绑定的只读计划快照。
5. 只有当前 token 对应 verified 快照且没有 blocked 项，才允许开始复制。verified 表示完整性通过，不能替代每项业务可执行性判断。

重复 ID（含跨页重复）、未知/缺失状态、字段类型异常、数量/字节矛盾、空页但仍 has_more、重复/缺失游标、终页仍带下一页游标、缺少明确 has_more/items、读取失败/超时、预检过期都不会放行。不会静默去重或截断后声称完整。

保护上限为 **200 页 / 50,000 项 / 单页 15 秒**，任一触发均停止并提示重试或缩小范围；这是当前 App 的内存/请求保护，不是已确认的服务端规模契约。页大小较小时，页数上限会先触发，需与后端结合真实集合规模复核。校验期间约每 50ms 检查取消、轮次失效或到期；取消后旧网络响应仍可能到达，但不能再更新当前状态或创建任务。

首次预检和提交前核对均可取消；失败后提供重新预检入口。POST 发出后的创建阶段不提供“取消核对”按钮，避免将页面取消误解为取消服务端任务。B1 已有的创建响应晚到仍记录原任务 ID、落盘失败不重复 POST 的行为保留。

**与 2026-09-17 的行为差异：** 已删除“明细不可用，不影响任务创建”的提示及放行逻辑。明细不可验证时，现在明确禁止创建；未提供计划仓储也不会降级放行。历史阶段 D 记录保留为历史事实，不代表当前门禁。

## 3. 提交时的新 token 与再次确认

开始复制仍先执行二次预检，并独立读取新预检的所有分页；不能复用旧 token 的验证结果。

将新计划与用户刚确认的完整计划进行语义比较：源/目标、逻辑数、复制数、字节、分类/异常统计、文件身份与路径、目标文件名、plan_state 和冲突决策等。比较忽略 token、跨预检重新生成的 item ID 及分页顺序；同一预检内 ID 仍必须唯一。配置/范围仍受 B3 的冻结 draft、配置版本及环境版本保护。

- 仅 token 刷新、实际计划等价：检查设备和有效性后，用新 verified token 创建。
- 文件名、数量、字节或决策等变化：更新确认页，显示“预检计划已变化”，本次不 POST；用户再次点击开始复制才重新确认。
- 新计划不可验证或包含 blocked：禁用创建。
- 会话、页面、配置或设备轮次变化：旧响应丢弃，不能覆盖较新的预检。

明细弹层优先展示本次已核对的快照，避免再次请求时把另一个列表拼进确认结果。弹层独立调用的旧分页入口也增加在途请求、重复项及游标保护，但它不能授权 Cubit 提交。
