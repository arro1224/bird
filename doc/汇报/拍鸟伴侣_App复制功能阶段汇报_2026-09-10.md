# 拍鸟伴侣 App 复制功能迁移 — 阶段汇报（2026-09-10）

## 一、项目背景与目标

拍鸟伴侣是一个三端系统：**App（Flutter）** + **拍鸟盒子（嵌入式硬件）** + **盒子业务后端**。本次工作围绕「复制功能」——把相机卡里的照片/视频复制到外部存储设备（U 盘、移动硬盘），并支持「摄影资料全量备份」。

旧实现的三大问题：

1. **单目标盘** —— 只有一个固定的"默认目标设备"概念，不支持多存储设备管理
2. **双轨制** —— 复制模式有 keep/all/dual 三种，逻辑复杂、语义模糊
3. **协议陈旧** —— 两步式 estimate/create，没有幂等、没有任务状态机、没有结果报告

目标：按冻结版《三端协议 v1.0-rc1》（2026-08-24）把复制功能整体迁移到新协议 `birdbox-copy-v1`，支持多存储设备、批次概念、全量备份、任务进度与报告。

## 二、本周已做：阶段 A + B + C

按迁移对照文档的"分阶段实施建议"，完成前三个阶段：

**阶段 A — 模型和接口壳**

- 新建 `copy_models.dart`，落地协议 10 个领域模型：复制范围（四种）、同名策略、冲突策略、审阅导出配置、存储设备摘要、选择快照、预检、任务摘要、批次目标偏好
- Repository 接口全部重写：设备列表 / 创建选择 / 预检 / 创建任务 / 批次上次成功目标 / 设备别名
- `CopyApi` 按协议 §13 实现真实 HTTP 调用：请求带 `X-BirdBox-Protocol: birdbox-copy-v1` 头，创建类请求自动生成 `X-Idempotency-Key`（幂等键），网络重试时复用、用户重新发起时生成新值

**阶段 B — 设备选择与确认页**

- 确认页重写为三步流程：**配置 → 确认 → 成功对话框**
- 设备卡片：只显示用户可读信息（名称/厂商/容量/文件系统），**绝不显示 `/dev/sdX`**；不可选的设备必须显示**具体原因**而不是单纯置灰；身份降级有专门提示
- 同名策略**必选无默认值**，未选时不能提交（协议 §8）
- 提交前**二次预检**（§10.2）：拿最新 preview_token，空间不足/超时则中止

**阶段 C — 相册多选与入口**

- 任务首页拆分两个入口：「复制照片」（需当前批次有照片）+「摄影资料全量备份」（只要有相机卡就能进，无批次也可用）
- 相册多选 → 「复制所选」→ 创建不可变 `selection_id` → 配置页固定"已选择 N 张"
- 设置页改造：删除双轨开关、完整性校验开关、全局默认目标；新增「随副本保存审阅信息」；存储目标页改为「存储设备」页（实时列表 + 别名编辑）
- 旧偏好迁移：旧 `dualTrack` → `batchAllAssets`（复制全部），旧目标盘直接丢弃不映射

## 三、核心实现逻辑（关键设计点）

1. **门控规则重写**：分析/导入任务**不再阻止复制**（旧逻辑是任何任务进行中都拦）；只有另一个"目标写任务"（copy 类型）才互斥，提示"已有复制/备份任务正在使用目标设备"
2. **同设备互斥**：源/目标由用户分别确认，同一设备不能同时担任源和目标，后选的角色覆盖先选并清除另一角色
3. **批次预选策略**：只预选"同批次上次成功目标"，记在本地偏好 `batchTargetPreferences`（batchId → media_id）；**上次目标离线时不自动换盘**，目标留空让用户重选——这是协议明确要求，避免静默写到错误设备
4. **文件边界暂停语义**（为阶段 D 预留设计）：暂停/恢复只能在文件边界生效，防止文件传一半被切断
5. **mock 先行策略**：后端尚未交付接口（OpenAPI 契约仍是旧 `/copy/estimate` + `/copy`），按协议要求**所有 mock 用协议字段、禁止创造临时枚举**。单一开关 `useMockCopyRepository = true`（mock_copy_repository.dart:11），后端交付后置 false 即切换真实 HTTP，页面零改动
