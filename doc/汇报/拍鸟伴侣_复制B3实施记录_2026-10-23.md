## 1. 核对结果与边界

原实现有以下可复现缺口：

- `submissionBlockReason` 未核对设备在线、可作目标、源只读绑定等状态；读取设备失败后也缺少“状态过期”门禁。
- 配置只在初始化读取设备；预检后设备断开不能及时更新页面。
- `setConflictStrategy` 未清除旧预检；其他配置修改虽清空了预检，但在途旧响应仍可能重新填回。
- 提交中刷新源绑定后直接使用可变 `state.draft`，容易把不同阶段的源绑定/目标混用。
- 提交报离线等错误后只显示 error，旧 token 与开始条件仍可能保留。
- 目标卡片谓词会把当前源卡（带 block reasons）列入禁用候选，且禁用原因直接显示内部字符串。

已有 `ApiException.fromDio` 已支持顶层 `error_code/error_message` 和嵌套 `error.code/error.message`。本轮为这两种已支持结构做合成回放，没有因缺少现场包络而增加猜测性别名，也没有把所有 HTTP 409 解释成拔盘。

## 2. B3-A：预检有效性与提交门禁

### 显式状态

`CopyConfigState` 区分未获取、获取中、有效、已失效、待重新预检；App 内部失效原因覆盖源离线、目标离线、源绑定变化、配置变化、过期、设备/预检不一致、设备数据过期、盒子连接变化、目标不可用、空间不足及验证失败。

这些是 App 状态，不作为新 wire 枚举发送。已有预检到期和源绑定到期会主动清除旧预检，不必等待下一次点击才禁用。

页面和 `submit` 共用状态门禁与 `previewProblem` 判定：

- 原盒子可用、页面可操作、设备快照有效。
- 当前源在线、能作源、只读绑定已验证、绑定 token 存在且未过期。
- 当前目标在线、可作目标且无阻止原因；源目标不同。
- 范围、策略、偏好版本与选择上下文齐备，偏好写入已完成。
- 预检 token 有效、设备身份与冻结请求一致、预检目标可写、当前空间及安全余量足够。

这里的“不一致”仅检查 B3 所需的源/目标身份和可用性；B4 的完整计划分页、plan_state 与计数校验尚未实施。

### 冻结请求与异步隔离

提交先复查设备/源状态，基于一份冻结 draft 做二次预检，再复查设备，最后使用**同一 draft 与二次预检 token** 创建任务。

配置版本、连接环境、请求轮次和设备上下文分开检查。配置修改、源身份变化、设备拔出或旧响应晚到时，创建前停止；不把后台新快照拼进旧 draft。

源接口可能在每次 GET 签发不同的 opaque token。本轮不把字符串变化猜成换卡：当前设备身份、只读证据一致且原绑定未过期时，普通状态刷新保留已确认绑定；用户明确重新预检才续签。二次预检由服务端再次验证冻结绑定，创建也继续使用该绑定。明确身份变化、绑定过期、只读证据变化或服务端拒绝仍会废弃旧预检。这避免轮询/提交前读取导致“每点开始就因新 token 被阻断”，也避免将新绑定与旧预检混用。真实签发/撤销语义仍需现场样本确认。

RAW/JPEG 偏好写入串行吸收版本号，在途期间不允许预检或创建；读取到更新的权威偏好版本会废弃旧预检。外部 copyPreferences 信号也会使当前预检失效。

POST 已发送后的成功结果仍记录原 jobId。即使期间断线、页面关闭，也保留 B1 的成功任务记录，不因本地刷新或保存失败重复 POST。旧预检请求结束时也不能解除另一笔 POST 的提交保护。

## 3. 离线、恢复与页面提示

- 已确认源离线：**相机卡已断开，请重新插入后重新预检。**
- 已确认目标离线：**目标 U 盘已断开，请重新插入或选择其他目标设备。**
- 设备恢复：**设备已恢复，请重新预检后开始复制。**
- 网络读取失败：说明设备状态暂时无法确认、当前显示上次记录；保留列表，不伪造“已拔出”。
- 未知 409：沿用通用冲突提示，废弃旧预检并提供重新检测，不猜具体硬件原因。

已知离线错误或其他预检/创建失败会清除旧 token，并禁用“开始复制”。重插后保留原目标 ID，不自动选另一块盘；状态刷新清理已失效的离线错误，但必须重新预检才可提交。

预检被清掉时，确认页显示原因和“重新预检”，不再永久显示等待 spinner。配置页/确认页都有“重新检测设备”。原始机器码、路径和异常诊断文字不会通过禁用原因或已知离线文案直接显示。

## 4. B3-B：设备刷新与目标候选

### 刷新

- 接入现有会话、全局 refresh 及设备数据变化信号；页面可见时 5 秒低频读取设备、源绑定及适用的复制偏好。
- 在途刷新合并；连接变化及页面生命周期使旧响应失效。初始化阶段被后台打断也能重新加载，不遗留 spinner。
- App 后台或被其他完整页面覆盖时暂停轮询，返回后刷新并重新预检。查看本页的预检明细弹层保持当前预检，单纯查看明细不会废弃确认；真实后台/设备变化仍正常失效。
- 一个并行读取明确失败就及时废弃预检，不等待其他慢读取结束。
- `CopyApi` 缓存设备快照时检查读取轮次和连接地址，旧列表响应不能覆盖更新请求的缓存。

### 目标策略

新增统一 `CopyDevicePolicy`，供候选列表、点击选择、历史目标预选、卡片禁用和提交校验共用。

- 排除当前源 mediaId、明确 `product_role=import_source` 的设备及依据能力/已确认源原因判定的源卡。
- `product_role` 为可选字段；旧响应不要求补字段，未知角色不被臆造为新协议枚举。
- 不因 `canBeSource=true` 排除合法双用途目标；`canBeTarget=true` 且无阻止原因时仍可选。
- 离线、只读、占用等有解释价值的目标保留禁用卡片。只读双用途设备也保留解释，不被误归为源卡。
- 已确认的阻止码映射成中文；未知内部码显示通用原因。旧协议中的安全中文原因可保留，未知代码、路径、URL 不直接渲染。
