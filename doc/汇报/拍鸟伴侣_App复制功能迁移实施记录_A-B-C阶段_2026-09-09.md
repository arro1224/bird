## 3. 关键设计点（检查时重点看）

### 3.1 门控规则（§3.1）
- 「复制照片」入口：需当前批次有照片；**分析/导入任务不再阻止复制**；仅另一个目标写任务（copy 类型）互斥，提示「已有复制/备份任务正在使用目标设备」
- 「摄影资料全量备份」入口：**无当前批次也可用**，只要有相机卡（`deviceStatus.card.inserted`）；同样受目标写任务互斥

### 3.2 目标设备预选（§4.4）
- 仅预选「同批次上次成功目标」：在设置 `batchTargetPreferences`（batchId → media_id）中记录；预选设备离线时**不自动换盘**，目标留空并要求用户重选
- 卡片上显示「上次用于这个批次」标记

### 3.3 同名策略必选（§8）
- Cubit 中 `conflictStrategy` 无默认值；未选择时 `submissionBlockReason` 恒非空，确认页「开始复制」禁用
- mock 服务器与 `CopyApi` 对缺失策略返回 422

### 3.4 提交前二次预检（§10.2）
- `submit()` 内重新调用 `preview()`：token 过期或空间不足则中止并提示，创建请求携带最新 `preview_token`

### 3.5 同设备互斥（§1.3）
- 后选的角色生效并清除另一角色（`selectSource`/`selectTarget` 内处理）；「源与目标能力都有」的设备（如 T7）可验证

### 3.6 相册多选（§3.2 / §13.3）
- 点「复制所选」→ `POST /batches/{batchId}/copy-selections` 创建不可变 `selection_id` → 配置页范围固定「已选择 N 张」→ 确认页显示弃选数量提醒（复制不改变审阅状态）

### 3.7 提交后反馈
- mock 阶段：成功对话框（任务编号 + 说明），返回后任务首页刷新
- **阶段 D 待办**：后端交付后在此接入「查看任务进度」跳转（`job_detail_page.dart` 的兼容路由已就绪）

### 3.8 后端切换
- 单一开关：`lib/bird_companion/features/copy/data/mock_copy_repository.dart` → `useMockCopyRepository`，置 `false` 即走真实 HTTP（CopyApi 已按 §13 实现全部调用与解析）
- mock 盒子服务器已具备 copy-v1 路由，可直接用于后端联调前的自测
