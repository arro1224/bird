## 1. B5-A：设备名称

任务设备名称使用统一解析：

1. 任务详情中冻结的别名/展示名优先；报告中的同设备冻结名称可补缺。
2. 无可读冻结名称时，通过相同 mediaId 的在线存储清单补名。
3. 再无可用名称，显示“源存储设备（名称暂不可用）”或“目标存储设备（名称暂不可用）”。

不再把 mediaId 当展示名；过滤与 ID 相同的名称、内部 media_ 标识、裸 UUID 及设备挂载路径。不会按 ID 前缀或盘符猜设备型号。详情首次取得的冻结名称在同一任务页面内保留，后续同设备的稀疏响应或在线改名不会覆盖它；离线历史盘仍可依赖冻结快照显示。

任务/报告同时支持已存在的 source_device/target_device 快照及 source_media_id/target_media_id 身份字段；嵌套快照缺 ID 时可由对应根字段补缺。没有给后端新增未确认的冻结名称别名。

名称清单通过 CopyJobDetailCubit 的可选 deviceReader 独立读取，生产页面接入 copyRepository.devices：

- 不等待清单才展示详情，也不等待它才读取事件、报告或允许动作。
- 同一轮次合并在途请求，15 秒上限；读取失败保留任务，不污染 detail.error。
- 连接轮次或动作改变后丢弃旧响应；关闭页面释放名称读取的本地等待。
- 初次读取/手动刷新补名，不为名称额外建立高频轮询。

## 2. B5-B：真实阶段

重写 CopyTimeline，删除两类推测：任务成功后所有阶段一律 done；copied>=total 后自动进入“校验文件”。

阶段现在区分尚未开始、进行中、成功、失败、不适用、未知和部分完成。只有已有状态或结果能支持的部分才显示：

| 输入依据 | 展示 |
|---|---|
| queued/draft/preflighted | 当前等待，目标获取/复制尚未开始 |
| waiting_for_source / waiting_for_target / acquiring_target | 对应等待或获取阶段 |
| running / pause_requested / cancel_requested | 任务运行中，同时说明子阶段未独立提供；不推断正在校验 |
| paused | 任务已暂停，未知子阶段不伪装为正在执行 |
| completed | 仅整体任务结束成功；不替代校验、审阅及同步结果 |
| completed_with_errors，或 completed 但报告有失败/降级 | 整体部分完成，不标为全成功，也不冒充整个任务失败 |
| failed / cancelled | 保留实际整体结果，不猜哪个子阶段失败或被跳过 |
| 冻结任务 review_export.enabled=false | 审阅阶段不适用/未启用；缺配置仍为未知 |
| csv_status=failed / export_failed_count>0 | 审阅导出失败，整体部分完成 |
| embed_degraded_count>0 | 审阅阶段及整体保留部分完成/降级 |
| CSV success / not_requested | 仅说明 CSV 子结果；不能证明 XMP/嵌入整体成功或整体未启用 |
| 无独立校验、安全同步结果 | “未提供独立状态”，不标绿 |

review_export.enabled 在既有创建协议中已有定义，本轮仅在详情响应实际提供 bool 时可选读取；不要求旧任务补字段，也不用手机当前偏好替代历史配置。没有臆造 stage_status、safe_sync_status、active_seconds 或平均速度的新响应适配。

现有报告仅有 XMP 数量、CSV 状态和嵌入数量等局部信息，不能仅凭数量证明全部审阅输出成功。因此即便 CSV 成功，整个审阅阶段仍可显示未知并明确局部结果。独立成功阶段需后端提供已确认的只读结果后再接入。

## 3. 耗时与速度

新增共享 CopyTaskTiming，详情和报告统一显示“耗时（盒子统计）”“速度（盒子统计）”：

- 运行态使用 stats.elapsed_seconds / stats.bytes_per_second。
- 终态报告可用后，两项一起切换至报告；报告缺速度就显示暂不可用，不借用旧运行速度。
- 报告未到达时可展示详情统计，并明确标识来源；不同来源不拼接。
- 数值解析保留有限、非负 JSON 数值的精度，不再把秒和字节/秒直接截断为 int。负数、NaN、Infinity、非法值显示暂不可用；0 原样展示，不据此推断暂停或平均吞吐。
- UI 秒数最多保留三位小数，避免分钟换算带出浮点尾差；模型保留原数值。合成 47.74 秒测试仅证明不截断，不证明实际固件的精度。
- 不用手机计时器、事件文本、copiedBytes/本机经过时间推算速度；未确认累计区间前不标“有效耗时”“平均速度”或“有效吞吐”。

报告任务 ID 与当前任务不匹配时拒绝采用，避免其他任务的名称和 timing 覆盖当前结果。旧报告缺 ID 的兼容路径保留。

## 4. 任务进度一致性

新增共享 CopyTaskProgress，列表、详情、报告使用相同四类计数：复制、跳过、失败、不适用。已处理数量为四类之和；任一类缺失/非法时不将其默认为零来宣称完整总数，显示“数量暂不可用”及已知分类。

运行中显示“已处理”；completed/completed_with_errors 显示“处理完成”。例如：

```text
处理完成 5 项（复制 4，跳过 1，失败 0，不适用 0）
```

移除 copied/total 的百分比回退。真实 total_files 是否包含全部 skip/not_applicable 尚未确认，因此本轮不显示推算 N/N 或百分比；服务端总数另列为“盒子文件总数”。4 复制+1 跳过不会再被 App 算成 80%。

已有 progress_percent 的比例/百分数兼容规则保留；仅有效非零服务端进度用于进度条。负数、非有限数、>100 的值拒绝，不再夹成 100%。终态旧的不足 100% 数值不再显示，避免与任务结束矛盾；也不自行补造 100%。

已复制字节单独显示，不把跳过/不适用计入字节。终态报告到达后，详情处理数量与报告统一使用报告数据；不把运行统计与报告逐项拼接。列表仍使用列表端点返回的统计，不逐行额外拉取报告；不同端点若实际返回矛盾数据，仍需真实联调定位，App 不改写服务端计数。
