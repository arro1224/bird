## 1. 请后端确认：App 当前按什么契约在写（可能有偏差，请逐条确认或纠正）

App 严格遵循 01 文档「不要自行猜测接口路径、状态值或报告结构」——以下是我们**当前 mock 的形态**，请后端**逐条确认"按此交付"或给出更正**。每条都给了 App 的容错边界，确认成本很低。

### 1.1 能力声明（已按 rc3 接入，有两个硬校验点需要确认）

App 请求 `GET /api/v1/copy-capabilities`（携带 `X-BirdBox-Copy-Revision: 1.0-rc3`），按以下结构解析：

```json
{
  "revision": "1.0-rc3",
  "copy_ready": true,
  "supported_scopes": ["selected_assets", "filtered_assets", "recognized_assets", "batch_all_assets", "media_full_backup"],
  "recognition_policy_version": "recognized-assets-v1",
  "missing_requirements": []
}
```

**两个硬校验点（请重点确认）：**

| # | App 行为 | 风险 | 请确认 |
|---|---|---|---|
| A | `revision != "1.0-rc3"` 时 App 直接拒绝进入复制流程（提示"盒子复制能力尚未就绪"） | 后端若升 rc4/改写法，App 全部置灰 | revision 取值是否会变？是否按字符串精确匹配？ |
| B | `scope-options` 响应**必须恰好 5 个**范围，多或少都按协议错误拒收 | 增删范围需同步 App | 五范围集合是否冻结？ |

### 1.2 RC3 任务闭环——App 假定的契约形态（按协议 rc1 §13.5/§13.6 实现，请冻结或更正）

| 端点 | App 假定 | 必须字段（App 硬性） | 容错范围（后端可自由增改） |
|---|---|---|---|
| `GET /api/v1/copy-jobs` | cursor 分页列表 | 每行 `copy_job_id`、`state` | 其余全部（`scope`/`stats`/`created_at`/`next_cursor`/`has_more` 缺失有默认） |
| `GET /api/v1/copy-jobs/{id}` | 任务详情 | `copy_job_id`、`state` | `state_version`（依次尝试 `state_version`/`expected_state_version`/`version`）、`event_seq`、`stats`、`allowed_actions`、`source_device`/`target_device` 快照、时间字段全部可缺省 |
| `GET /api/v1/copy-jobs/{id}/items?cursor=&state=failed` | 文件明细分页 | 每项 `copy_item_id`（`item_id`/`id` 也可） | 全部描述性字段可缺省；`next_cursor` **int 或 String 都接受** |
| `GET /api/v1/copy-jobs/{id}/events?after_seq=N` | 事件增量 | 事件含 `seq`（`event_seq` 也可） | `type`/`message`/`created_at` 可缺省 |
| `GET /api/v1/copy-jobs/{id}/report` | 终态报告 | 无硬字段 | **全部字段 optional**；"部分成功"由 `failed_files > 0` 判定，请确保该字段语义准确 |
| `POST /api/v1/copy-jobs/{id}/actions/{action}` | 动作 | — | 见 1.3 |

**解析容错总原则（请后端放心扩展字段）：** App 对以上响应**未知字段一律忽略、未知状态值保留原文展示不崩溃、`allowed_actions` 未知动作直接丢弃**。后端加字段不需要等 App 发版；但**删改下面这些硬性字段需要同步我们**：`copy_job_id` / `state` / `copy_item_id` / `revision`。

### 1.3 动作与幂等（01 文档"双方均需补齐"项——App 侧已就绪）

- 请求体：`{"expected_state_version": <int>, "reason": "user_requested"}`，请求带 `X-Idempotency-Key`。
- App 期望：版本不符返回 **409 `COPY_STATE_VERSION_CONFLICT`**（App 收到后自动重拉详情并提示用户，不会重试动作本身）。
- App 只渲染详情 `allowed_actions` 返回的动作按钮，**不自行推断状态**（01 文档要求）。请确保动作执行后详情的 `allowed_actions`、`state`、`state_version` 同步更新。
- 请确认动作集合冻结为：`pause / resume / cancel / retry_failed / safe_remove_source / safe_remove_target`。

### 1.4 安全移除（后端尚未提供——01 文档 §二已确认）

App 已实现：`POST /api/v1/storage/devices/{media_id}/safe-remove`，请求体 `{"role": "target"|"source", "expected_copy_job_id": "<可选>"}`。App 期望响应：

```json
{ "safe_to_remove": true, "keep_until": "2026-09-17T12:00:00Z" }
```
或忙碌时：
```json
{ "safe_to_remove": false, "reason": "有复制任务正在使用该设备，任务结束后再移除" }
```

- `safe_to_remove` 缺失时 App 按 false（保守）处理。
- App 文案承诺"保持期 60 秒"：**请确认后端保持期语义与时长**，若非 60 秒请告知实际值，App 改文案。
-忙碌判定请覆盖"有非终态 copy 任务占用该设备"场景（对应错误码 `COPY_SAFE_REMOVE_BUSY` 也可，App 两态都支持）。

### 1.5 两处 App 暂定的等价关系（请确认）

| # | App 暂定 | 请确认 |
|---|---|---|
| C | 预检明细用 `preview_token` 的值直接当 `preview_id` 调 `/api/v1/copy-previews/{preview_id}/items` | 两者是否同值？若不同请告知从预检响应哪个字段取 |

## 3. 负向行为对齐（双方镜像确认，来自 01 文档 §二）

后端已冻结的负向行为，App 侧已逐条适配并在 mock 中同值镜像，联调时行为应一致：

| 后端行为 | App 表现 |
|---|---|
| `copy-capabilities` 按真实存储返回，未插源卡/目标不可写/协议不匹配时 `copy_ready=true` **不会**出现 | 任务首页按 `copy_ready` 与 `supported_scopes` 置灰入口；`capabilities()` 请求失败时 App 回退本地推导（不阻塞页面） |
| `media_full_backup` 预检返回 `COPY_SCOPE_UNSUPPORTED`（HTTP 422） | 任务首页隐藏全量备份；若能力声明支持但预检仍拒绝（能力与实现不一致），复制页显示琥珀提示"当前盒子不支持全量备份，本次不会创建任务"并禁用提交 |
| 元数据相关调用返回 `METADATA_EXPORT_UNAVAILABLE` | App 不显示入口；错误码已映射文案"审阅信息导出暂不可用" |
| 预检明细返回实际计划文件，空列表不算正常 | 空明细 + 文件数>0 → 琥珀警告"预检明细暂不可用，不影响任务创建"，**不**渲染"暂无文件" |

错误包络请继续按 §13.1：`{"request_id", "error": {"code", "message", "details"}}`，`message` 用普通语言（App 优先展示后端 message）。
